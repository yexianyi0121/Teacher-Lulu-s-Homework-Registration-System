# 23 · 需求说明书 · v2.5.8

> 版本：2.5.8
> 起因：用户反馈（原话）「截图中为什么还是会出现这种图标重叠以及显示过小的问题?」
> 定性：**显示层的五个独立缺陷**，不涉及数据。其中一条已经能把整个应用打崩成白屏。

## 1. 现场

- **单张海报**：主值（`A+`、`×`、`假`）整格居中，右下角的状态角标（✓/标/缺/假）与主值挤压重叠；「假」「一二三」这类多字文本按基础字号撑破格子。
- **本周汇总图**：10 列固定 32px 小格，整块缩在卡片左侧、右边一大片空白；8px 的学号直接压在 11px 的主值上——物理上不可能不重叠。
- **弹窗预览**：1080px 的海报被塞进 960px 的弹窗（还要扣内边距），缩放约 0.55，格子糊成一片。这就是「显示过小」。
- 附带发现：某次打开应用直接白屏。

## 2. 根因与修复

### FR-63.1 白屏：可选字段没有兜底

`PosterModal` 原来写 `comment = draft.comment ?? settings.defaultComment`。
`defaultComment` 在类型上是必填，但老数据 / 手改过的备份 / 迁移中间态都可能缺 → 两个都是 undefined →
下面 `comment.length` 直接把整个应用打崩。弹窗组件不该因为一个可选字段缺失就崩：兜底成空串。

### FR-63.2 字号阶梯从未生效：属性根本没渲染

CSS 里 `[data-len="3"]`、`[data-len="5"]` 那组「多字文本降级字号」的规则一直存在，但 `CellView`
**从来没有输出 `data-len` 属性**，所以规则永远不会触发，「假」「一二三」只能按基础 24px 撑破格子。
补上 `data-len = min(6, Array.from(text).length)`。这是本批唯一可自动化的部分，已进测试（见 §3）。

### FR-63.3 海报格子：分成上下两条带

第一轮只放大格子与印章，结果主值仍旧整格居中、角标在右下角——还是挤。真正的解法是分区：

- **上带**：左上学号 / 右上印章
- **下带**：主值居中（`max-width` 横向预留角标位）/ 右下角标

主值只在下带里居中，物理上就碰不到印章与角标。另外「假」「缺交」的主值本身就是状态名，
右下角再挂一个同名小角标是重复信息——去重。

### FR-63.4 汇总 mini 格：固定 32px → 弹性 10 列

`repeat(10, 32px)` 只有 380px，而卡片宽 1080px，整块缩在左边。改为 `repeat(10, minmax(0, 1fr))`
（格子宽度跟着卡片走），格高 52px，与海报同一套上下带分区；补交小字贴底居中、主值上移；
mini 尺寸里不渲染表情（放不下）。

### FR-63.5 海报弹窗单独一档宽度

新增 `size="poster"`：`width: min(1240px, 100%)`，1080px 海报近似 1:1，所见即所得。
「缩到 0.55」这条路径到此关闭；`xl` 档保持 960px 不动，其他弹窗不受影响。
