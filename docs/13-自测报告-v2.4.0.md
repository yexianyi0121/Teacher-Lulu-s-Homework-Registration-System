## 4. 实现中的两个真问题（顺带修）

1. **night 主题的 `--brand` 不能当链接色**：night 主色 `#8E7CD8` 压设置弹窗白底只有 ≈3.5:1，不够 4.5:1。没有去改主题（ADR-24 边界：主题只换三组变量），而是新增不随主题换的 `--link: #2F6FBA`（≈5.1:1），E2E-42b 六主题逐个实算兜底。
2. **测试读 package.json 在 jsdom 下跑偏**：jsdom 把全局 `URL` 换成以 `http://localhost:3000/` 为基的实现，`new URL('../../package.json', import.meta.url)` 解析出 `http://localhost:3000/package.json`（scheme 不是 file）。改用 `createRequire(import.meta.url)` 走 Node 原生解析，两条测试（单测 + E2E）同步修正。

## 6. 有意偏差与设计决策（请评审重点看）

1. **版本号镜像 + 同步测试，而不是 import package.json**：domain 层保持纯常量（不引构建产物），漂移由 `appInfo.test.ts` 兜底——改版本忘改 appInfo，测试直接红。
2. **`--link` 不随主题换**：见 §4.1。六套主题共用同一个链接蓝，视觉上链接永远「可识别为链接」，对比度永远达标。
3. **关于分区放在最后**：老师反馈问题时要能自报版本号——放在最后不打扰日常设置动线，也不插队在「数据安全」与「历史记录」之间。
4. **GitHub 链接 `target=_blank` + `rel="noopener noreferrer"`**：既方便「看完设置还能回来」，又防 tabnabbing；应用自身不发起任何请求（零网络承诺不破）。

## 7. 未覆盖项（延续 v2.3.1 的诚实清单）

1. 真机 PWA 安装流程（standalone 行为仅在 E2E 里 mock 了 media query）。
2. `navigator.share` 真实系统面板（E2E-40 只 mock 了 `navigator.share` 函数本身）。
3. 7 天导出提醒的真实时间流逝（纯函数单测覆盖，UI 用注入时钟）。
4. Safari / Firefox 兼容（`color-mix`、`env(safe-area-inset-*)` 在现代 Edge/Chrome 验证）。
5. 语音识别质量（依赖系统能力，无自动化）。
6. 大班（100+ 人）手机端性能未测。
7. **浅色主题的卡片内文字未逐主题实算对比度**（本轮只实算了关于链接 vs 弹窗白底；白底卡片沿用 `--text-*` 天然达标的设计口径不变）。
8. `mailto:` 链接只验证了 href，未真机唤起邮件客户端。
