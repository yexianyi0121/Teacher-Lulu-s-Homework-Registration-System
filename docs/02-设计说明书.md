## 0. 设计目标与三条铁律

### 0.1 铁律

| 编号 | 铁律 | 对应的可验证约束 |
|---|---|---|
| L-1 | **录入路径不得有任何异步阻塞**：按键 → 状态更新 → 重绘 必须在同一帧内完成，保存、统计、海报全部派生且可延迟 | 按键到 DOM 更新 < 50ms（NFR-02）；保存是防抖的副作用，不在渲染关键路径上 |
| L-2 | **业务计算必须是纯函数**：统计、名单分拣、报表文案、海报数据模型都不允许依赖 store / DOM / 时间 / 随机数 | 全部模块可被 Vitest 直接单测，覆盖率 ≥ 90% |
| L-3 | **零网络**：除同源静态资源外不得发起任何请求；字体、图标、图片全部内联或用系统资源。**唯一例外**：用户**主动**点击【🎤语音】时，浏览器原生 `SpeechRecognition` 会连厂商服务（该连接由浏览器发起，不在应用代码内） | DevTools Network 面板除同源文档、以及用户主动开启语音时的识别请求外为空（NFR-07） |

### 0.2 设计取舍总纲

- **单页无路由**：产品只有一个工作面，路由只会增加状态同步成本。
- **本地优先（local-first）**：没有服务端，所有数据在浏览器里，这既满足隐私红线，也让离线、零成本部署同时成立。
- **同一套组件既做编辑态又做海报态**：视觉只有一份实现，避免「屏幕上看是 A，导出成 B」的经典问题（见 §9.3）。
- **能力可降级，功能不可缺失**：剪贴板、语音、PWA 都有降级路径，但核心的「录入 + 报表 + 海报」必须 100% 可用。

## 1. 技术选型与决策记录（ADR）

### 1.1 形态决策

**决策：纯前端 SPA，无后端、无账号、无数据库。**

| 备选 | 否决理由 |
|---|---|
| 前后端分离（Node + DB） | 引入部署成本、运维成本与学生个人信息合规风险；而产品没有协作需求，服务端 0 收益 |
| 桌面应用（Electron/Tauri） | 安装成本对「一个班一个老师」场景过重；浏览器书签足够 |
| 微信小程序 | 需要企业主体与审核，且 `html-to-image`、剪贴板写图片、语音识别能力受限 |
| 浏览器插件 | 分发成本高，且无宿主页面可挂载 |

**理由**：单机单用户、数据敏感不宜上云、需要高保真截图与剪贴板能力——浏览器是最合适的运行时。

### 1.2 框架决策

**决策：React 18 + TypeScript + Vite 5。**

- React：网格是典型的「高频小状态更新 + 大量同级节点」场景，`memo` + 细粒度 store 订阅足够；生态里 `html-to-image` 的示例与坑位文档最全。
- TypeScript `strict: true`：数据模型有 3 种值类型 × 3 种模式 × 多种状态，没有类型系统必然写错。
- Vite：冷启动快、产物小、PWA 插件成熟。

### 1.3 状态管理决策

**决策：Zustand 4 + 自研快照式撤销栈。**

| 备选 | 否决理由 |
|---|---|
| Redux Toolkit | 模板代码多；`entries` 是「一个对象里 120 个键」的高频局部更新，RTK 的不可变写法与 `useSelector` 开销都更重 |
| React Context + useReducer | 任一格变更会触发全部 `Cell` 重渲染，50×3 模式下掉帧 |
| Jotai / Valtio | 可用，但 Zustand 的 `subscribeWithSelector` + `useShallow` 已能精确控制，依赖更少 |

### 1.5 ADR 汇总表

| 编号 | 决策 | 一句话理由 |
|---|---|---|
| ADR-01 | 纯静态 SPA，无后端 | 隐私 + 零部署 + 离线 |
| ADR-02 | React 18 + TS strict + Vite | 类型安全 + 小体积 + 快 |
| ADR-03 | Zustand + 快照撤销 | 高频局部更新下最省开销且最不易写错 |
| ADR-04 | `localStorage` 主存 + `IndexedDB` 定时快照 | 主存快且同步易读，IDB 提供损坏回滚 |
| ADR-05 | `html-to-image` 渲染专用海报 DOM，**不截屏** | 视觉只有一份实现；可输出长图与 2× 清晰度 |
| ADR-06 | **自研 SVG 图表**，不引入图表库 | 只有环形/柱状/折线三种固定图形，需像素级贴合参考图；省 100KB |
| ADR-07 | Tailwind + CSS 自定义属性做设计令牌 | 主题集中、可读、构建后可摇树 |
| ADR-08 | 撤销用「快照」而非「命令逆操作」 | 命令逆操作在「清空/批量盖章/语音批量」上极易写漏；快照 120 人 × 50 层仅约 500KB，可接受 |
| ADR-09 | 语音用 `Web Speech API`，作为可选增强 | 零依赖、零成本；不支持时功能降级不影响主线 |
| ADR-10 | 不用 `react-router` | 单页面，路由只会引入状态同步问题 |

## 2. 总体架构

### 2.1 分层

```
┌─────────────────────────────────────────────────────────────────────┐
│  表现层 (views / components)                                        │
│   Header  ParamsBar  ActionsBar  StatsBar  ChartsCard  Grid  Cell    │
│   Modals: Settings / Report / Poster / ImportRoster / Confirm        │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ 只读订阅 + dispatch action
┌──────────────────────────────▼──────────────────────────────────────┐
│  状态层 (store)  —— 唯一可变状态源                                   │
│   Zustand: class / draft(record) / history / settings / ui / undo    │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ 纯函数调用（无副作用）
┌──────────────────────────────▼──────────────────────────────────────┐
│  领域层 (domain)  —— 纯函数，零依赖 DOM/store                        │
│   grades.ts   stats.ts   roster.ts   report.ts   voice-parse.ts      │
│   poster-model.ts   round.ts   wrap.ts                               │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ 副作用集中在此层，可替换
┌──────────────────────────────▼──────────────────────────────────────┐
│  基础设施层 (infra)                                                 │
│   persistence.ts  clipboard.ts  speech.ts  rasterize.ts  toast.ts    │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 数据流（单向）

```
用户按键
  → InputEngine.handleKey (components/grid/useInputEngine.ts)
  → dispatch(store action)  ── 同步更新 entries + focusedNo
  → React 重渲染（< 16ms）
  → [副作用] 变更订阅器 → scheduleSave(300ms 防抖) → localStorage
  → [派生] useStats / useRoster / useReport 选择器 → 统计条 / 报表 / 海报
```

**关键点**：统计、名单、报表**不是**在 action 里算好存进 state 的，而是用选择器从 `entries` 派生。这样「同步更新」是天然成立的，不可能出现「统计和网格不一致」（PRD BR-13/BR-16）。

## 4. 数据模型

### 4.1 领域类型（`src/domain/types.ts`，【必须】照抄）

```ts
export type Mode = 'homework' | 'quiz' | 'dictation';

export type Grade = 'A+' | 'A' | 'A-' | 'CHECK' | 'CROSS';
// CHECK = √（已交未评级）  CROSS = ×（未提交）

export type Stamp = 'none' | 'corrected' | 'excellent';

export type CellValue =
  | { kind: 'grade'; grade: Grade }
  | { kind: 'score'; score: number }      // 0–100，最多 1 位小数
  | { kind: 'text'; text: string };       // 听写默写原文，≤ 20 字符

export interface Entry {
  value: CellValue | null;
  stamp: Stamp;
  updatedAt: number;
}

/** 学号 -> Entry。键为 '1'..'120' 的字符串形式 */
export type Entries = Record<string, Entry>;

export interface Student {
  no: number;          // 1..120
  name?: string;       // 可选敏感字段
}

export interface ClassInfo {
  id: string;
  name: string;        // 班级名
  school: string;      // 学校名（海报署名）
  teacher: string;     // 教师名（海报署名）
  subject: string;     // 学科
  students: Student[]; // 长度 = 人数，no 从 1 连续
}

export interface RecordDoc {
  id: string;          // recordKey
  date: string;        // 'YYYY-MM-DD'
  content: string;     // 作业内容，≤ 20 字
  mode: Mode;
  entries: Entries;
  createdAt: number;
  updatedAt: number;
}

export interface HistoryEntry {
  id: string;          // 与 RecordDoc.id 同源（覆盖更新）
  date: string;
  content: string;
  mode: Mode;
  entries: Entries;
  metrics: SessionMetrics;   // 落盘时快照，避免历史重算
  savedAt: number;
}

export interface Settings {
  count: number;               // 班级人数 N（1–120），所有统计/名单/报表/海报的取值域恒为 1..count
  secondsJump: boolean;        // 秒跳
  showName: boolean;           // 显示姓名
  excellentLine: number;       // 优秀线，默认 90
  passLine: number;            // 及格线，默认 60
  honorIncludesA: boolean;     // 光荣榜是否含 A（常规作业），默认 false
}

export interface SessionMetrics {
  entered: number;
  avg: number | null;
  excellent: number;
  good: number;
  pass: number;
  fail: number;
  excellentRate: number | null;
  corrected: number;
  notSubmitted: number;
  max: number | null;
  min: number | null;
}

export interface RosterGroups {
  honor: number[];
  notSubmitted: number[];
  needsFix: number[];
  fixed: number[];      // 需更正但已盖「已更正」章（PRD §6.6），只用于报表第四段
}
```

### 4.2 持久化 Schema（`localStorage` 键 `xq.state.v1`）

```ts
export interface PersistedState {
  version: 1;
  classInfo: ClassInfo;
  drafts: Record<string, RecordDoc>;   // key = recordKey
  activeKey: string;
  history: HistoryEntry[];             // 最多 200 条
  settings: Settings;
  savedAt: number;
}
```

**约束**：
- `drafts` 中每个 `RecordDoc.id === key`。
- `activeKey` 必须存在于 `drafts`；加载时若不存在，取 `drafts` 中 `updatedAt` 最大者，或新建。
- 清理策略：`drafts` 若超过 90 条，按 `updatedAt` 淘汰最旧到 60 条（防止 localStorage 撑爆）。

### 4.3 版本迁移（`infra/persistence.ts`）

```ts
const CURRENT_VERSION = 1;

export function migrate(raw: unknown): PersistedState | null {
  if (!isObject(raw)) return null;
  const v = typeof raw.version === 'number' ? raw.version : 0;
  let data: any = raw;
  // switch (v) { case 0: data = v0ToV1(data); /* fallthrough */ }
  if (v !== CURRENT_VERSION) data = { ...data, version: CURRENT_VERSION };
  return validate(data) ? (data as PersistedState) : null;
}
```

- `validate()` 必须做**结构校验**（不只是 `JSON.parse` 成功），任何字段类型不符即返回 `null`，触发快照恢复。
- `validate()` 还必须**夹取阈值**：`settings.passLine = clamp(passLine, 0, 80)`、`settings.excellentLine = clamp(excellentLine, 80, 100)`，保证恒有 `0 ≤ 及格线 ≤ 80 ≤ 优秀线 ≤ 100`（PRD §6.1.2）。设置面板的输入同样走这个 `clampThresholds()`，越界时提示「已调整为最近合法值」。
- 迁移函数必须写单测（用旧版本样例 JSON）。

### 4.4 recordKey 设计

```ts
export function recordKey(date: string, content: string, mode: Mode): string {
  return `${date}||${encodeURIComponent(content)}||${mode}`;
}
```

- 使用 `encodeURIComponent` 避免内容里的 `||` 造成歧义。
- `content` 为空时用空串，键仍合法。
- 该键同时用作 `drafts` 的 key 与 `RecordDoc.id`，保证「同日期+同内容+同模式 = 同一条记录」（PRD BR-36）。

### 4.5 不变量（【必须】在 dev 模式下用 `invariant()` 断言）

| ID | 不变量 |
|---|---|
| INV-1 | `Object.keys(entries)` 中每个键都能解析为 `1..N` 的整数 |
| INV-2 | `score` 值 ∈ `[0, 100]` 且 `Math.round(score*10)/10 === score` |
| INV-3 | `text` 长度 ≤ 20 |
| INV-4 | `Entry.stamp ∈ {'none','corrected','excellent'}` |
| INV-5 | `value.kind` 与 `mode` 匹配：homework→grade，quiz→score，dictation→text |
| INV-6 | `drafts` 的每个 value 的 `id` 等于其键 |
| INV-7 | `history.length ≤ 200`，且 `id` 唯一 |
| INV-8 | 调小人数后，被隐藏的 entries **仍然存在**于 `entries` 中（只是不渲染） |

> INV-8 是 PRD AC-02.2/3 的实现保证：**永远不按人数裁剪 entries**，渲染时才过滤。

### 5.2 快照式撤销（`store/undoSlice.ts`）

**不做命令逆操作**，而是记录「变更前的 entries 与相关元信息」：

```ts
export interface UndoPatch {
  key: string;              // recordKey
  entries: Entries;         // 变更前的完整快照（浅拷贝 + 被改 Entry 深拷贝）
  count: number;            // 变更前人数
  focus: number | null;
  label: string;            // '录入' | '盖章' | '清空' | '批量盖章' | '语音' | '人数'
}
```

实现要点：
1. **在 mutation 之前**调用 `pushUndo()`；同一 tick 内多次 mutation 合并为一条（用 `batchLabel` + `requestAnimationFrame` 合并窗口 16ms）。
2. `entries` 快照用 `structuredClone`（现代浏览器均支持）或 `JSON.parse(JSON.stringify(...))` 的等价手写克隆；**必须深拷贝 `Entry`**，否则撤销无效。
3. 栈深 50；`redo` 在任意新 mutation 时清空。
4. 不持久化。

**体积核算**：120 人 × 每 Entry 约 80 字节 ≈ 10KB/层 × 50 层 ≈ 500KB 内存峰值，可接受。若未来支持 > 300 人，改为「仅记录被修改键的 diff」。

### 6.1 录入内核（`hooks/useInputEngine.ts`）★ 最重要

#### 6.1.1 焦点模型

- 单一事实来源：`focusedNo: number | null`。
- DOM 焦点：网格容器持有 `tabIndex={0}`，内部单元格用 **roving tabindex**（焦点格 `tabIndex={0}`，其余 `-1`），通过 `ref` 映射在 `focusedNo` 变化后 `.focus({ preventScroll: true })`，再用 `scrollIntoView({ block: 'nearest' })` 做最小滚动。
- **键位分两级（PRD BR-08）**，这是最容易实现错的一处：
  - **导航键**（`1`–`5`、方向键、`Tab`、`空格`、`Delete`/`Backspace`、数字/小数点）：监听挂在 **`Grid` 容器**的 `onKeyDown`（事件冒泡），减少 120 个监听器，也天然满足「输入框内不生效」。
  - **命令键**（`/`、`Esc`、`Ctrl+Z`、`Ctrl+Y`、`Ctrl+S`、`Ctrl+M`、`Ctrl+Enter`）：**必须**挂在 **`document`** 上（`useEffect` 装配），否则焦点在 Modal 或作业内容框时快捷键全部失效；入口统一过 `isEditableTarget()` 白名单。
  - 两者共用一个 `handleKey(e)` 纯函数，只是装配位置不同——**不能只装一份**。

#### 6.1.2 键处理管线（【必须】按此顺序短路）

```ts
function onKeyDown(e: React.KeyboardEvent) {
  // 0) IME 组合态一律放行（PRD BR-09 / AC-04.6）
  if (e.nativeEvent.isComposing || e.keyCode === 229) return;

  // 1) 可编辑元素内部的按键，除全局快捷键外一律放行
  const t = e.target as HTMLElement;
  const inEditor = t.tagName === 'INPUT' || t.tagName === 'TEXTAREA' || t.isContentEditable;

  // 2) 命令键（document 级装配）；编辑器内只放行 Esc / Ctrl+Z / Ctrl+S / Ctrl+Enter
  //    注意：此分支在 document 监听器里先跑，Grid 监听器里也要跑同一函数（幂等）
  if (handleGlobal(e)) return;

  if (inEditor) return;   // 3) 其余一律交给浏览器

  // 4) 网格导航
  if (handleNavigate(e)) return;

  // 5) 值输入（按模式分派）
  if (handleValueInput(e)) return;

  // 6) 盖章
  if (e.key === ' ') { e.preventDefault(); toggleStamp(focusedNo); return; }
}
```

#### 6.1.3 值输入分派

```ts
case 'homework':
```

**单元测试缓冲态设计（关键）**：
- `uiSlice.buffer: { no: number; text: string } | null`。
- 输入时 `buffer.text` 拼接，单元格实时显示缓冲内容（不写入 entries，避免每键一次持久化）。
- 提交时机：`Enter` / `Tab` / 方向键 / 失焦 / 秒跳触发 → `setValue`。
- `Esc` → 丢弃 buffer。
- 上限：整数部分 ≤ 3 位，小数 ≤ 1 位；超出忽略。
- `>100` → 截断为 `100` + `shake()`（PRD AC-03.3）。

> **决策**：为什么单元测试不采用「每次按键直接写 entries」？因为 87.5 需要按 4 个键，逐键写入会产生 4 条撤销记录、4 次持久化调度、以及中间值 8/87 的错误统计跳变。缓冲态让统计只在提交时跳变一次，符合老师直觉。

#### 6.1.4 秒跳（Auto-Advance）

```ts
function moveFocus(delta: number) {
  const n = classInfo.students.length;
  const from = focusedNo ?? 1;
  const next = from + delta;
  if (next < 1 || next > n) {
    if (delta > 0 && from === n) toast('已完成最后一格 ✓', 'ok');
    return;
  }
  setFocusedNo(next);
}
```

- 秒跳只影响「提交后是否前进」，不影响方向键与 Tab。
- 开关关闭时提交后播放 120ms `pulse` 动画（`data-pulse` 属性 + CSS 动画）。

#### 6.1.5 学号极速定位（`/` 键）

1. `/` → `setSearchOpen(true)`，把焦点移入搜索框（`autoFocus`）。
2. 输入数字 → `uiSlice.searchQuery`；渲染层面给匹配的单元格加 `data-match` 高亮（不改变布局）。
3. `Enter` → 若只有一个匹配则直接跳转；多个匹配时跳到当前候选（`candidates[0]`），`Tab` 在候选间循环。
4. `Esc` → 关闭并清空，焦点回到原单元格。
5. 跳转后：`setFocusedNo(no)` + `setSearchOpen(false)` + 清空 query。

#### 6.1.6 全选态

- `selection: Set<number>`；由【✨全选】切换为「**所有 `value !== null` 或 `stamp !== null`** 的学号，取值域 1..`s.count`」。
- 全选态下：不显示焦点环，显示粉色多选环；`空格`/`Delete` 作用于整个集合（批量盖章 / 批量清空各只产生一条撤销记录）。
- 全选态下 `1`–`5`、数字、方向键均不生效（见 PRD §4.6.5 状态矩阵）。
- `Esc` 退出全选，焦点回到 anchor。

#### 6.1.7 撤销/重做接线

- 在 `useInputEngine` 的 keydown 里处理 `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`，并 `preventDefault()`。
- 撤销后：`setFocusedNo(patch.focus)` + `scrollIntoView`。

### 6.3 统计引擎（`domain/stats.ts`，纯函数）★

```ts
export function computeStats(mode: Mode, entries: Entries, s: Settings): SessionMetrics
// N 恒取自 s.count（【唯一】人数来源）；不得从 entries 的键数量反推（BR-40：人数调小后隐藏键仍在 entries 里）
```

**算法（伪代码）**：

```
entered = 0; sum = 0; excellent = good = pass = fail = 0
corrected = 0; notSubmitted = 0; max = null; min = null

for (no = 1 .. s.count):                // N = s.count（BR-40：超出 count 的键保留但不参与计算）
  e = entries[no]
  if (e?.stamp === 'corrected') corrected++

  if (!e || !e.value) { notSubmitted++; continue }

  switch (mode):
    homework:
      switch (e.value.grade)
        'A+'    -> entered++, excellent++             (honorIncludesA 时 A 也 +excellent)
        'A'     -> entered++, good++   ; 若 honorIncludesA 则 excellent++ 且 good 不增
        'A-'    -> entered++, fail++   // 用于「需更正」计数，语义见下
        'CHECK' -> entered++
        'CROSS' -> notSubmitted++（不计 entered）
    quiz:
      x = e.value.score
      entered++; sum += x; max/min 更新
      if (x >= s.excellentLine) excellent++
      else if (x >= 80)         good++
      else if (x >= s.passLine) pass++
      else                      fail++
    dictation:
      k = classifyDictation(e.value.text)
      if k.kind === 'missing' { notSubmitted++ } else { entered++; perfect/error/other 分别计数 }
```

**映射到 PRD §6.1.2 的字段**：

| `SessionMetrics` 字段 | 各模式含义 |
|---|---|
| `excellent` | homework: A+ 人数（含 A 时按设置）｜quiz: ≥优秀线｜dictation: 全对 |
| `good` | homework: A 人数｜quiz: 良好｜dictation: 有错 |
| `pass` | homework: 恒 0（不展示）｜quiz: 及格｜dictation: 恒 0 |
| `fail` | homework: A- 人数（=需更正）｜quiz: 不及格｜dictation: 错≥4（仅用于着色统计） |
| `notSubmitted` | 三模式一致 |

> **注意**：PRD 里 homework 的统计条字段是「录入人数 / A+ / A / A- / 未提交 / 已更正」，与 `SessionMetrics` 的通用字段不是一一对应。实现上提供 `computeStats` 返回**通用指标**，再由 `StatsBar` 按模式取字段组合渲染。不要为了统计条去改引擎签名。

**平均值**：
```ts
avg = entered === 0 ? null : round1(sum / entered);
```

### 6.4 名单分拣（`domain/roster.ts`）★

```ts
export function classifyRoster(
  mode: Mode, entries: Entries, s: Settings

// 取值域恒为 1..s.count（BR-40），**不额外传 n**
```

**判定表（PRD §6.1.1，【必须】互斥）**：

| 模式 | 先判 暂未提交 | 再判 需更正 | 否则 光荣榜 |
|---|---|---|---|
| homework | 无 value 或 `CROSS` | `A-` **且未盖 `corrected`** | `A+`（`honorIncludesA` 时含 `A`） |
| quiz | 无 value | `score < passLine` **且未盖 `corrected`** | `score >= excellentLine` |
| dictation | 无 value 或 `missing` | `errors >= 1` **且未盖 `corrected`** | `kind==='perfect'` |

**第四组 `fixed`（PRD §6.6）**：命中「需更正」条件但已盖「已更正」章的学号单独进 `fixed`，用于报表的可选第四段。类型定义见 §4.1：`{ honor, notSubmitted, needsFix, fixed }`。

恒有 `needsFix ∩ fixed = ∅` 且 `needsFix ∪ fixed = 全部不及格/未达线学号`。

**互斥性【必须】用单测守住**：三个数组两两交集为空，且并集 ⊆ [1..N]、且 `∪` 之外的学号恰好是「不计入任何名单」的学号。

排序：三个数组均按学号升序。

### 6.6 海报渲染（`components/Poster.tsx` + `infra/rasterize.ts`）★

#### 6.6.1 为什么不用截屏

| 方案 | 问题 |
|---|---|
| `html2canvas(document.body)` 截当前页 | 会把工具栏、焦点环、滚动条一起截进去；长图要处理滚动拼接；分辨率不可控 |
| **专用海报 DOM + `html-to-image`**（【必须】采用） | 视觉可控、可 2× 输出、可长图、天然不含交互元素 |

#### 6.6.2 渲染流程

```
点击【📋截图发群】
 → setPosterLoading(true)
 → 渲染 <PosterRaster> 到屏幕外容器：
     position: fixed; left: -20000px; top: 0; width: 1080px; z-index: -1;
 → await document.fonts.ready                      ← 【必须】防缺字
 → await nextFrame() × 2                            ← 等布局稳定
 → await toPng(node, { pixelRatio: 2, backgroundColor: undefined, skipFonts: true })
 → 得到 dataURL → fetch(dataURL).blob() → objectURL → setPosterUrl()
 → setPosterLoading(false); 打开预览 Modal
```

**参数【必须】**：
- `pixelRatio: 2`（PRD BR-22）。
- `skipFonts: true`：**不内联 @font-face**。因为本产品只用系统字体，内联字体会显著拖慢并可能失败。同时 `tokens.css` 里禁止 `@font-face` 引用远程字体。
- `backgroundColor: undefined`：保留渐变背景（不能填白色，否则吞掉渐变）。

#### 6.6.3 海报图形与编辑态共享样式

```tsx
// Cell.tsx —— 编辑态

// Poster.tsx —— 海报态
<CellView variant="poster" entry={entry} mode={mode} no={no} />
```

`CellView` 内部：
- `variant==='edit'` → 加 `data-focus` / `data-selected` / `data-match` / `tabIndex` / `aria-*` / 事件。
- `variant==='poster'` → 只输出静态 `<div>` + 文字 + 角标，**不挂任何事件**，`pointer-events: none`。

**好处**：颜色/边框/字号只有一份 CSS 来源，海报不可能与屏幕不一致（PRD §4.5 与 §6.3 的「视觉完全一致」要求由结构保证，而不是靠人工比对）。

#### 6.8.3 语义解析（纯函数，可单测）★

```ts
export interface VoiceEdit {
  no: number;
  action:
    | { type: 'grade'; grade: Grade }
    | { type: 'score'; score: number }
    | { type: 'stamp'; stamp: Exclude<Stamp,'none'> }
    | { type: 'text'; text: string }
    | { type: 'clear' };
}

export function parseUtterance(text: string, n: number): VoiceEdit[]
```

**解析步骤**：

1. **归一化**：全角→半角（`１２`→`12`），去空白，`加`→`+`，`减`→`-`。
2. **抽取学号**：`/([0-9]+|[零一二三四五六七八九十百两]+)\s*号/g` → `toArabic()`。
   - 支持一句多号：`1号2号3号优秀` → `[1,2,3]`。
3. **抽取动作**（优先级从上到下）：
   | 正则 | 结果 |
   |---|---|
   | `取消\|清除\|不要` | `clear` |
   | `优秀\|很棒\|全对` | `stamp: 'excellent'` |
   | `已更正\|更正\|订正好的` | `stamp: 'corrected'` |
   | `(A加\|A\+\|甲加)` | `grade: 'A+'` |
   | `(A减\|A-)` | `grade: 'A-'` |
   | `([0-9]+(?:\.[0-9])?)\s*分` | `score` |
   | `错\s*([0-9]+|[一二三四五六七八九十]+)` | `text: '错N'` |
4. **学号越界**：`no > n` → 丢弃并在 `onUnmatched` 里回一句话术。

**中文数字转换 `toArabic`（【必须】支持 0–120）**：

```ts
const DIGIT: Record<string, number> = { 零:0, 一:1, 二:2, 两:2, 三:3, 四:4, 五:5, 六:6, 七:7, 八:8, 九:9 };

export function toArabic(s: string): number | null {
  if (/^[0-9]+$/.test(s)) return Number(s);
  if (s === '一百') return 100;
  // 处理 一百二十 / 一百零五 / 十 / 十二 / 二十 / 二十三
  let result = 0, section = 0, current = 0;
  for (const ch of s) {
    if (ch === '百') { section += (current || 1) * 100; current = 0; }
    else if (ch === '十') { section += (current || 1) * 10; current = 0; }
    else if (ch in DIGIT) { current = DIGIT[ch]; }
    else return null;
  }
  result = section + current;
  return result > 0 ? result : null;
}
```

## 8. 核心算法

### 8.1 四舍五入（`domain/round.ts`）★ 浮点陷阱

```ts
/** 保留 1 位小数，四舍五入（half-up），规避 87.65*10 = 876.4999 的浮点误差 */
export function round1(x: number): number {
  return Math.round((x + Number.EPSILON) * 10) / 10;
}

/** 转成「十分位整数」，用于分段比较，彻底消除浮点比较 */
export function toTenthInt(x: number): number {
  return Math.round(x * 10 + Number.EPSILON);   // 90.5 -> 905
}
```

**【必须】的分段判定用整数比较**：
```ts
const t = toTenthInt(score);          // 0..1000
const ex = toTenthInt(s.excellentLine);  // 900
const gd = toTenthInt(80);               // 800
const ps = toTenthInt(s.passLine);       // 600
if (t >= ex) excellent++; else if (t >= gd) good++; else if (t >= ps) pass++; else fail++;
```
> 这样可以正确处理：`89.95`（不存在，因最多 1 位小数）、`90` 归优秀、`80` 归良好、`60` 归及格；**并且允许用户把优秀线改成 85 等值时区间自动重排**。

**边界说明（写进单测）**：
| 输入 | `round1` | 说明 |
|---|---|---|
| 87.65 | 87.7 | half-up |
| 87.675 | 87.7 | |
| 87.05 | 87.1 | EPSILON 修正 |
| 1753.5/20 = 87.675 | 87.7 | 与 PRD 样例 A 一致 |

### 8.2 名单折行（`domain/wrap.ts`）

```ts
/** 中日韩字符宽度 2，半角 1 */
export function charWidth(ch: string): number { return /[\u4e00-\u9fa5\u3000-\u303f]/.test(ch) ? 2 : 1; }

/**
 * 把 token 数组折成多行，每行显示宽度不超过 maxWidth
 * @param tokens 形如 ['1号、','2号、',...]（除最后一个外都带分隔符）
 */
export function wrapTokens(tokens: string[], maxWidth: number, sep = '、'): string[]
```

- `maxWidth` 取 `70`（**半角单位**：CJK 与全角标点记 2，数字/字母记 1），与 PRD BR-19 一致。
  - 换算：`1号、` = 5 单位 → 单数 14 个/行；`12号、` = 6 单位 → 双数 11 个/行。
  - 该值能**唯一**复现 PRD §7.1.3 的折行（光荣榜 70 单位单行；暂未提交按 11/11/8 折三行）。阀值取 66–69 会使光荣榜折成两行，取 72 以上会使暂未提交变成 12/12/6——**均不得改动**。
- 实现：累加宽度（**含** token 尾部 `、`），若「当前行宽度 + 下一个 token 宽度 > maxWidth」则先换行再放；渲染时行尾去掉 `sep`。
- 折行时**不拆分 token**；行尾若留有 `sep` 则去掉。

### 8.3 学号模糊匹配

```ts
export function matchStudents(query: string, n: number): number[] {
  const q = query.trim();
  if (!q) return [];
  return Array.from({ length: n }, (_, i) => i + 1)
    .filter(no => String(no).includes(q));
}
```
- 输入 `1` → `[1,10..19,21,31,...,100..120 中的含 1 者]`（精确优先排序：`startsWith` 优先于 `includes`）。

#### 8.4.1 DonutChart

### 8.5 海报高度自适应

```
海报 DOM 不设固定高度：
  外容器 width: 1080px
  卡片 padding: 40px
  网格：grid-template-columns: repeat(10, 1fr); gap: 12px
  行数 = ceil(n / 10)
→ 高度由内容自然撑开，toPng 会输出完整长图（html-to-image 按节点 scrollHeight 计算）
```
**尺寸推导（不要写死单元格宽度）**：外容器 1080 − 左右留白 48×2 = 卡片 984 − 内边距 40×2 = **内容宽 904px**；10 列 + 9 个 12px gap → 单元格宽 = (904 − 108) / 10 = **79.6px**，高固定 `60px`，等级字号 `24px`、**学号字号 `12px`**。**禁止**给单元格写 `width: 96px` 之类的固定值（10×96+108=1068 会横向溢出 164px），一律用 `1fr` 让浏览器算。
**【必须】检查**：`html-to-image` 对 `position: fixed` 且 `left:-20000px` 的节点要显式传 `width/height`：
```ts
const rect = node.getBoundingClientRect();
await toPng(node, { width: rect.width, height: rect.height, pixelRatio: 2, skipFonts: true });
```

- `homework`：`A+ → green`、`A → green`（浅一档，见 §10 的 `.tone-a`）、`A- → amber`、`√ → blue`、`× → gray`。
- `dictation`：`0 错 → green`、**`1–3` 错 → amber**、**`≥4` 错 → red**、`缺交/未交 → gray`、其他文本 → `blue`（与 PRD §4.5.3 一致）。

## 11. 错误处理与降级矩阵

| 场景 | 检测方式 | 降级策略 | 用户可见反馈 |
|---|---|---|---|
| `localStorage` 不可用/超限 | `setItem` 抛错 | 仅内存态运行 | 顶部黄色警告条 + 提示导出备份 |
| 数据损坏 | `migrate/validate` 返回 null | 从 IDB 快照恢复；再失败则初始态 | Toast「已从自动备份恢复」/「数据损坏，已重置」 |
| 剪贴板文本失败 | `writeText` reject | 选中文本 + 提示手动复制 | Toast |
| 剪贴板图片不可用 | 无 `ClipboardItem` | 自动下载 PNG | Toast「已下载图片」 |
| 海报生成失败 | `toPng` reject | 重试一次 → 仍失败则提示 | Toast「海报生成失败，请重试」 |
| 语音不支持 | 无构造器 | 按钮禁用 | tooltip |
| 麦克风被拒 | `onerror` | 停止并提示 | Toast |
| 多标签页写冲突 | `storage` 事件 | 提示刷新 | 顶部提示条 |
| 字体emoji缺失 | 无法检测 | 使用系统 emoji，不强求一致 | — |
