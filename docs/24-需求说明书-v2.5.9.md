# 24 · 需求说明书 · v2.5.9

> 版本：2.5.9
> 起因：用户反馈（原话，2026-10-26）：「1. 登记等级需要增加 B- 选项。2. 通过标记在 Mac 上显示成根号（√），Windows 上是正确的 ✔——查字体。3. 老师建了 2 个班，填完 17 班质量监测切回常规作业，常规作业登记『没了』。4. 登记了两个常规作业时生成不了第二个常规作业的图，质量监测同样问题。检查所有类似操作。」
> 定性：前两条是**登记表的身份口径**问题，第三条是**码位**问题，第四条是**阶梯不完整**。**不涉及任何数据丢失**——对照老师当天的真实备份，四张表的数据全部完好。

## 1. 现场

- 老师建了两个班（19 班 / 17 班）。17 班录了质量监测后切回常规作业，常规作业的登记「不见了」。
- 同一天的同一模板登记了两张表（不同内容）后，第二张表在「选择登记表」里根本不出现，海报只能出第一张。
- 手工过关的标记在 Mac 上显示成根号。
- 对照当天备份（10-26 导出）：4 张记录全在，17 班 42/42、19 班 55/55、19 班「岳阳楼」24 条——数据一条不少。**「没了」是入口关闭，不是数据丢失。**

## 2. 根因与修复

### FR-64.1 表的真实身份是完整 key，不是 sheetId

记录键的格式是 `classId|date|content|sheetId`；同一天的多张"表"共享同一个默认 sheetId。
`selectSheetsOfDay` 按 `sheetId` 去重 → 同一模板的第二张表永远不会出现在「选择登记表」列表里（问题 4 的直接原因）。改为按完整 key 去重。

### FR-64.2 海报的单表解析也跟着身份走

`selectPosterBySheet` 原来找"第一个 sheetId 相符的记录"——多表场景必然拿错。改为按完整 key 解析（records → history → draft 三级回退）。INV-23 的单表校验、OutputBar、PosterModal 的下拉选项同源，一并改为 key。

### FR-64.3 切回模板时不该落回空表

`switchTemplate` 原来只跳到该模板的默认 sheetId。老师填完质量监测（内容 X）切回常规作业，落到的是 `<班>|<日>|<X>|默认作业表` 这张**新空表**；她原来的数据在另一张表里，入口被关上了。改为：优先落到当天该模板**最近一条已有记录**，没有才开新表。

### FR-64.4 B- 配色：单源原则被打破

`GRADE_TONE` 是格子配色的唯一来源，CSS 的 per-grade 块必须逐档同步。tone.ts 加了 B- 条目，CSS 块没有 → B- 格子回退到通用 amber 背景。E2E-30 直接暴露了这一点。补上规则，与 tone.ts 保持逐字同源。

### FR-64.5 八档阶梯（问题 1）

Union、百分表（`B-` = 75，介于 B 80 与 C 70 之间）、RANK 重编、keymap 上限 1..7 → 1..8、语音解析、存储校验、海报统计顺序全部同步。
两个刻意保留的口径：
- 常规作业默认档保持 PRD §2.2 原案（不含 B+），但加入 B-；
- `voice/normalize.ts` 早就写了 `b减 → 'B-'` 的映射——规划过但阶梯从没落地，这次闭环，语音「B减」从模糊匹配（落到 B）变成精确命中。

**关键决策**：`roster.ts` 的光荣榜/需更正阈值原来是魔法数字 5/6（绑定旧 RANK 编号）。改为从 `RANK['A']` / `RANK['A-']` 推导。"字母秩 ≥ A 进光荣榜、A- 及以下进需更正"的语义不变，golden 样例测试一字不改；将来任何阶梯变动都不会再把阈值带偏。

### FR-64.6 导出「登记表数」同样按 key

`buildSummaryCsv` 的「登记表数」原来按 `sheetId` 去重——同模板多表又被合并成 1 张。改为按完整 key 统计。这是「检查所有类似操作」的最后一项：选择列表、单表海报、切模板落点、导出汇总全部走 key。

### FR-65.1 ✓ 不是字体问题，是码位本身（问题 2）

手工过关的主值一直是 **U+221A**——它在 Mac（PingFang）上就是根号；Windows（YaHei）恰好把 U+221A 渲染成 ✔。所以这不是"字体渲染不一致"，是代码输出的码位本身就是根号，只是 Windows 碰巧显示得像勾。显示层（格子、海报、CSV 导出）统一改为输出 **U+2713**，与角标同源；输入仍接受手打的 √。
这个修复是字体无关的：同一个码位在两台设备上必然一致——这是确定性修复，不需要按平台打字体补丁。Mac 真机无法在本机验证，请老师用 A-138 场景在 Mac 上确认一次。
