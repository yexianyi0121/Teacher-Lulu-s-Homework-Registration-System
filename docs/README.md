## 各版本结论速查

### v2.6.4：按表导出表格、过关标记清空、听写开关归位、方案提示与界面微调

结论：**「手打过关」是独立于「值」的一种登记状态**——它不写在 `CellValue` 里，清理逻辑必须单独看 `Entry.pass`，否则只清值不清标记，界面就会一直挂着 ✓。见 [29-修复日志-v2.6.4.md](./29-修复日志-v2.6.4.md)。

1. **表格导出让老师拿得走**：设置里按日期勾选若干张表，导出 CSV（一表一块，含班级 / 日期 / 登记表 / 作业内容 / 评价语 + 每生一行），Excel 双击直接打印。
2. **取消「允许 ✓ 过关标记」会真的清干净**：先二次确认，确认后标记与不兼容的值一起清，界面立即刷新；只改了标记时不再「什么都不发生」。
3. **听写开关只出现在听写 / 默写表**：名称统一为「听写/默写全对自动算过关」，其他模板看不到它。
4. **当前方案一眼可见**：参数行常驻「本表方案」chip（方案类型 + 过关规则），点开即进本表设置。
5. **界面更像给人用的**：系统名放大换楷体、去掉花、时间学期贴标题右侧；学科改初中口径；作业内容输入框收窄、新建登记改实底主色；设置里不再留过关规则的历史提醒。

### v2.6.3：过关规则随方案走、改方案二次确认、新建登记、时钟学期版本号

结论：**过关规则是方案的一部分**——它跟着 `ScoringScheme` 走（等级制看白名单、分数制看档位、混合制两套并存），不再有全局 `settings.passRule`；老的全局配置在载入时迁移进每条记录，不丢。见 [28-修复日志-v2.6.3.md](./28-修复日志-v2.6.3.md)。

1. **等级值不再被及格线兜底**：等级制 / 混合制下，某个等级算不算过关只看本表勾选的白名单，A-（90%）不会再因为过 60% 线而自动过关。
2. **分数制可挑档位**：新增「达到及格% / 良好% / 优秀% 才过关」，想只让优秀过关就选优秀档，不必改及格线的定义。
3. **过关规则搬进本表设置**：系统设置里只剩一句「已搬到本表设置」的说明，方案类型与过关口径在同一张面板里。
4. **改方案先问再清**：点「完成」时按新方案比对已登记值，有不兼容的就二次确认；确认后清空并记一条撤销，取消则方案整体回滚。
5. **新建登记才建表**：作业内容变成「待新建的名称」，点「＋ 新建登记」（或回车）才建表；同名直接切回，不再一个字一张表。
6. **界面信息补齐**：顶栏显示当前时间与学期（窄屏留时分秒）、页脚显示版本号、默认背景纯白。

### v2.6.2：选择器只列已登记表、登记表可删、缺交请假可选、按表删评价语

结论：**删表不能借道 `switchRecord`**——它会把当前草稿写回 `records` 并触发 `commitIfDirty`，删掉的表会自己回来。见 [27-修复日志-v2.6.2.md](./27-修复日志-v2.6.2.md)。

1. **选择器不再列空表**：只收 `hasEntries` 的表，当前正在编辑的表恒保留；随手打字的空表不再变成永久选项。
2. **登记表可以删了**：参数行「删除此表」二次确认，`deleteRecord` 同时清 `records` 与 `history`；删当前表时直接落到同模板当天最近的记录。
3. **缺交 / 请假可选是否算过关**：`PassRule` 增加 `missingPass` / `leavePass`（默认 false，老数据行为不变）。
4. **按表删评价语**：汇总模式每张表各有「删除评价语」按钮，删除即重新生成。

### v2.6.1：过关规则说清、及格% 下限、B- 两处遗漏、未启用等级入口

结论：**mixed 的百分兜底是规格原文，不改；补的防线放在阈值与入口上**。见 [26-修复日志-v2.6.1.md](./26-修复日志-v2.6.1.md)。

1. **过关规则说清了**：`mixed` 下等级值达到本表及格线时同样算过关（百分或等级取并集），设置里写明并列出当前勾选。
2. **及格% 有下限了**：低于 5% 拒绝入库并提示，避免及格线过低导致几乎人人过关。
3. **B- 的两处遗漏补上了**：`GRADE_LETTERS` 与 `GRADE_ORDER` 对齐；手机键盘等级行允许换行、每键可缩，375px 屏 8 档见得到也点得到。
4. **未启用等级有入口了**：提示条多一个「未启用…，点此添加」，一步到本表设置。

### v2.5.10（已并入 2.6.0）：主屏多表切换、按表评价语、表情版位、提示条键位与大屏适配

结论：**没有一条是数据丢失**。见 [25-修复日志-v2.5.10.md](./25-修复日志-v2.5.10.md)。

1. **主屏可以切表了**：同模板多张表只出现在海报预览的下拉里，主界面看不到第二张——新增主界面「选择登记表」，只在确有多张表时出现，切换走 `switchRecord` 落回原记录（不是新建）。
2. **汇总评价语按表写**：原来整张汇总只能写一条页脚语；现在每张表各写各的，仍与整图页脚语并存。
3. **表情不再压等级**：表情从「跟在主值后面 inline」改成主值下方独立一行，三种尺寸分别给字号；汇总格原来直接 `display:none`，现在正常显示。
4. **提示条看得懂键位**：当前方案启用的等级做成带键号的色块，配色与该等级格子一致，长等级链不再被省略号裁掉。
5. **界面跟着屏幕走**：`.app-inner` 的 1440px 上限解除，令牌按 1600/1920/2560 三档逐级放大。

### v2.5.9：表的身份、B- 档与 ✓ 码位

结论：**没有一条是数据丢失**，对照老师当天的真实备份四张表全在。见 [24-需求说明书-v2.5.9.md](./24-需求说明书-v2.5.9.md)。

1. **表的身份是完整 key**：记录键是 `classId|date|content|sheetId`；同一天的同模板多张表共享默认 sheetId。按 sheetId 去重 → 第二张表永远选不到、海报拿错表。全部改按 key。
2. **切模板不许落回空表**：`switchTemplate` 落当天该模板最近一条已有记录——「登记没了」是入口被关上，不是数据丢。
3. **✓ 是码位问题不是字体问题**：手工过关主值一直是 U+221A（它本身就是根号），Windows 恰好渲染得像勾。显示层统一输出 U+2713，输入仍接受 √。
4. **八档阶梯**：百分表 B- = 75、keymap 上限 1..8；名单阈值从魔法数字改为从 `RANK['A']` / `RANK['A-']` 推导。
5. **CSS per-grade 块必须逐档与 GRADE_TONE 同步**：B- 缺规则回退通用 amber，被 E2E-30 当场抓住。

### v2.5.8：海报与汇总图的显示问题

五个独立缺陷，都在显示层，不涉及数据。见 [23-需求说明书-v2.5.8.md](./23-需求说明书-v2.5.8.md)。

1. **属性不渲染，CSS 规则就永远不会生效**：`[data-len="3"]` 字号阶梯一直存在，但 `CellView` 从来没输出 `data-len` 属性。已补上并进测试。
2. **格子分上下两条带**：上带学号/印章、下带主值/右下角标。只放大格子解决不了重叠。整格状态（假/缺交）去重角标。
3. **汇总 mini 格不许定死宽度**：改弹性列占满卡片，与海报同一套分区。
4. **海报弹窗单独一档**：新增 `poster` 档 `min(1240px, 100%)`，近似 1:1。
5. **可选字段不能崩整个应用**：`defaultComment` 老数据可能缺，弹窗组件自己兜底。

### v2.5.7：数据事故修复（必读）

老师实机反馈「上方一直有数据为空的提示，点了清空并重来也没用」，实为三个叠加缺陷造成的**真实数据丢失事故**。
见 [22-需求说明书-v2.5.7.md](./22-需求说明书-v2.5.7.md)。

1. **打开看到的不是今天的表**：原来取 `updatedAt` 最大的记录当草稿，今天的成绩写进昨天那条记录，覆盖昨天的数据。现在：今天有内容→今天；否则→库里最近的记录，且硬保证 `draft.key === 该记录自身 key`。
2. **录入根本没存盘**：`exportState()` 不含当前草稿 → 录一整天不切表就关浏览器，数据全丢。
3. **覆盖保护误判**：把「今天还没录」当成「数据被清空」→ 永久只读，且清除后仍为空、仍被拦，出不来。

## 编码前必看的高危点

1. **过期闭包**：凡是「切换」类按钮，回调参数必须是**目标值**，不许读闭包。
2. **写盘守门**：`main.tsx` 必须先 `await loadState()` 再 `render`；`useAutoSave` 在 `booted` 之前必须直接 return；`saveState` 必须过 `shouldBlockOverwrite`。
3. **`file://` 与 `http://` 是不同 origin**：数据不互通，必须给老师显式提示，不要静默。
4. **`0.9*100 = 90.00000000000001`**：所有阈值比较走 `gtePct` 整数标尺，禁止改回浮点。
5. **等级色与统计色是两套**：不要把 `tierTone()` 用在等级格子上。
6. **`mixed` 方案的 `maxScore` 必须兜底 100**：否则分数折算为 `null` → 全灰。
7. **本周汇总不许缩放**：1:1 的 2× DPR，宽 1080 逻辑像素；超 16000px 分卷，不要缩小字号硬塞。
8. **颜色/焦点别进 store 持久化**：`cellError`、`filterNotPassed` 都是 UI 态，刷新重置。
9. **点格子必须退出多选**：否则老师以为「批量没生效」。
10. **撤销要把焦点放回被改的那一格**：否则下一个按键记到别人头上。
11. **弹窗/确认框开着时禁用全部录入快捷键**：Enter 是最容易误触的。
12. **「录入值」不能静默改写缺交/请假状态**：必须留下补交痕迹。
13. **双击编辑框内容未变则不提交**：否则 `A+` 会被提交成文字、掉出优秀率。
14. **写盘前比对磁盘指纹**：多窗口场景不许静默整表覆盖。
15. **值口径与当前方案不符时不参与名单判定**：切分数制后存量等级不该还挂榜上。
16. **空数据不许照常出报表/海报**：一份「全员未提交」发到群里就是事故。
17. **Toast 要有优先级与足够寿命**：「可撤销」这类信息不能被 3 秒后的备份提醒顶掉。
18. **改格子布局前先跑 `tests/component/fr63-cell-render.test.tsx` 并重新截图对照**：`data-len` 属性曾经不渲染，字号阶梯规则就永远没生效（v2.5.8，见 [23-需求说明书-v2.5.8.md](./23-需求说明书-v2.5.8.md)）。
19. **改「选择登记表 / 单表海报 / 切模板落点」前先跑 `tests/unit/fr64-sheet-identity.test.ts`**：表的身份永远是完整 key（`classId|date|content|sheetId`），不是 sheetId——同模板多表共享默认 sheetId，按 sheetId 去重会把第二张表吞掉（v2.5.9，见 [24-需求说明书-v2.5.9.md](./24-需求说明书-v2.5.9.md)）。
20. **改表情版位或格子高度前先跑 `tests/e2e/v5-feedback.spec.ts` 的 FR-67.1**：它同时盯主网格与汇总格两处，而汇总格只存在于屏幕外的 `.poster-stage`（`left:-20000px`）里，且生命周期只有几百毫秒（v2.5.10，见 [25-修复日志-v2.5.10.md](./25-修复日志-v2.5.10.md)）。
21. **不要把 `mixed` 改成白名单优先**：`docs/05` FR-32 规则 2 明写「百分或等级取并集（默认）」，改了就是推翻规格；老师觉得「D 也自动过关」时，要查的是及格% 与勾选的等级，不是 `isPassed()`（v2.6.1，见 [26-修复日志-v2.6.1.md](./26-修复日志-v2.6.1.md)）。
22. **删表不要借道 `switchRecord`**：它会把当前草稿写回 `records` 并触发 `commitIfDirty` 进历史，等于没删；`deleteRecord` 必须自己算好落点并直接 `set`（v2.6.2，见 [27-修复日志-v2.6.2.md](./27-修复日志-v2.6.2.md)）。
23. **手打过关标记（`Entry.pass`）不在「值」里，清理时要单独判**：键 `G` 会把 `value` 顶成 `null` 只留 `pass: true`，`pruneEntries` 若按「没有值就是空格子」提前 `continue`，就永远清不到这类格子——老师看到的就是「取消了开关却什么都不发生」（v2.6.4，见 [29-修复日志-v2.6.4.md](./29-修复日志-v2.6.4.md)）。
24. **改方案 / 改满分后一定要 `pruneEntries` 再落库**：方案变了，旧值可能已经不属于这张表（等级制改分数制、满分 100 改 120），清空必须记撤销并先二次确认；同时 `normalizeScheme` 要把旧 `settings.passRule` 迁进每条记录，否则老师的过关配置会在升级时悄悄丢（v2.6.3，见 [28-修复日志-v2.6.3.md](./28-修复日志-v2.6.3.md)）。

## 三不可让步点

1. **数据不丢**：任何版本升级、任何操作，都不能让老师的登记变少；出问题必须能从备份/快照/JSON 恢复。
2. **输出逐字对**：报表文案、样例 A/B/C 的数字与名单，一位都不能错。
3. **不联网**：除用户主动点语音外，不得有任何请求。
