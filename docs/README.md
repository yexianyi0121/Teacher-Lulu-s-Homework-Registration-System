## 编码前必看的 8 个高危点

| # | 坑 | 出处 |
|---|---|---|
| 1 | 秒跳只管「提交后前进」，不管输入过程；单元测试必须按 `Enter` 提交，否则 `87.5` 输不完 | PRD FR-04 |
| 2 | 键位两级：导航键挂 `Grid`、命令键挂 `document`（过 `isEditableTarget`），只挂一处会有一半快捷键失效 | 设计 §6.1.1 |
| 3 | 折行按显示宽度 **70 半角单位**（`1号、`=5，`12号、`=6），不是按人数；66–69 会折错、≥72 变 12/12/6 | 设计 §8.2 |
| 4 | **档位比较必须整数化**：`p*10 >= round(rate*1000)`，否则 `0.9*100=90.000…01` 会把 `A-`（90）误判成良好 | 设计 §8.1 / §16-1 |
| 5 | **名单口径 ≠ 四档口径**：等级值按字母秩判名单、分数值按百分判；用 `tierOf` 判名单会把 `A-` 塞进光荣榜 | PRD §2.3.1 |
| 6 | `D` 折算 **55%** 不是 60%（否则 D 会被判成「及格」，与「D=不合格」矛盾） | PRD §2.2 / 设计 ADR-13 |
| 7 | `√`/`×` **不是等级**：`√→pass=true`、`×→status='missing'`；迁移时最容易漏 | 设计 §4.6.2 |
| 8 | 迁移必须**先备份再升级**、失败只读不覆盖；`migrate()` 是纯函数 | 设计 §4.6 / ADR-20 |

## 产品的三个不可让步点

1. **全键盘录入**：一次按键完成「定位 → 赋值 → 前进」，手离开键盘即算失败。
2. **零手工统计**：统计条、图表、各名单全部由录入数据派生，不存在第二份真相。
3. **一键对外**：报表文案、海报图片、当日汇总图都能直接进剪贴板，粘贴到微信即为成品。
