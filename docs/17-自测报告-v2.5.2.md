# 自测报告 v2.5.2（FR-54 只读卡死与 xlsx 导入修复）

> 版本：2.5.2　提交：`ad201b6`　基线：`5c93b75`（v2.5.1）
> 触发：老师实际使用中把 `7.19名单.xlsx` 导入花名册后，班级被改成乱码姓名，系统锁死在只读，无法继续任何操作。

---

## 1. 事故还原

| 项 | 内容 |
|---|---|
| 操作 | 花名册 → 📁 导入花名册 → 📂 选择 CSV / TXT → 选 `7.19名单.xlsx` |
| 现象 1 | 班级从 55 人变成 66 个乱码姓名 |
| 现象 2 | 界面顶部出现只读横幅，Toast 提示「数据升级失败进入只读模式，请先导出备份」 |
| 现象 3 | 横幅只有一个「导出备份」按钮，无法关闭，无法继续录入 |
| 现象 4 | 即使从设置里成功「导入恢复」，横幅依旧存在，改动仍不保存 |

现场文件：`7.19名单.xlsx`，14168 字节，真实 Excel 2007+ 工作簿。

---

## 2. 根因（四层，逐层独立验证）

### B1 乱码被当成学生姓名（根因，最严重）

`xlsx` 本质是 ZIP 容器。原流程：

1. `<input accept=".csv,.txt,...">` 在部分浏览器/系统对话框下仍可选中 `xlsx`；
2. `decodeCsv()` 用 UTF-8 解码二进制 → 得到大量控制字符与替换符；
3. `parseRosterText()` 只按换行切分，任何「不以纯数字开头」的行都成为一条学生记录；
4. `warnings` 为空数组，界面上**没有任何提示**。

实测（用真实文件跑 `parseRosterText(decodeCsv(buf))`）：

```
解析出学生数= 66
前5个= [{"no":1,"name":"PK\u0003\u0004"},
        {"no":2,"name":"\u0000\u0000...嘚釦..."},
        {"no":3,"name":"藡鴙...白zXBㄨ烏祌"},
        ...]
warnings= []
```

### B2 只读原因不分（误导性文案）

`App.tsx` 的只读横幅文案**写死**为「数据升级失败」，而 `setReadOnly(true)` 有三个调用来源：

- `main.tsx` → `NEWER_VERSION`（更新版本写的）/ `UNKNOWN_STATE`（结构无法识别）/ `MIGRATE_FAILED`
- `useAutoSave.ts` → `BLOCKED_OVERWRITE`（阻止空覆盖）

老师看到「升级失败」根本不知道该怎么办，而且这个说法在她的场景里是**错的**——她既没升级也没迁移。

### B3 只读状态没有任何自救出口

横幅只有一个按钮「导出备份」。设置里虽然有「🗑️ 清空全部数据」，但那是把一切删光的核选项，不是「丢掉坏数据、保留能用的部分」。老师实际上被锁死。

### B4 导入成功却不解除只读（最隐蔽）

`replaceState()` 重置了 `focusedNo / selection / undoStack / modal` 等**一长串**状态，唯独没有重置 `readOnly`。

实测：只读态下用一份完全正确的 v4 备份执行「导入恢复」→ Toast 显示「已恢复数据（导入前的数据已留底）」，但：

```
导入后 只读横幅= 1   （仍是只读）
敲字后磁盘 records= -1（解析失败，说明根本没写进去）
```

老师会以为恢复成功，实际什么都没保存。

## 3. 修复方案

### B1 — 字节级文件类型判定 + 乱码兜底

`src/domain/roster-import.ts` 新增：

```ts
export function looksLikeNonText(buffer: ArrayBuffer): boolean
export function nonTextFileHint(fileName: string): string
```

判定规则：ZIP 魔数 `50 4B 03 04`（xlsx/docx/zip）、OLE 魔数 `D0 CF 11 E0`（xls/doc）、以及控制字符占比 > 2%（放过 TAB/LF/CR）。

`parseRosterText()` 增加第二道闸：文本中 U+FFFD 占比 > 1% 时直接返回 `fatal`，`students` 恒为空。

`ImportRosterModal` 前置拦截：命中即显示红色错误条，明确告诉老师**该怎么做**：

```
「7.19名单.xlsx」没法导入
这是 Excel 文件，系统读不了。请用 Excel 打开后「另存为 → CSV」，再导入那个 CSV。
正确做法：用 Excel 打开名单 → 文件 → 另存为 → 选「CSV UTF-8（逗号分隔）」→ 再回到这里导入那个 CSV。
也可以直接把名单复制粘贴到下面的输入框里。
```

同时把 `accept` 放宽为 `.csv,.txt,.xlsx,.xls`——**故意让 xlsx 可选**，这样老师得到的是明确报错，而不是「文件选不了、不知道为什么」。

### B2 — 只读原因结构化

- `store-types.ts`：新增 `readOnlyReason: 'MIGRATE_FAILED' | 'UNKNOWN_STATE' | 'NEWER_VERSION' | 'BLOCKED_OVERWRITE' | null`
- `setReadOnly(v, reason?)` 签名扩展
- `main.tsx` / `useAutoSave.ts` 传入具体原因
- `App.tsx` 按原因给三套文案

### B3 — 三个自救出口

只读横幅改为：

| 按钮 | 作用 |
|---|---|
| 导出当前数据 | 导出内存中的可用数据（可能不全） |
| 下载原始数据 | 把无法解析的原始存储文本原样下载，供以后修复 |
| 清空并重来 | 二次确认 → `resetAll()` → 恢复正常可写 |

### B4 — 导入即解除只读

`replaceState()` 显式追加：

```ts
readOnly: false,
readOnlyReason: null,
blockedOverwrite: false,
```

### 顺带修复：日期敏感的既有 E2E

`tests/e2e/v3-week.spec.ts` 用 `iso(0)/iso(-1)/iso(-2)` 取三天，断言「7 天里 4 天没登记」。每逢周一/周二这三天会跨周，本周汇总里只剩 1~2 张登记、空日变 5~6 个，用例必然失败。已在干净基线上复现确认是既有缺陷（非本次引入）。改为 `currentWeekDays(3)` 锚定「本周一往后三天」。

## 5. 未做与后续建议

1. **真正解析 xlsx**：本次是「明确拒绝 + 给出替代路径」，不是「支持导入 xlsx」。若要直接读 xlsx 需引入 SheetJS（约 400KB），与「零依赖、单文件离线」的产品原则冲突，建议不做。若老师坚持，可考虑独立转换页。
2. **已入乱码的班级如何修**：老师若已导入乱码名单，可在花名册里「🗑️ 清空全部数据」后重来，或导入之前导出的备份（现在能真正恢复可写）。
3. **`MIGRATE_FAILED` 实际不可达**：当前 `migrate()` 只抛 `UnknownStateError`，因此该枚举值暂时是死代码，保留是为将来迁移逻辑可能抛出的其他异常留位。
