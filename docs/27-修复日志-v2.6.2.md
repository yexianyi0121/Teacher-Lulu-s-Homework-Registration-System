# 27 · 修复日志 · v2.6.2

> 版本：2.6.2
> 性质：用户反馈修复（本轮为 bug 修复日志，不进入需求文档）
> 验收：A-148 ~ A-151

## 1. 本轮修了什么

- 修复 「选择登记表」会把随手打字的空表也列出来：只列真正录过的表，当前正在编辑的表始终保留（FR-71.1）。
- 修复 登记表删不掉：参数行新增「删除此表」（二次确认），删除后从选择器、当日汇总、历史里一起消失（FR-71.2）。
- 修复 缺交 / 请假一律按不过关处理：设置里加两个开关，老师可以自己决定是否算过关（FR-71.3）。
- 修复 汇总图里每张表的评价语没有删除入口：按表提供「删除评价语」按钮，删除后立即重新生成（FR-71.4）。

## 2. 根因（含代码位置）

### FR-71.1 空表进了「选择登记表」

- `src/store/selectors.ts:159-180` `selectSheetsOfDay` 把当天该班该模板的**全部**记录按 key 收进来，
  包括「在作业内容里刚打了两个字、一个格子都还没录」的空记录。
- 作业内容每次改动都会走 `setContent → switchRecord`，key 一变就多一条空记录，
  选择器于是每打一个字就多一项，而且**没有任何删除入口**——这些表永远删不掉。

### FR-71.2 没有删除登记表的动作

- `src/store/sheetSlice.ts` 只有 `deleteHistory / clearHistory`（删历史快照），
  没有删「当前登记表」的方法；`records` 里的表只能靠清空（`clearCurrentRecord`）或覆盖，
  误打出来的表会一直留在当天列表里。

### FR-71.3 缺交 / 请假写死不过关

- `src/domain/passRule.ts` `isPassed()` 开头 `if (e.status !== 'normal') return false`，
  缺交与请假永远不算过关；`PassRule`（`src/domain/types.ts:61-66`）里也没有对应开关。
  想把请假当成「不拖后腿」的老师没有办法。

### FR-71.4 评价语只能覆盖不能删

- `src/components/modals/PosterModal.tsx` 汇总模式的每表评价语只有 textarea，
  老师不知道「删空文字」到底算不算删掉；缺一个明确的删除动作与反馈。

## 3. 改了什么

| 位置 | 改动 |
| --- | --- |
| `src/store/selectors.ts` | `selectSheetsOfDay` 只收 `hasEntries` 的表；当前草稿恒保留（切内容用） |
| `src/store/sheetSlice.ts` | 新增 `deleteRecord(key)`：从 `records` 与 `history` 一起移除；删当前表时直接落到同模板当天最近的记录（不再走 `switchRecord`，否则会把草稿写回 records 并触发 `commitIfDirty`，等于没删） |
| `src/store/store-types.ts` | `SheetSlice` 增加 `deleteRecord` 签名 |
| `src/components/ParamsBar.tsx` | 新增「🗑 删除此表」按钮，`openConfirm` 二次确认（显示日期/类型/作业内容/人数） |
| `src/domain/types.ts` | `PassRule` 增加 `missingPass?` / `leavePass?`（默认 false，老数据缺省即旧行为） |
| `src/domain/passRule.ts` | `isPassed()` 缺交 / 请假按开关判定；`DEFAULT_PASS_RULE` 补两个默认 false |
| `src/components/modals/SettingsModal.tsx` | 过关规则区新增「缺交算过关」「请假算过关」两个开关 |
| `src/components/modals/PosterModal.tsx` | 每张表的评价语块新增「删除评价语」按钮（清空 + toast + 重新生成） |
