## 0. 本轮实测证据（先给数据，再给方案）

在 `v2.2.1` 上实测（Edge，`vite preview`，1366×768 与三档移动视口）：

| 视口 | `scrollWidth - clientWidth` | 网格列数 | 单元格 | 结论 |
|---|---|---|---|---|
| 1366×768 | 0 | 10 | 127×78 | 现状刚好满屏（`scrollHeight = 768`，零余量） |
| 768×1024 | **42** | 6 | 116×69 | 轻微横向溢出 |
| 390×844 | **408** | 4 | 87×69 | 不可用 |
| 375×667 | **423** | 4 | 83×69 | 不可用 |

溢出根因（逐元素定位）：

- `.header-right` 实测宽 **573px**（品牌/班级/保存/秒跳/搜索/两枚图标按钮全在一行且 `nowrap`）→ 直接把 `html` 撑到 798px；
- `.actions-row` 内容宽 **719 / 762px**，却只被分到 351px → 按钮被挤压变形（并未换行）。

另一个关键结论：**响应式列数其实已经实现了**——`src/domain/layout.ts` 的 `gridColumns()` 与 `global.css` 的 4 档媒体查询（10/8/6/4 列）都在，4 列在 375px 下确实生效。**手机端不可用的原因不是网格，而是两行工具栏与 header 单行不换行。**

1366×768 各区高度实测（合计正好 768）：`header 64 · params 56 · actions 80 · hint 32 · grid 412`，区块间距与页面内边距合计 **124px**。

## 1. 决策记录（ADR-22~ADR-28）

### ADR-22 数字键歧义用「显式语义 chip」解决，不做延迟裁决

**背景**：`mixed` 方案下 `1..7` 既可解释为等级键，也可解释为分数首位（`useInputEngine.ts` 数字分支 `schemeAllowsScore` 先命中）。

**候选**：

| 方案 | 优点 | 致命缺点 |
|---|---|---|
| A 延迟裁决（500ms 内第二位数字→分数） | 零新增 UI | 输入 `1` 后要等半秒才知道是 A+ 还是 1 分；老师连打 `12` 时会先闪 A+ 再变 12，**状态可见性崩塌** |
| B 前缀键（`/`、`.`、`=` 等） | 不动默认行为 | `/` 已被搜索占用，`=`/`-` 已被等级修饰占用；剩下的键用户猜不到 |
| C 显式 chip 切换 + 每表持久 | 状态始终可见、可发现 | 多一个控件（4×32px） |
| D 混合方案默认分数 | 零改动 | 与用户本轮预期正相反 |

**决策：C。** 具体：

- `settings.digitKey: 'auto' | 'grade' | 'score'`（`auto` 默认），按表落库。
- 解析集中在**一个纯函数**里，禁止各处自行判断：

```ts
// src/domain/digitKey.ts（新增，纯函数，可单测）
export type DigitKeyMode = 'auto' | 'grade' | 'score';
export type DigitMeaning = 'grade' | 'score' | 'dictation';

export function resolveDigitMeaning(
  mode: DigitKeyMode,
  scheme: ScoringScheme,
  templateId: SheetTemplateId,
): DigitMeaning {
  if (mode !== 'auto') return mode;
  if (scheme.kind === 'check') return 'dictation';
  if (schemeAllowsScore(scheme) && !schemeAllowsGrade(scheme)) return 'score';
  if (schemeAllowsGrade(scheme)) return 'grade';   // grade / mixed 都走这里
  return 'score';
}
```

- 内核改动（`useInputEngine.ts` 数字分支，**顺序改为先看解析结果**）：

```ts
if (/^[0-9]$/.test(key) || key === '.') {
  if (pendingRef.current) commitPending();

  const meaning = resolveDigitMeaning(store().settings.digitKey, scheme, sheetTemplateId);

  if (meaning === 'grade' && km[key] && gradeAllowed(km[key], scheme)) {
    e.preventDefault();
    s.commitValue(no, { kind: 'grade', grade: km[key] });
    maybeAdvance(no);
    return;
  }
  if (meaning === 'grade' && !km[key] && schemeAllowsScore(scheme)) {
    // 等级模式下按到 8/9：不能静默吞键（R-10），给提示并保持可打分数
    e.preventDefault();
    s.showToast('本表没有该等级键，可切到「数字＝分数」再输入', 'warn');
    return;
  }
  if (schemeAllowsScore(scheme)) { e.preventDefault(); appendBuffer(key); return; }
  if (scheme.kind === 'check') { e.preventDefault(); dictationDigit(key); return; }
  s.showToast('本表不接受分数', 'warn');
  return;
}
```

- UI：`HintBar` 最左新增 chip `<button class="digit-chip" aria-pressed>`，文案 `⌨ 数字＝等级` / `⌨ 数字＝分数`，点击循环 `auto→grade→score→auto`；`score` 方案不渲染。
- 快捷键 `` ` ``（`Backquote`）：`onKeyDown` 命令区新增分支，切到下一个语义并 Toast。
- `buildHint()` 增加参数 `meaning`，按语义拼提示（等级模式列 `1 A+ 2 A …`；分数模式写「输入分数后 Enter」）。

### ADR-23 单元格四角分区（L-11 单一实现）

固定四角分配，全部用**同一组 CSS 变量**，`cell` / `mini` / `poster` 三个变体只改尺寸不改位置：

```css
/* global.css 替换 .cell-no / .cell-stamp 的定位 */
.cell { --no-inset: 4px 6px; --stamp-inset: 3px 5px; --badge-inset: 3px 4px; }

.cell-no    { position:absolute; top:4px;  left:6px;  }          /* 左上 */
.cell-stamp { position:absolute; top:2px;  right:5px; font-size:14px; z-index:2; }  /* 右上（改） */
.cell-badge { position:absolute; bottom:3px; right:4px; }        /* 右下（改） */
```

- 学号最长 3 位 + `max-width: 62%`，右上印章 14px，二者最近水平间距 ≥ 6px（3 位数字约占 60px，127px 格子下不冲突；手机 83px 格子需 `--stamp-size: 12px` 且学号 `font-size: 9px`）。
- 印章保留 `title`，并加 `aria-label`（`优秀` / `已更正`）。
- `CellView.tsx` 只负责渲不负责定位；**禁止在内联 style 里写 top/left**。

### ADR-25 三段式布局与高度预算

目标结构（对应 FR-49）：

```
Header 64 │ Params 48 │ OutputBand 48 │ InputBand 48 │ Hint 28 │ Grid 412
```

预算核算（依据 §0 实测：区块间距+内边距合计 124，本轮压到 112）：

| 区 | 现状 | 目标 | 手段 |
|---|---|---|---|
| header | 64 | 64 | 不动 |
| params | 56 | **48** | pill 高度 36→32；`本表设置` 移入输入带右端 |
| output band | — | **48** | 新增（R-49.1） |
| input band | 80 | **48** | 单行；`清空/更新修改` 右对齐并与左侧留 12px 分隔；`积分/导出` 收进「⋯ 更多」 |
| hint | 32 | **28** | `padding` 8→6 |
| grid | 412 | 412 | 5 行 × 76 + 4 × 8（不动） |
| 合计 | 768 | **760** | 留 8px 缓冲，AC-90 以 `scrollHeight ≤ 768` 为硬闸门 |

`ActionsBar.tsx` 拆成两个组件：

```tsx
<OutputBar onReport onPoster onSummary onWeek busy={posterBusy} />   // src/components/OutputBar.tsx
<InputBar  … />                                                       // 原录入行 + 清空/保存 + ⋯更多
```

- `busy`：生成中按钮显示 spinner + `disabled`（FR-49.7a）。
- 弹窗关闭后 `restoreFocus()`：`App.tsx` 记录打开前的 `focusedNo`，关闭时 `setFocusedNo(back)`（FR-49.7b）。
- 危险动作：`清空` 使用 `variant="danger"`（红边 ghost），确认弹窗显示「将清空 N 格」（FR-49.7c）。
- 保存状态胶囊可点击 → 打开「数据健康」面板（复用 V3 的 `storageHealth`）。

### ADR-26 移动端：先修溢出，再做形态

优先级严格如下（对应 §0 的实测）：

1. **`.header-right` 单行化改造**（这是溢出的真正原因，573px）：`< 1024px` 时品牌文字隐藏只留 🌸、保存状态收进⚙️、`秒跳/搜学号` 收进「⋯」；header 允许两行但高度锁 64。
2. `.actions-row` 改为 `overflow-x:auto; flex-wrap:nowrap;` + `scrollbar-width:none`，**输入带在手机端横滑**。
3. `< 768px`：输出带改为**底部固定条**（`position:sticky; bottom:0`，4 项图标 44px），网格 4 列（已生效）→ 按 FR-50.2 定 **5 列**（改媒体查询 4→5 并收紧 `--cell-gap:6px`）。
4. 点格子 → 底部升起 `MobileKeypad`（数字 0–9 / `.` / 等级 6 钮 / 过关 / 缺交 / 请假 / 清空），复用 store 的 `commitValue`。

### ADR-27 不做原生小程序（记录理由，避免下一轮再讨论）

- `web-view` 官方明确「**个人类型的小程序暂不支持使用**」，且 `src` 必须是**已备案 HTTPS 业务域名** → 套壳路线需要企业主体 + 服务器，与本产品「零后端纯本地」冲突。
- 原生重写（Taro/uni-app）需替换：存储（`wx.setStorageSync`）、栅格化（canvas）、导出（文件系统）、语音（插件）、`file://` 打开方式。估 2–3 周且需企业主体。
- 教育类内容涉及小程序类目与资质问询。
- **结论**：V4 只做 PWA + 响应式；小程序作为独立立项（若未来需要）。

### ADR-28 数据模型迁移 v3 → v4

`Settings` 新增 4 个字段（全部有默认值，迁移不丢数据）：

```ts
theme: ThemeKey;                  // 'pink' 默认
posterFollowTheme: boolean;       // false
digitKey: DigitKeyMode;           // 'auto'
installHintDismissed: boolean;    // false
lastExportAt: string | null;      // ISO，初始 null（用于 7 天提醒）
```

- `STORAGE_KEY` 升 `xq.state.v4`；`migrate.ts` 增 `v3→v4` 纯函数，未知 `theme` 回落 `pink`（B-4）。
- 备份 `exportJson` 自动包含新字段；`importJson` 对缺字段补默认值（保持向后兼容：v3 备份能导入 v4）。
