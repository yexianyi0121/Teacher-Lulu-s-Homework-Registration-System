# 28 · 修复日志 · v2.6.3

> 版本：2.6.3
> 性质：用户反馈修复 + 界面小改进（本轮为 bug 修复日志，不进入需求文档）
> 验收：A-152 ~ A-159

## 1. 本轮修了什么

- 修复 等级制 / 混合制的过关判定被「及格线」兜底：等级的通过与否只看本表勾选的等级白名单（FR-72.1）。
- 修复 分数制只有一个及格线口径：新增「达到及格% / 良好% / 优秀% 才过关」三档可选（FR-72.2）。
- 修复 过关规则放在系统设置里、与本表方案割裂：整块搬到「本表设置」，口径随方案类型走（FR-72.3）。
- 修复 改完方案点「完成」后已登记值与新方案不兼容却毫无提示：先二次确认，确认后按新方案清空不兼容的格子（FR-73.1 / FR-73.2）。
- 修复 在作业内容里打一个字就凭空多一张登记表：作业内容改成待新建的名称，点「＋ 新建登记」才建表（FR-73.3）。
- 修复 没填作业内容也能直接往格子里记：未填内容时登记被拦下并提示（FR-73.4）。
- 改进 顶栏显示当前时间（年月日时分秒）与当前学期，页脚显示系统版本号，默认背景改为纯白（改进1）。

## 2. 根因（含代码位置）

### FR-72.1 等级值被百分线兜底

- `src/domain/passRule.ts` 旧 `isPassed(e, s, rule)` 在 `kind === 'mixed'` 时先算
  `gtePct(percentOf(e), s.passRate)`，只要百分达标就直接判过关，等级白名单形同虚设：
  只勾 A+ / A / A- 时，A-（90%）以上的等级全部因 60% 线过关，除 D 外全绿。
- 老师实际数据还把及格% 改成了 7%（`scheme.passRate = 0.07`），7 分以上即过关。

### FR-72.2 分数制只有一条及格线

- 旧的 `PassRule.kind === 'percent'` 只有一个 `s.passRate` 判定，没有「优秀才算过关」这类口径；
  想收紧只能整体调高及格%，连带把「及格」的定义改掉。

### FR-72.3 过关规则放在系统设置

- `src/components/modals/SettingsModal.tsx` 的 `pass-rule` 区管过关规则，
  而方案类型（等级制 / 分数制 / 混合制）在 `src/components/modals/SchemeModal.tsx`，
  两处割裂：改方案不会改规则，改规则又看不出对应哪张表。

### FR-73.1 改方案后旧值不刷新

- `SchemeModal` 的「完成」只 `close()`；`setScheme` 改的是方案，`entries` 原样保留。
  把等级制改成分数制后，之前的等级值仍然在格子里；改满分后旧分数也不清。

### FR-73.3 输入作业内容就建表

- `src/components/ParamsBar.tsx` 旧实现的 `onChange` 直接 `setContent(v)`，
  而 `setContent` 内部是 `switchRecord({ content })`——key 一变就 `createRecord`，
  于是每敲一个字都多一张空表。

## 5. 明确不改

- 老师既有数据里的 `settings.passRule`：载入时迁移进每条记录的方案（`normalizeScheme`），
  配置不丢；迁移后 `settings` 里不再保留 `passRule` 字段。
- 混合制「等级值 + 分数值都能录」：混合制只是两套口径并存，等级值走白名单、分数值走及格档位，
  不再互相兜底。
- 改方案时清空的值仍然可以 `Ctrl+Z` 撤回（清空动作记一条撤销）。
