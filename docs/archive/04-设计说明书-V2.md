## 0. 阅读指南与铁律

### 0.1 文档优先级（冲突时按此裁决）

```
本文档 §17（交付与发布） > 本文档 §16（与 PRD-V2 的对齐补充） > 本文档 §4/§6/§8（数据模型、模块、算法）
> PRD-V2 §2.4/§2.2/§5（统计定义、判定、业务规则） > PRD-V2 其他章节 > V1 的设计说明书
```

**PRD 说「要什么」，本文档说「怎么实现」。** 两者冲突时以 PRD 的**行为**为准、以本文档的**结构**为准，并在 PRD §10「待确认决策」里登记。

### 0.2 三条铁律（沿用 V1，且 V2 新增第 4 条）

| 编号 | 铁律 |
|---|---|
| **L-1** | **纯前端 + 本地存储**：无后端、无账号、无云端同步。除用户主动点击【语音】外，不得发出任何网络请求。 |
| **L-2** | **不丢数据**：任何操作（含人数调小、切换班级、切换登记表、清空、导入升级）都不得物理删除学生成绩；只在用户显式删除并二次确认时删除。 |
| **L-3** | **数字必须可复现**：PRD-V2 §8 的黄金样例 C（以及 V1 的样例 A/B）必须由单测逐格断言，任何一位小数不得偏差。 |
| **L-4（新）** | **闭集优先**：所有由「机器猜」产生的值（语音识别、批量导入、迁移推断）都必须落入**有限的合法值集**，越界即拒绝并要求人工确认——不允许把非法猜测直接写进成绩。 |

### 0.3 术语

沿用 PRD-V2 §1。本文档额外使用：

| 术语 | 含义 |
|---|---|
| **登记表（Sheet）** | 一个可录入的表格实体 = 模板（行为类）× 计分方案（取值类）。V2 里「登记类型」不再是 `mode`，而是 `sheetId`。 |
| **模板（SheetTemplate）** | 行为差异：`homework / dictation / quality / custom`，决定键位快捷与是否显示统计条。 |
| **方案（ScoringScheme）** | 取值差异：`grade / score / check / mixed / text`，决定能录什么、怎么折算百分比、怎么分档。 |
| **折算百分（percent）** | 把「分数 / 等级 / 勾」统一到 0–100 的标尺，用于分档、平均值、达标判断、积分。 |
| **台账（Ledger）** | 积分账本，只追加不修改（INV-10）。 |

## 1. 架构决策记录（V2 新增 ADR-11 ~ ADR-21）

> V1 的 ADR-01 ~ ADR-10 继续有效（纯静态 SPA、Zustand、自研 SVG 图表、快照撤销、html-to-image 海报、零网络等）。以下为 V2 新增。

### ADR-11 值与状态分离：`value` 不再包含「√ / ×」

**决策**：`Grade` 枚举缩为 7 个字母等级；`√`（已交未评）改为 `pass: true`，`×`（缺交）改为 `status: 'missing'`。

**理由**：需求 1/3/5 要求「任何登记表都能打分数或等级」「支持请假」「支持补交」。若 `√`/`×` 仍属等级枚举，则「A 等级 + 缺交」「90 分 + 请假」「补交后又有分数」这些组合无法表达。分离后 `value × status × pass × makeup` 四维正交，组合全覆盖。

**代价**：V1 数据需迁移（见 §4.6），且所有读 `grade === 'CROSS'` 的地方要改。

### ADR-12 登记表 = 模板 × 方案，`mode` 降级为模板属性

**决策**：新增 `sheetId` 作为记录键的一部分；`mode` 字段保留但语义变为「模板的行为类别」，由模板定义决定，不再由用户三选一。

**理由**：需求 1/6 要求「所有类型都能打分或打等级」「满分可配置」，需求 7 要把「单元测试」改名「质量监测」，需求 9 要支持自定义输入。若继续用 `mode` 驱动 UI，每加一种取值方式就要改 `switch(mode)`，组合爆炸（4 模板 × 5 方案 = 20 种）。拆开后 UI 由**方案**驱动取值区、由**模板**驱动快捷键与统计条，是笛卡尔积而非枚举。

**代价**：V1 的 `mode` 三元组记录键改为 `(classId, date, content, sheetId)`；`switch(mode)` 全部改写为查表。

### ADR-13 折算百分是唯一标尺，但**等级→档位走 percent 而非字母直映射**

**决策**：`GRADE_PERCENT = { A+:100, A:95, A-:90, B+:85, B:80, C:70, D:55 }`；档位一律由 `percent` 与阈值比较得出，不做 `A+→excellent` 的硬编码。

**理由**：需求 6 允许改满分与阈值。若等级硬映射档位，老师把优秀线调到 95% 后 A-（90%）仍显示「优秀」，自相矛盾。用 percent 统一标尺，等级与分数在同一条数轴上比较，阈值改动一处生效（这也是 V1 的 `cellTone` 教训）。

**关键细节**：`D` 折算 **55%** 而非 60%，保证默认阈值（及格 60%）下 `D` 恒为「不及格」——这是小学/初中老师的直觉（D 就是不及格）。若老师把及格线调到 50%，D 自然变「及格」，语义自洽。**不要**把 D 设成 60，否则 `D` 与 `C`（70）在「及格」档里挤在一起，且与「D 代表不合格」的常识冲突。

### ADR-14 多班级：`classes[]` + `activeClassId`，记录键含 `classId`

**决策**：持久化根对象新增 `classes: ClassDoc[]` 与 `activeClassId`；`recordKey` 与 `historyKey` 的首段改为 `classId`。

**理由**：需求 12。把班级做进键里（而不是「导出时再按班级过滤」）可以从根上杜绝串班污染，且切换班级只是换 `activeClassId`，无需重算任何索引。

### ADR-15 积分账本：追加式 + `dedupeKey` 幂等 + 反向记录撤销

**决策**：积分不做「学生身上的累计字段」，而是独立 `pointLedger: PointLedgerEntry[]`，每次变动一行；自动规则用 `dedupeKey` 去重；撤销写 `source:'revert'` 的反向行。

**理由**：需求 10 要求「月度统计」「可解释」。累计字段一旦算错无法追溯，账本可以随时重算、可审计、可撤回。`dedupeKey` 解决「重复保存同一条登记导致重复加分」（V1 的 INV-4 幂等思想延续）。

### ADR-16 导出：手写 CSV + 手写 ZIP（store，不压缩）

**决策**：`.csv` 用 `\uFEFF` BOM + `,` 分隔 + 双引号转义；`.zip` 用自研的 store-only（无压缩）写入器（中央目录 + CRC32 表），**不引入 jszip**。

**理由**：需求 11 要月份/学期导出。jszip 压缩后 gzip ≈ 40KB 且带来异步复杂度；CSV 文本压缩收益极低，store-only 实现 < 120 行、同步、可全量单测。桌面上 120 人的一个月数据 ≈ 300KB，完全可接受。

### ADR-17 语音：不换引擎，把「开放听写」收敛为「闭集槽位填充」

**决策**：继续使用浏览器内置 `SpeechRecognition`（Edge 优先），但在前后各加一层：
1. **前**：`continuous` 守护重启、`interimResults` 全量重建、VAD 能量门限；
2. **后**：中文数字归一化 → 闭集动作词拼音相似度匹配 → 「学号 + 动作」槽位解析 → 回显确认（可撤销）。

**理由**（基于实测调研，见 §6.8.0）：识别率低的真实瓶颈不是模型能力，而是①网络失败被误判为识别差、②`interimResults` 增量拼接导致文本错乱、③连续说话没有分段。而教师口令的**信息熵极低**（学号 1..N + 约 25 个动作词），闭集填充的准确率远高于开放听写。换 whisper/Vosk 的代价是 40MB–1.3GB 模型 + 1–3s 延迟 + 中文 CER 17–38%，反而更差。

**代价**：需要自建拼音相似度表与同音表（< 5KB），并接受「必须先说得像口令」的使用习惯。

### ADR-18 当日汇总截图：独立海报组件，复用 html-to-image

**决策**：新增 `DailySummaryPoster`，按「日期 + 班级」聚合当日全部登记表，纵向卡片列表，每张卡片 = 表名 + 统计摘要 + 迷你色块网格；导出复用 §6.6 的 2× 渲染管线。

**理由**：需求 4。老师的真实场景是「放学前一键发家长群」，需要一张图说清"今天考了什么、谁没过"。迷你网格（32×24）能在 1366 宽内塞下 3–6 张表，且比纯文字更直观。

**代价**：需要「当日快照」选择器（从 `records` + `history` 合并当日所有条目），注意去重（同 key 优先 `records`）。

### ADR-19 用户手册：内置静态内容，手写 JSX 段落数组

**决策**：`domain/manual.ts` 导出 `MANUAL: ManualSection[]`（结构化数据），组件渲染；**不引入 markdown 解析库**，不请求外部文档。

**理由**：需求 8。引 md 库（marked/markdown-it）≈ 30–60KB，还要处理 XSS；手册内容是固定的 12 节，结构化数组足够，且能被单测断言「每节都有标题与步骤」。

### ADR-20 迁移：单次幂等 `migrate()`，失败即回滚并提示

**决策**：`loadState()` 读出后立即跑 `migrate(raw)`，按 `version` 逐级升级；升级前把原始 JSON 备份到 `localStorage['xq.backup.v1']`；任何异常都不写回、不覆盖，直接 Toast 提示并进入只读展示。

**理由**：老用户（用户的妻子）已经在 V1 里录了真实数据。迁移失败必须可恢复，不能静默丢数据（L-2）。

### ADR-21 版本与构建：锁定 Node ≥ 22

**决策**：`package.json` 增加 `"engines": {"node": ">=22"}`，并把 `vite-plugin-pwa` 升到 `^0.21` 或移除（见风险表 R-2）。

**理由**：V1 实测在 Node 20 LTS 下 `vite build` 直接失败（`Dynamic require of "workbox-build" is not supported`）。这是**评审发现的 P1**，V2 必须消除。

## 4. 数据模型（V2 完整定义）

### 4.1 核心类型（`src/domain/types.ts`）

```ts
// ---------- 取值 ----------
export type GradeLetter = 'A+' | 'A' | 'A-' | 'B+' | 'B' | 'C' | 'D';

/** 折算百分。唯一准据，禁止在别处出现等级→百分的映射表 */
export const GRADE_PERCENT: Record<GradeLetter, number> = {
  'A+': 100, 'A': 95, 'A-': 90,
  'B+': 85,  'B': 80,
  'C': 70,
  'D': 55,
};

export type CellValue =
  | { kind: 'grade'; grade: GradeLetter }
  | { kind: 'score'; score: number }   // 0..maxScore
  | { kind: 'text';  text: string }    // ≤ 12 字
  | { kind: 'pass' };                  // 纯过关（无分值）

export type EntryStatus = 'normal' | 'missing' | 'leave';

export type Stamp = 'none' | 'corrected' | 'excellent';

export interface Makeup { at: number; note: string }   // note ≤ 30 字，可空串

export interface Entry {
  value: CellValue | null;
  stamp: Stamp;
  status: EntryStatus;          // 'missing' 时 value 必须为 null
  pass: boolean;                // 过关勾；check 方案下的主值，也可与 grade 共存
  makeup: Makeup | null;
  updatedAt: number;
}

export type Entries = Record<string, Entry>;   // 键 '1'..'120'

// ---------- 计分方案 ----------
export type SchemeKind = 'grade' | 'score' | 'check' | 'mixed' | 'text';

export interface ScoringScheme {
  kind: SchemeKind;
  maxScore: number | null;        // score/mixed 必填，10..1000，默认 100
  grades: GradeLetter[];          // grade/mixed 可用等级集，默认全 7 档
  allowCheck: boolean;            // 是否允许 √（仅混合/过关制）
  allowText: boolean;             // 是否允许自定义文字
  decimals: number;               // 0 | 1，分数小数位
  excellentRate: number;          // 0-1，默认 .90
  goodRate: number;               // 默认 .80
  passRate: number;               // 默认 .60
}

export type Tier = 'excellent' | 'good' | 'pass' | 'fail';

// ---------- 模板 ----------
export type SheetTemplateId = 'homework' | 'dictation' | 'quality' | 'custom';

export interface SheetTemplate {
  id: SheetTemplateId;
  name: string;                  // 常规作业 / 听写默写 / 质量监测 / 自定义
  icon: string;                  // 📖 听写 / 📝 常规 / 📊 质量 / 🏷️ 自定义
  showStatBar: boolean;          // quality=true
  showGraph: boolean;            // quality=true
  dictationQuickKeys: boolean;   // 错N 快捷
  defaultScheme: SchemeKind;
}

// ---------- 班级 ----------
export interface Student { no: number; name?: string }

export interface ClassDoc {
  id: string;                    // `cls_` + nanoid(8)
  name: string;                  // ≤ 20 字
  school: string;
  teacher: string;
  subject: string;
  students: Student[];           // length === count（INV-9）
  count: number;                 // 1..120
  createdAt: number;
}

// ---------- 记录 ----------
export interface RecordDoc {
  key: string;                   // `${classId}|${date}|${content}|${sheetId}`
  classId: string;
  date: string;                  // 'YYYY-MM-DD'
  content: string;
  sheetId: string;               // `sheet_` + id，或模板预设 id
  templateId: SheetTemplateId;
  scheme: ScoringScheme;         // ★ 方案快照：改方案不影响历史
  entries: Entries;
  createdAt: number;
  updatedAt: number;
}

export interface HistoryEntry extends RecordDoc {
  metrics: SessionMetrics;
  metricsVersion: 2;
  savedAt: number;
}

export interface SessionMetrics {
  n: number; entered: number;
  excellent: number; good: number; pass: number; fail: number;
  missing: number; leave: number; madeUp: number; notSubmitted: number;
  avgPercent: number | null; avgScore: number | null;
  excellentRate: number | null; qualifiedRate: number | null;
  passCount: number;
  max: number | null; min: number | null;
}

export interface RosterGroups {
  honor: number[];        // 光荣榜（等级秩≥A，或分数 percent≥优秀线）
  needsFix: number[];     // 需更正（含子集 corrected）
  corrected: number[];    // needsFix 中已盖「已更正」的子集
```

### 4.3 记录键与历史键


### 4.4 方案快照 vs 模板引用

- `RecordDoc.scheme` 是**快照**：老师事后改「默认满分 120」，不应篡改历史记录的分档。
- `SheetTemplate` 是**引用**：`templateId` 决定 UI 行为，改模板不重算成绩。

> **易错点**：`HistoryEntry.metrics` 也用**记录自己的 scheme** 重算，不得用当前全局方案。旧 V1 历史（`metricsVersion:1`）在渲染时按 v1 分档重算（§4.6.5）。

### 4.5 状态优先级（写入时的归一化）

任何写入都必须走 `normalizeEntry()`，它按下列优先级收敛出唯一合法状态：

| 优先级 | 条件 | 结果 |
|---|---|---|
| 1 | `status === 'leave'` | `value = null`，`pass = false` |
| 2 | `status === 'missing'` | `value = null`，`pass = false` |
| 3 | `pass === true` 且方案允许 | `value = { kind:'pass' }` 或保留已有值 |
| 4 | `value !== null` | `status = 'normal'` |
| 5 | 全空 | `value = null`，`pass = false`，`status = 'normal'` |

`stamp` 与 `makeup` 正交，不受上表影响。

### 4.6 v1 → v2 迁移（`domain/migrate.ts`）

#### 4.6.1 触发与安全

```ts
export function migrate(raw: unknown): { state: PersistedStateV2; migrated: boolean } {
  if (isV2(raw)) return { state: raw, migrated: false };
  if (!isV1(raw)) throw new Error('UNKNOWN_STATE');   // 交给调用方提示，不覆盖
  // 调用方已把原始 JSON 备份到 xq.backup.v1
  ...
}
```

- 迁移前备份：`localStorage.setItem('xq.backup.v1', JSON.stringify(rawV1))`（只写一次，不覆盖已有备份）。
- 迁移**纯函数、不可变**，返回新对象，不 mutate `raw`。
- 失败不写回：`storage.load()` 捕获异常 → 返回 `{state: EMPTY, error}` → UI 显示「数据升级失败，已备份原始数据」并提供【下载原始备份】。

### 5.2 积分的撤销必须联动

> **判定**：`undo` 时若 `ledger.length > pointsBefore.length`，则 `ledger = ledger.slice(0, pointsBefore.length)`；否则不动。这样自动加分不会在撤销后残留。

- `useStats()` 走 `useMemo`，依赖 `[record.entries, record.scheme, activeClass.count]`。
- **禁止**在渲染期直接 `computeStats(...)`（120 格 × 每键一算会掉帧）——V1 已验证需要 memo。
- 积分月度统计用 `useMemo` 依赖 `[pointLedger, monthKey, activeClassId]`。

## 6. 模块详细设计

### 6.1 判定内核：`scoring.ts`

```ts
/** 折算百分；不可折算（无值/请假/缺交/text/pass）返回 null */
export function percentOf(e: Entry, s: ScoringScheme): number | null {
  if (e.status !== 'normal' || !e.value) return null;
  const v = e.value;
  switch (v.kind) {
    case 'score':
      return s.maxScore && s.maxScore > 0 ? (v.score / s.maxScore) * 100 : null;
    case 'grade':
      return GRADE_PERCENT[v.grade];
    case 'pass':
    case 'text':
      return null;
  }
}

/** 档位：唯一入口，UI 颜色/报表名单/积分全部走这里 */
export function tierOf(e: Entry, s: ScoringScheme): Tier | null {
  const p = percentOf(e, s);
  if (p === null) return null;
  if (p >= s.excellentRate * 100) return 'excellent';
  if (p >= s.goodRate      * 100) return 'good';
  if (p >= s.passRate      * 100) return 'pass';
  return 'fail';
}

/** 是否「达标」：passRate 及以上 */
export const isQualified = (e: Entry, s: ScoringScheme) => {
  const t = tierOf(e, s);
  return t === 'excellent' || t === 'good' || t === 'pass';
};
```

**与 V1 的等价性**：满分 100、阈值 .90/.80/.60 时，`98 → excellent`、`89 → good`、`72 → pass`、`43 → fail`，与 V1 `cellTone` 完全一致（回归测试 R-1）。

**边界**：`percentOf` 用 `>=` 比较，故 `72/120 = 60.0%` 恰为 `pass`（AC-18.1）。

### 6.2 统计：`stats.ts`

严格按 PRD-V2 §2.4 实现，逐字段：

```ts
export function computeStats(
  entries: Entries, s: ScoringScheme, n: number, honorIncludesA: boolean,
): SessionMetrics {
  let entered=0, graded=0, excellent=0, good=0, pass_=0, fail=0, missing=0, leave=0, madeUp=0, passCount=0;
  let sum = 0; let max: number|null = null; let min: number|null = null;

  for (let no = 1; no <= n; no++) {
    const e = entries[String(no)];
    if (!e) continue;                        // 空白
    if (e.status === 'leave') { leave++; continue; }
    if (e.status === 'missing') missing++;
    if (e.makeup) madeUp++;
    if (e.pass) passCount++;
    const p = percentOf(e, s);
    // 已登记：有值或已过关（FR-21-2 过关会清空 value）；四档只认能折算百分的值
    if (e.status === 'normal' && (e.value !== null || e.pass || e.value?.kind === 'pass')) entered++;
    if (p === null) continue;
    graded++; sum += p;
    const t = tierOf(e, s)!;
    if (t === 'excellent') excellent++;
    else if (t === 'good') good++;
    else if (t === 'pass') pass_++;
    else fail++;
    max = max === null ? p : Math.max(max, p);
    min = min === null ? p : Math.min(min, p);
  }
  const avgPercent = graded ? round1(sum / graded) : null;
  const avgScore = graded && s.maxScore ? round1((sum / graded) / 100 * s.maxScore) : null;
  return {
    n, entered, excellent, good, pass: pass_, fail,
    missing, leave, madeUp,
    notSubmitted: n - entered - leave,        // 含缺交与空白
    avgPercent, avgScore,
    excellentRate: graded ? round1(excellent / graded * 100) / 100 : null,
    qualifiedRate: graded ? round1((excellent + good + pass_) / graded * 100) / 100 : null,
    passCount, max: max === null ? null : round1(max), min: min === null ? null : round1(min),
  };
}
```

**注意**：
1. `missing` 的人**也可能**有 `entered`（补交后补录分数、但状态仍记 missing？）——**不允许**：§4.5 优先级规定 `missing ⟹ value=null`，所以二者互斥；`madeUp` 可与 `entered` 重叠（补交且有分）。
2. `notSubmitted` 含缺交，故 `missing ≤ notSubmitted` 恒成立。
3. `round1(x) = Math.round(x * 10) / 10`（half-up，禁止 `toFixed`，V1 教训：`(0.15).toFixed(1)` 在二进制下可能给 `0.1`）。

### 6.3 名单：`roster.ts`（口径见 PRD-V2 §2.3.1，**不是** `tierOf`）

```ts
const RANK: Record<GradeLetter, number> = { 'A+':7,'A':6,'A-':5,'B+':4,'B':3,'C':2,'D':1 };

/** 入光荣榜？（等级看字母秩，分数看百分） */
function inHonor(e: Entry, s: ScoringScheme, honorIncludesA: boolean): boolean {
  const v = e.value; if (!v) return false;
  if (v.kind === 'grade') return RANK[v.grade] >= (honorIncludesA ? 5 : 6);
  const p = percentOf(e, s);
  return p !== null && p >= toPct(s.excellentRate);
}

/** 入需更正？（等级看字母秩，分数看及格线） */
function inNeedsFix(e: Entry, s: ScoringScheme, honorIncludesA: boolean): boolean {
  const v = e.value; if (!v || inHonor(e, s, honorIncludesA)) return false;
  if (v.kind === 'grade') return true;                       // 非荣即需
  if (v.kind === 'pass') return false;                       // 已过关（已由规则 4 抢走）
  if (v.kind === 'text') return s.kind === 'check';          // 听写「错N」→ 需更正
  const p = percentOf(e, s);
  return p !== null && p < toPct(s.passRate);                // 只抓不及格
}

export function classifyRoster(
  entries: Entries, s: ScoringScheme, n: number,
  opts: { honorIncludesA: boolean },
): RosterGroups {
  const g: RosterGroups = { honor:[], needsFix:[], corrected:[], notSubmitted:[], leave:[], passed:[], madeUp:[] };
  for (let no = 1; no <= n; no++) {
    const e = entries[String(no)];
    // 规则 1：请假
    if (e?.status === 'leave') { g.leave.push(no); continue; }
    // 规则 2：缺交且无补交
    if (e?.status === 'missing' && !e.makeup) { g.notSubmitted.push(no); continue; }
    // 规则 3：缺交但已补交（尚未补录值）
    if (e?.status === 'missing' && e.makeup) { g.madeUp.push(no); continue; }
    // 规则 4：过关
    if (e?.pass) { g.passed.push(no); if (e.makeup) g.madeUp.push(no); continue; }
    // 无值无状态 → 规则 9
    if (!e?.value) { g.notSubmitted.push(no); continue; }

    if (e.makeup) g.madeUp.push(no);
    if (inHonor(e, s, opts.honorIncludesA)) { g.honor.push(no); continue; }
    // 规则 6/7/8：需更正（已盖章则同时进 corrected）
    if (inNeedsFix(e, s, opts.honorIncludesA)) {
      g.needsFix.push(no);
      if (e.stamp === 'corrected') g.corrected.push(no);
    }
    // 其余（分数制的良好/及格档）不进任何名单
  }
  return g;
}
```

> **关键差异**：V1 的 `fixed` 字段改名为 `corrected`（与 `stamp` 枚举统一），且 `corrected` 是 `needsFix` 的**子集**而非并列组——报表里它是【需更正】段下的小标题。
>
> **`honorIncludesA` 的语义**：开启时 `A-`（秩 5）也进光荣榜。注意它是「含 A-」而不是「含 B+」。
>
> **等级制下没有中立档**：`B/C/D` 全部进需更正（见 PRD §2.3.1）。

测试例子（单测必写）：
- `A-`（秩5）在 `honorIncludesA=false` → `needsFix`；`=true` → `honor`。
- 分数 `72`（满分100）→ 三组皆无。
- 听写：`全对`（`pass=true`）→ `passed`；`错3`（`text='错3'` + `pass=false`）→ `needsFix`。
- `A+` 且 `stamp='corrected'` → 依然在 `honor`（盖章不剥夺光荣榜）。

- 【已更正】是【需更正】的**子段**（不移除人）；子段非空时缩进三空格 + `⤷`。
- 补交顺序固定在「暂未提交」之后、「需更正」之前。
- 折行沿用 `wrapTokens(maxWidth = 70)`（PRD-V2 BR-19，**唯一解**：66–69 会让光荣榜折行，≥72 变 12/12/6）。
- **回归保护**：样例 A（无补交/无请假/无过关）时输出必须与 V1 **逐字符相等**。

#### 6.7.3 幂等：`dedupeKey`


#### 6.7.4 撤销

```ts
export function revokePoint(ledger: PointLedgerEntry[], id: string, now: number): PointLedgerEntry[] {
  const src = ledger.find(x => x.id === id);
  if (!src || src.source === 'revert') return ledger;
  return [...ledger, { ...src, id: uid(), delta: -src.delta, source: 'revert',
                       revertedId: src.id, reason: `撤销：${src.reason}`, createdAt: now,
                       dedupeKey: `${src.dedupeKey}#rev#${now}` }];
}
```

### 6.8 语音识别优化（需求 13）— 全篇最需要"照抄"的一节

#### 6.8.0 调研结论（必须先读，否则会走错方向）

用户反馈「语音识别率低」。实测调研的结论是：**不要换引擎，瓶颈在管线而非模型**。

| 事实 | 影响 |
|---|---|
| Chrome 用 Google 语音服务，**断网必失败**；Edge 用微软服务，国内通常可用 | 「识别差」里有一部分其实是 `network` 错误。必须先统计 `onerror` 分布 |
| `continuous=true` 下静音 5–8s 会触发 `end` / `no-speech`，不会一直听 | 必须 `onend` 守护重启；`running` 状态再 `start()` 抛 `InvalidStateError` |
| `interimResults` 同一 `resultIndex` 的文本**反复改写**；`final` 也会重复投递 | 每次事件都**从 `event.results` 全量重建**，不能 append |
| `SpeechGrammarList` / `.bnf` 规范已声明 "does nothing" | 语法约束路线**作废** |
| `maxAlternatives` 桌面常只回 1–2 条；`confidence` 未校准（常固定 0.8–0.9 或 0） | 不能拿 `confidence` 当门限 |
| `phrases`（`new SpeechRecognitionPhrase(text, boost)`，boost 0–10）是 Chrome/Edge **142**；`processLocally/available()/install()` 是 **139** | 可特性检测使用，**不能当主力** |
| 端侧语言包官方示例仅 en-US/en-GB/es-ES/fr-FR，**无 zh-CN** | 中文 `processLocally` 预期 `language-not-supported`，勿依赖 |
| whisper.cpp WASM（tiny q5 40MB / fp16 75MB）：非流式、短指令易幻觉、CPU 1–3s | 不做 |
| transformers.js Whisper（40–140MB）：同上且首载更慢 | 不做 |
| Vosk small-cn（42MB）CER 17.15/23.54/38.29（不同测试集），学号必错；大模型 1.3GB | 不做 |
| sherpa-onnx 流式中文（int8 数十 MB + 数 MB WASM，Apache-2.0，支持热词） | 唯一保留为**可选实验**（P3，见 §14 R-5） |
| Windows UWP `SpeechRecognizer` 仅原生可用 | PWA 用不了；替代是让用户用 Win+H 系统听写喂同一管线 |

**一句话结论**：教师口令的信息熵极低（学号 1..N + 约 25 个动作词），把「开放听写」变成「闭集槽位填充」，准确率提升远大于换模型。

#### 6.8.2 识别层（`infra/voice/recognizer.ts`）

```ts
export interface VoiceCb {
  onFinal(text: string): void;
  onInterim(text: string): void;
  onError(code: string): void;
  onStateChange(s: 'idle'|'listening'|'restarting'|'unsupported'): void;
}

export function createRecognizer(cb: VoiceCb, opts: { lang?: string } = {}) {
  const Ctor = (window as any).SpeechRecognition ?? (window as any).webkitSpeechRecognition;
  if (!Ctor) { cb.onStateChange('unsupported'); return { start(){}, stop(){} }; }

  const rec = new Ctor();
  rec.lang = opts.lang ?? 'zh-CN';
  rec.continuous = true;
  rec.interimResults = true;
  rec.maxAlternatives = 3;          // 有就用，没有不报错

  let alive = false;                 // 用户意图：是否应该处于聆听
  let restartTimer: number | null = null;
  let restartBackoff = 300;

  rec.onstart = () => { restartBackoff = 300; cb.onStateChange('listening'); };

  rec.onresult = (ev) => {
    let finalText = '';
    let interim = '';
    for (let i = 0; i < ev.results.length; i++) {          // ★ 全量重建，禁止 append
      const r = ev.results[i];
      if (r.isFinal) finalText += r[0].transcript;
      else interim += r[0].transcript;
    }
    if (finalText) cb.onFinal(finalText.trim());
    cb.onInterim(interim.trim());
  };

  rec.onerror = (ev) => {
    // 'network' 与 'no-speech' 要区分：前者提示检查网络/切 Edge，后者静默
    if (ev.error === 'no-speech') return;
    cb.onError(ev.error);
  };

  rec.onend = () => {
    if (!alive) { cb.onStateChange('idle'); return; }
    cb.onStateChange('restarting');
    restartTimer = window.setTimeout(() => {
      try { rec.start(); } catch { /* InvalidStateError：已在跑，忽略 */ }
    }, restartBackoff);
    restartBackoff = Math.min(restartBackoff * 2, 3000);   // 退避，避免疯狂重启
  };

  const start = () => { alive = true; try { rec.start(); } catch {} };
  const stop  = () => { alive = false; if (restartTimer) clearTimeout(restartTimer); try { rec.stop(); } catch {} };
  return { start, stop };
}
```

**关键点**：
1. `onend` **必须**重启（否则说两句话就"没反应了"），但要退避 + `alive` 标志，避免用户停止后又被拉起来。
2. `onresult` **全量重建**：这是 V1 识别"越说越乱"的最可能原因。
3. `no-speech` 不算错误（用户停顿是常态），不弹 Toast。
4. `network` 错误要给出**可操作**提示：「语音服务连不上，请改用 Edge 或检查网络」，而不是笼统的"识别失败"。

#### 6.8.3 归一化层（`domain/voice/normalize.ts`）

```ts
export function normalize(raw: string): string
```

规则（顺序敏感，先长后短）：

| # | 规则 | 例 |
|---|---|---|
| 1 | 全角→半角、去空白/标点（保留 `号`） | `１２ 号` → `12号` |
| 2 | 中文数字→阿拉伯 | `十二号`→`12号`、`一十二`→`12`、`二十`→`20`、`两百`→`200` |

#### 6.8.4 拼音近似（`domain/voice/phonetics.ts`）

**目标**：把识别出的 `全对` 之外的各种离谱写法（`劝对`、`全兑`、`泉对`）映射回闭集。

**方案（不引 `pinyin-pro`）**：自建 < 500 字的**汉字→(声母, 韵母)**表，只覆盖词表里出现的字 + 常见同音字。相似度：

```ts
export interface Py { sm: string; ym: string }        // 声母、韵母
export function pyOf(ch: string): Py | null
export function simChar(a: string, b: string): number // 0..1
export function simWord(a: string, b: string): number // 逐字对齐，长度不同取最优子序列
```

`simChar` 打分：
- 声母 + 韵母全同 → 1.0
- 声母同 + 韵母不同（或反之）→ 0.5
- 都不同 → 0
- 非表内字：只比字形（相同 1，不同 0）

`simWord` 用**编辑距离变体**：替换代价 = `1 - simChar(...)`，插入/删除代价 0.8。`simWord ≥ 0.6` 视为候选。

> **保守阈值**：`0.6` 是经验值。低于阈值**不猜**，走「未识别，请重说」——宁可不做，不可写错（L-4 闭集优先）。

#### 6.8.5 槽位解析（`domain/voice/parse.ts`）

**闭集**：

```ts
export const ACTIONS = [
  '全对','错1','错2','错3','错4','错5','错6','错7','错8','错9',
  '过关','不过关','缺交','请假','补交','已更正','优秀',
  'A+','A','A-','B+','B','C','D',
  '清空','撤销',
] as const;

export interface VoiceCommand {
  no: number;                       // 1..N
  action: typeof ACTIONS[number] | null;
  value: CellValue | null;           // 分数时给出
  status?: EntryStatus;
  pass?: boolean;
  conf: 'exact' | 'fuzzy';
}

export function parseVoice(text: string, ctx: { n: number; scheme: ScoringScheme }): VoiceCommand[]
```

**切分**：以 `号` 为分隔符切成若干「号段」；每段形如 `{数字}号{动作}`。例：
- 「12号优秀 5号已更正」→ `[{12, 优秀}, {5, 已更正}]`
- 「3号错2 4号全对」→ `[{3,错2},{4,全对}]`
- 「12号98分」→ `[{12, value:{kind:'score',score:98}}]`

**解析规则**：

| 步骤 | 规则 |
|---|---|
| 1 | 找号段：正则 `(\d{1,3})\s*号`；无则整段尝试「动作」+ 当前焦点学号 |
| 2 | 学号约束 `1..N`；越界 → 尝试最近邻（±1 内且唯一）否则丢弃并提示 |
| 3 | 动作匹配：先 `ACTIONS` 精确匹配 → 再拼音 `simWord ≥ 0.6` 取最高分唯一候选 |
| 4 | 分数：`(\d{1,3}(\.\d)?)\s*分`，且 `0 ≤ v ≤ maxScore`，否则丢弃 |
| 5 | 方案校验：`grade` 方案收到分数 → 拒绝；`check` 方案收到等级 → 拒绝（L-4） |
| 6 | 歧义表（见下） |
| 7 | 输出按 `no` 升序去重（同号后者覆盖前者，并在 UI 标「覆盖」） |

**歧义表（必须硬编码）**：

| 识别文本 | 解释 | 处理 |
|---|---|---|
| `不交` | 可能 =「没交」或「补交」 | **默认「缺交」**，并在回显里给【改成补交】按钮 |
| `没有交` / `没交` | 缺交 | 缺交 |
| `优秀` | 可能是光荣榜表扬，也可能是等级 A+ | 按方案：`grade` 方案 → 若 `grades` 含 `A+` 则给 `A+`；否则只盖 `excellent` 章 |
| `过关` | `pass=true` | 仅 `check`/`mixed` 方案可用 |
| `错` + 单数字 | 听写错数 | 需模板 `dictationQuickKeys` |
| 纯数字 + 方案为 grade | 可能是学号 | 不解析，提示「请说『X号』」 |

#### 6.8.6 回显确认层（`ui/components/VoiceConfirm.tsx`）

**这是感知收益最大的一层（0 成本）**，必须做：

- 每解析出一条命令，立即在网格上**闪示**（高亮 600ms）+ 顶部出现灰色胶囊：
  `🎤 12号 → 优秀  [撤销]  [改…]`
- `settings.voiceAutoConfirmMs`（默认 1500ms）内可撤销；撤销后该条不写库。
- 多条命令时显示为列表（最多 5 条，超出折叠为「+3 条」）。
- 「改…」打开内联小面板，可改学号/动作（不打断语音）。

> **注意**：回显层不能阻止后续命令，否则连续报 20 个学生会卡住。所以是"闪示 + 事后可撤"而非"逐条确认"。

#### 6.8.7 纠错日志（`infra/idb.ts`，可降级）

- 表 `voice_log`：`{ id, raw, normalized, parsedJson, accepted, correctedTo, at }`。
- `accepted=false` 或用户手动改过 → 记一条。
- 用途：老师可在设置里【导出语音纠错日志】（CSV），后续据此扩充同音表。
- IndexedDB 不可用（隐私模式）→ 全部 try/catch 静默跳过，**不影响主流程**。

#### 6.8.8 可选：`phrases` 热词（特性检测，失败静默）

```ts
const hasPhrases = typeof (window as any).SpeechRecognitionPhrase === 'function';
if (hasPhrases) {
  rec.phrases = HOTWORDS.map(w => new SpeechRecognitionPhrase(w, 5));
}
```

`HOTWORDS` = 动作词表 + 全部学生姓名 + `号`。捕获异常一律忽略。**不得**因这个特性缺失而改变主流程。

#### 6.8.9 VAD（可选，P2）

`getUserMedia({ audio: true })` + `AnalyserNode` 算 RMS，低于阈值 800ms 视为停顿，给 UI 一个「可以说话了」暗示。**不阻断识别**（识别仍走 SpeechRecognition 自己的 VAD）。

> **注意**：`getUserMedia` 会二次申请麦克风权限，若用户拒绝要静默降级到"无 VAD"，不得报错。

#### 6.11.3 ZIP 写入（store-only）

```ts
// infra/zip.ts —— 无依赖，~110 行
export function zipStore(files: { name: string; data: Uint8Array }[], mtime?: Date): Blob
```

实现要点：
1. 每个文件：local file header（签名 `0x04034b50`，method 0 = store）+ 文件名（UTF-8，置 flag bit 11 = `0x0800` 表明 UTF-8）+ 数据。
2. 中央目录：签名 `0x02014b50`，版本 `20`，CRC32、压缩/原始大小相等。
3. 结尾：`0x06054b50` + 条目数。
4. CRC32 用查表法（`makeCrcTable()` 一次生成）。
5. **必须置 UTF-8 flag**，否则 Windows 资源管理器解压中文文件名会乱码——V1 的 zip 就踩过这个坑（评审 P3）。

**单测**：R-9 用 Node 的 `zlib`/手工解析验证 zip 可被 Python `zipfile` 读出且文件名正确（可在 CI 里跑一个 `node -e` 校验，或直接断言中央目录字节）。

### 7.1 一次录入（含积分）

```

```

## 8. 算法与公用工具

### 8.1 数值工具

```ts
/** half-up 保留 1 位小数。禁止 toFixed（二进制误差 + 返回字符串） */
export const round1 = (x: number) => Math.round(x * 10) / 10;

/** 百分比转 0-100 整数（用于阈值比较，避免浮点） */
export const toPct = (rate: number) => Math.round(rate * 1000) / 10;   // .90 → 90
```

> **⚠️ 关键**：`tierOf` 里比较用 `p >= s.excellentRate * 100`。若 `excellentRate = 0.9`，`0.9*100 = 90.00000000000001`（IEEE754），`p = 90`（由 `A-` 折算）时 `90 >= 90.00000000000001` 为 **false**，A- 会被判成「良好」！
> **必须**改成 `p >= toPct(s.excellentRate)` 且 `toPct` 用整数化：`p * 10 >= Math.round(s.excellentRate * 1000)`。
> 这条已在 V2 单测里用 `A-`（90）与 `B+`（85）两个"恰好在阈值上"的样本钉死（AC-60.3）。

### 8.2 折行 `wrapTokens`

沿用 V1（PRD BR-19，`maxWidth = 70` 半角单位，CJK=2、数字/字母/逗号顿号=1，`号、`=2 单位 + 数字位数）。**不得改动 70**（66–69 让光荣榜折行；≥72 使暂未提交变 12/12/6）。

### 8.3 归档与对比

- 历史对比图：选一个历史记录 → 柱图两根（历史 vs 本次），仅当两者 `maxScore` 与 `kind` 兼容时可比；不兼容时柱图只画本次并提示「方案不同，无法对比」。
- `metricsVersion:1` 的历史不参与对比（§4.6.5）。

### 8.4 拼音近似表规模

- 汉字表：动作词 + 同音候选 + 常见姓氏（用于姓名热词），约 400–600 字，`< 8KB`。
- 生成方式：**手写**（不做构建期生成，避免增加工具链复杂度）。
- 单测：`simWord('全对','全兑') ≥ 0.6`、`simWord('全对','清空') < 0.4`。

### 9.1 单元格显示优先级（必须按此实现）

```
status==='leave'   → 灰底 + 「假」
status==='missing' → 灰底虚线 + 「×」
value?.kind==='score' → 数字（按 tier 着色）
value?.kind==='grade' → 字母（按 tier 着色）
value?.kind==='pass'|pass===true → 「√」（绿）
value?.kind==='text' → 文字（截断 4 字 + tooltip 全文）
空 → 只有学号
```
`stamp==='corrected'` 加右下角 ✓ 角标；`stamp==='excellent'` 加 ⭐ 角标；`makeup` 加右上角 ↺ 角标。**角标与主值不互斥**。

**色调细则**（V1 §4.2 继承，评审 F4 / §4 裁定）：
- `text` 走 `classifyDictation()`：全对 → 绿、错 1–3 → 琥珀、错 ≥4 → 红、其他 → 灰（不能因为折算不出百分就一律灰，否则与「缺交/请假」同色）。
- `grade` 走档位，但 `A-` **固定琥珀**：统计条里它算优秀（90%），老师的批改直觉却是「很好但有错要订正」。
- `score` 按百分比档位（绿/蓝/琥珀/红）。
- `leave` / `missing` 恒灰。

### 9.1.1 【👁 只看未过关】过滤（FR-21）

## 16. 与 PRD-V2 的对齐补充（实施时必读）

> 本节是 PRD-V2 未写、但实现时必须遵守的**补充裁定**。本节优先级高于 §1–§15。

1. **档位比较必须整数化**（§8.1）：`p * 10 >= Math.round(rate * 1000)`，否则 `A-`(90) 在 `0.9*100` 的浮点误差下被判成「良好」。这是最容易写错且最难被发现的一条。
2. **`D` 折算 55%**（ADR-13）：不要改成 60，否则 D 与"及格"语义打架。
3. **`√` 与 `×` 不是等级**：迁移时 `√→pass=true`、`×→status='missing'`（§4.6.2）；任何地方出现 `grade==='CHECK'` 都是错的。
4. **`notSubmitted` 含缺交**：`= N − entered − leave`；`missing` 单独计数但 ≤ 它。
5. **报表班级行恒输出**：即使只有一个班（INV-11），否则改班级名后老师看不到效果。
6. **补交不自动给分**：补交只是"标记 + 扣分规则"，分数要老师补录。
7. **方案是记录快照**：历史报表用历史自己的 `scheme` 重算，不得用当前全局方案。
8. **积分账本只追加**：撤销写反向行，不 `splice`（INV-10）。
9. **语音必须能 mock**：`recognizer` 之外不得直接引用 `SpeechRecognition`，否则 E2E-21 做不了。
10. **当日汇总必须含已固化的历史**：老师可能先【更新修改】固化再截图，只看 `records` 会漏。
11. **`maxWidth` 保持 70**：不要"优化"成 72 或 68。
12. **手册不引 md 库**：结构化数组 + JSX。
13. **不新增运行时依赖**（§15.1）。
14. **每个里程碑都要提交**，不要一次性大提交——评审时要能按里程碑看 diff。
15. **名单口径必须与四档口径分开写**（PRD §2.3.1）：等级值按字母秩、分数值按百分。用 `tierOf` 判名单会把 `A-` 归入光荣榜，与参考成品不符（`A-` 在统计里算优秀、但名单进【需更正】）。
16. **【已更正】不是独立名单**：它是【需更正】的子集，报表里以下子段呈现，人**不从【需更正】里拿掉**。
17. **【👁 只看未过关】不持久化**，且保留原学号重排（不重新编号）。
18. **听写默写的「错 N」**不进入四档统计（只算 `pass/missing/leave` 与文字标记）；只有分数与等级参与 `percentOf`。但「错 N」与「过关」都要计入 `entered`（已登记），否则 `notSubmitted = N − entered − leave` 会把已过关/已写「错N」的人算成未提交（v2.0.0 的 F1）。
