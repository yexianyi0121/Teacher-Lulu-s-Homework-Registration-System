## 1. 缺陷 #1：混合方案的数字键歧义

### 1.1 现象（已复现 + 代码定位）

「自定义」模板默认评分方案是 `mixed`（`src/domain/constants.ts:49`：`custom.defaultScheme = 'mixed'`）。
`useInputEngine.ts` 数字分支的判断顺序是 **先分数、后等级**：

```ts
if (/^[0-9]$/.test(key) || key === '.') {
  if (pendingRef.current) commitPending();
  if (schemeAllowsScore(scheme)) { … appendBuffer(key); return; }   // ← mixed 命中这里
  if (schemeAllowsGrade(scheme) && km[key]) { … }                    // ← 永远到不了
}
```

`mixed` 同时允许分数与等级，于是 **1/2/3/4 全部进分数缓冲区**，敲 `1` 得到「1 分」，而不是 `A+`。
提示条却写着「1 A+ 2 A 3 A- 4 B+ 5 B 6 C 7 D」（`hint.ts` 按 `buildGradeKeyMap` 生成）——**提示与行为不一致**，这是老师会觉得「系统坏了」的那类缺陷。

### 1.2 判定

缺陷成立。根因是**同一物理键承载两种语义，且没有显式消歧机制**。不是「顺序写反了」——单纯调换顺序会让分数永远打不进去。

### 1.3 需求

**FR-46 数字键含义可显式切换（必做）**

- FR-46.1 新增会话级（按表持久）设置 `digitKey`，取值 `auto | grade | score`，默认 `auto`。
- FR-46.2 `auto` 的解析规则：`grade` 方案 → `grade`；`score` 方案 → `score`；`check` 方案 → `dictation`；**`mixed` 方案 → `grade`**（因为混合表的主用途是打等级，且用户本轮明确按 `1` 期待等级）。
- FR-46.3 提示条最左侧显示当前数字键语义 chip：`⌨ 数字＝等级` / `⌨ 数字＝分数`，点击即切换并 Toast 说明；`\``（反引号）为快捷键。
- FR-46.4 切换后 `hint.ts` 的提示语必须同步：等级模式显示 `1 A+ 2 A …`，分数模式显示「输入分数后按【Enter】」。
- FR-46.5 只影响**数字键**；字母键（A/B/C/D 及 700ms 内的 `+`/`-` 修饰）在两种模式下都保持「打等级」语义。
- FR-46.6 在 `score` 方案下不显示该 chip（没有歧义，避免噪音）。

**验收 AC-86**：新建「自定义」表（mixed）→ 敲 `1` → 格子显示 `A+`；点击 chip 切到「数字＝分数」→ 敲 `85`+`Enter` → 格子显示 `85`；切回后 `2` → `A`。
**验收 AC-87**：质量监测表（score）不出现该 chip，数字键始终是分数。
**回归 R-10**：`mixed` 表在「数字＝等级」模式下，`8`/`9` 无动作且有 Toast「本表没有该等级键」——不得静默吞键。

## 2. 缺陷 #2：印章与学号重叠

### 2.1 现象与根因

- 学号：`src/styles/global.css:371` `.cell-no { position:absolute; top:4px; left:6px; }`
- 印章：`src/styles/global.css:1253` `.cell-stamp { position:absolute; top:2px; left:4px; z-index:2; }`

两者**同在左上角**，印章（⭐/✅ 12px）直接压住学号（10px）。这是 V3 新增七档色 + 印章提级时引入的定位冲突。

### 2.2 需求

**FR-47 单元格四角分区（必做）**

| 角位 | 内容 | 尺寸/样式 |
|---|---|---|
| 左上 | 学号（+ 姓名） | 10px `--text-2` |
| **右上** | 印章 ⭐（优秀）/ ✅（已更正） | 14px，`z-index:2` |
| **右下** | 状态角标：缺 / 假 / 补 | 16px 圆角方，现有色不变 |
| 中部 | 主值（A+/分数/全对/错N） | 不变 |

- FR-47.1 四个角位**互不重叠**且任一组合下都不压主值；无角标时不留空洞阴影。
- FR-47.2 印章必须有 `title`（`优秀` / `已更正`），供鼠标悬停与读屏。
- FR-47.3 迷你变体（`data-variant="mini"`，用于汇总图）按比例缩到 8px，仍不重叠。
- FR-47.4 海报/汇总图里的同一套布局必须复用同一 CSS 类，不得各写一份。

**验收 AC-88**：给 1 号盖「优秀」、2 号盖「已更正」、3 号同时缺交 + 优秀 + 有分数 → 截图三格，学号/印章/角标三者可同时看清、无重叠（人工目检 + 提供截图）。
**验收 AC-89**：375px 宽视口下同样不重叠（配合 FR-51）。

## 3. 布局重排：把「输出」和「录入」分开

### 3.1 现状问题诊断

当前页面的两条工具栏（`src/components/ActionsBar.tsx`）：

```
行 1（录入动作）：语音 · 盖章类型 · 过关 · 👁只看未过关 · 补交 · 缺交 · 请假 · 全选
行 2（输出+管理混排）：报表生成 · 截图发群 · 当日汇总 · 本周汇总 · 积分 · 导出 · 清空 · 更新修改
```

问题三条：

1. **价值最高的动作被埋在第二行**：老师一节课后最常做的是「报表生成 / 截图发群」，却在第二行第 1~2 位，和「清空」这种破坏性动作用同样的视觉层级（Pill ghost），容易误点。
2. **语义混装**：`积分`/`导出` 是「管理」，`报表/海报/汇总` 是「输出」，`清空/更新修改` 是「写入存储」，三种职责挤在一行。
3. **录入动作离网格太远**：`补交/缺交/请假/盖章` 作用对象是「当前格」，却和网格隔了一整行输出按钮，视线要跨越。

用户的三条猜想（最上方 / 左侧 / 补交那行上方）里，**「补交那行上方」最接近正解**——即「输出带紧贴参数行、录入带紧贴网格」。但还不够：需要同时解决「破坏性动作混杂」与「视觉层级」两个问题。

### 3.2 采用方案：三段式（输出带 / 录入带 / 管理收纳）

```
┌──────────────────────────────────────────────────────────────────┐
│ 🌸 学情登记分析系统   三年二班·50人 ▾   已自动保存 12:45   [⚡秒跳] [🔍搜学号] [📁] [⚙️] │  H1 Header 64
├──────────────────────────────────────────────────────────────────┤
│ 登记类型 ▾  日期 ▾  作业内容 ______________        [⚙ 本表设置]  │  H2 参数行 56
├──────────────────────────────────────────────────────────────────┤
│ 📋 报表生成     🖼️ 单条海报     📸 当日汇总     🗓️ 本周汇总     │  H3 输出带 52（右对齐，主按钮 2 个实心）
├──────────────────────────────────────────────────────────────────┤
│ ⌨数字＝等级  语音  盖章▾  过关  👁只看未过关 │ 补交 缺交 请假 全选 │ 🧹清空 💾保存 │  H4 录入带 52
├──────────────────────────────────────────────────────────────────┤
│ 💡 1 A+ 2 A 3 A- …                                               │  H5 提示 32
│ ┌─ 单元格网格 ────────────────────────────────────────────────┐  │
│ │   1 A+   2 A   3 A-   …                                     │  │
└──────────────────────────────────────────────────────────────────┘
```

**FR-49 输出带独立（必做）**

- FR-49.1 新增独立「输出带」置于**参数行下方、提示条上方**，占满一行，内容右对齐；左侧可留空或放本表信息（只读）。
- FR-49.2 输出带只放 4 个：`📋 报表生成`（主按钮，实心橙）、`🖼️ 单条海报`（主按钮，实心紫）、`📸 当日汇总`、`🗓️ 本周汇总`（次级 ghost）。顺序固定，不得插入其它动作。
- FR-49.3 录入带（原行 1）下移，紧贴提示条；末尾追加 `🧹 清空` 与 `💾 更新修改`，两者之间用 12px 分隔。
- FR-49.4 `⭐ 积分` 与 `📤 导出` 移入 `⚙️ 设置` 菜单下的「数据与积分」入口，**同时保留**在录入带最右侧的「⋯ 更多」浮层中（两处入口，避免老用户找不到）。
- FR-49.5 破坏性动作（清空）与写入动作（更新修改）必须与输出带**视觉隔离**：不得出现在同一行。
- FR-49.6 高度预算（与设计说明 ADR-25 同一份账）：输出带 **48px**、录入带压到 **48px**、参数行 56→**48px**、提示条 32→**28px**，合计 760px 仍 ≤ 768；**统计条与图表卡片默认折叠**（已有折叠能力，改为默认收起），1366×768 下网格可见行数不得少于 4 行。

**验收 AC-90**：1366×768 下 `document.documentElement.scrollHeight ≤ 768`（常规作业表，5 行网格）。
**验收 AC-91**：输出带 4 个按钮的 `aria-label` 与 `title` 齐备；`Ctrl+Enter`/`Ctrl+J` 快捷键仍可用。

### 3.3 其它交互改进（FR-49.7，随本轮一起做）

| # | 改进 | 理由 |
|---|---|---|
| a | 输出带按钮点击后，**生成中的按钮显示 spinner 并禁用**，其余按钮不变灰 | 海报栅格化约 300~800ms，现在没有任何反馈，老师会连点 |
| b | 报表/海报弹窗关闭后，焦点回到原格（不是回到 body） | 现在是回到 body，连续录入要重新点格子 |
| c | 危险操作（清空）使用**危险色描边 + 二次确认**，并显示将清空的格数 | 降低误触 |
| d | `只看未过关` 的开关放在录入带最右侧，与筛选语义分组 | 现在夹在「过关」和「补交」中间，误触多 |
| e | 保存状态从「已自动保存 12:45」改为**可点击**，点开显示「上次保存/历史条数/立即备份」 | 数据安全第一轮已被打回一次，给用户一个检查入口 |

## 5. 终端形态调研：手机端与小程序

### 5.1 现状评估

| 能力 | 现状 | 手机可用？ |
|---|---|---|
| 技术栈 | Vite + React 18 SPA，localStorage 单机存储 | ✅ 浏览器能跑 |
| PWA | 已有 `manifest` + Service Worker + 图标（`v3-shell` 用例覆盖） | ✅ 可加主屏 |
| 布局 | 固定 10 列网格、两行工具栏、最小可用宽度 ~1100px | ❌ **手机上会横向溢出** |
| 海报/汇总 | Canvas/HTML 栅格化，固定 1080 宽 | ⚠️ 可生成但预览拥挤 |
| 语音 | Web Speech API | ⚠️ iOS Safari 支持不全 |

结论：**功能全在浏览器里，改造量集中在「响应式布局」，不在「能力」**。

### 5.2 原生小程序：不建议（且 web-view 路线走不通）

关键事实（官方文档）：

- `web-view` 组件明确写着「**个人类型的小程序暂不支持使用**」，且 `src` 必须是登录后台配置过的**业务域名**（需已备案 HTTPS）。参见 [web-view 官方文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html) 与 [业务域名说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/domain.html)。
- 也就是说：想用「小程序套壳加载现有网页」，需要**企业/组织主体 + 备案域名 + 一台公网服务器**——而本产品是**零后端、纯本地存储**，为了套壳额外背上服务器与备案成本，性价比极低。
- 若走**原生重写**（Taro / uni-app）：`localStorage`→`wx.setStorageSync`、`html-to-image`→`canvas`、文件导出→`wx.getFileSystemManager`、语音→同声传译插件、`file://` 双击→不存在。等于把 1 万行里的大部分重写一遍，**估 2~3 周**，且必须企业主体。
- 类目与资质：教育相关内容在小程序类目里部分需资质（如培训机构需办学许可）。个人开发者可用「工具-效率」类目规避，但一旦涉及「学生成绩」，审核问询概率不低。

**结论：V4 不做小程序。** 若未来确需，建议路径是「企业主体 + uni-app 复刻 + 云端账号体系」，作为独立立项，不在本产品线里做。

### 5.3 推荐路径：PWA 响应式（本迭代做）

**FR-50 手机端可用（必做）**

- FR-50.1 断点：`< 720px` 手机单列；`720–1100px` 平板；`≥1100px` 桌面（现状）。
- FR-50.2 手机端网格列数：**10 → 5 列**（`gridColumns()` 按视口返回 5/6/10），单元格高度降到 56px，字号按 `--ui-scale` 缩放。
- FR-50.3 手机端工具条：输出带变**底部固定操作条**（4 个图标 + 文字，48px 高）；录入带变**可横向滚动的 chip 行**。
- FR-50.4 手机端不提供键盘录入，改为「点格子 → 底部弹出数字键盘/等级选择（6 个圆钮）」。
- FR-50.5 竖屏优先；横屏至少可用但不做专门优化。
- FR-50.6 首屏在 375×667 下必须：能看到班级、日期、5 列网格的首行，且无横向滚动条。

**FR-51 安装与数据安全提示（必做）**

- FR-51.1 首次在移动端打开时，底部提示条「添加到主屏幕，用起来更像 App」，可关闭（存 `settings.installHintDismissed`）。
- FR-51.2 移动端每 7 天未导出时提醒一次「建议备份到文件」——因为 **iOS 会在长期不用后清理站点存储**，这是纯前端 PWA 的唯一真实风险。
- FR-51.3 手机端海报/汇总生成后，优先调起系统分享（`navigator.share`），不支持则回退到下载。

**验收 AC-94**：用 375×667 与 390×844 两个视口跑 E2E，无横向溢出、网格 5 列、底部操作条 4 项可点。
**验收 AC-95**：`navigator.share` 存在时点击「分享图片」调用它（mock 断言），不存在时触发下载。
**验收 AC-96**：7 天未导出的提醒逻辑用可注入时钟单测覆盖（不依赖真实 7 天）。
