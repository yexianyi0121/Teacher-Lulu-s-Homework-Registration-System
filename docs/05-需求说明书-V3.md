## §1 术语补充（在 01/03 的术语表上追加）

| 术语 | 定义 |
|---|---|
| **过关（Pass）** | 一个学生的一次登记是否「通过」。**唯一判定入口** `isPassed()`，见 BR-61。 |
| **过关规则（PassRule）** | 教师可配置的过关判定方式，影响格子上的 ✅、只看未过关、海报过关人数、积分「达成」条件。 |
| **补交（Makeup）** | 对**未交/请假**的学生追加的一次提交，携带时间与说明。它不是新的登记记录。 |
| **登记表（Sheet）** | 一天内按「登记类型 × 作业内容」形成的一张表，`sheetId` 标识，见 V2 §1。 |
| **当日汇总 / 本周汇总** | 把多张表拼成一张长图。当日 = 同一天全部表；本周 = 同一 ISO 周内按日拼接。**1:1 像素，不缩放。** |
| **数据健康** | 存储是否正常：打开方式、存储键、字节、最后保存时间、快照数、记录/历史条数。 |
| **评价语（PosterComment）** | 出现在海报页脚的一段教师点评文字，替代原来的 `© Designed by …`。 |

### 不变量（在 01 §1 / 03 §1 的 INV 之后追加）

- **INV-14 数据可恢复**：任何时候都必须有一条「把数据完整取出」的路径（导出 JSON / 下载备份），且不能依赖网络。
- **INV-15 不空覆盖**：内存态为空而磁盘态非空时，**禁止写盘**（见 BR-75）。
- **INV-16 过关唯一**：全系统「是否过关」只能来自 `isPassed()`；禁止在 UI 里各写各的（V2 的海报「未过关 0」正是散落判定的后果）。
- **INV-17 颜色双通道**：每个视觉状态必须同时有「颜色 + 图标/字」两条通道，保证色弱与黑白截图可辨。
- **INV-18 补交封闭**：补交只对 `missing | leave` 开放；反向禁止（有值或已过关不得补交）。
- **INV-19 逐字回归**：报表文案、样例 A/B/C 的统计数字与名单**不得**因本次改动而变化（R-1~R-9 必须仍全绿）。
- **INV-20 打开方式可辨**：用户必须能在界面上看到「当前是双击文件打开还是网址打开，数据存在哪里」。

## §3 功能需求

### FR-31 缺交 / 请假 / 补交 三态必须一眼可辨

**痛点**：缺交是灰底，补交只加了一个白色小图标，老师在手机上根本看不见。

**规则（BR-79）**
1. 缺交：底色 `--state-missing-bg #FFE9E9`，1.5px 红色虚线边框，右上角**实心红角标「缺」**（16×16，白字 10px，圆角 4px）。
2. 请假：底色 `--state-leave-bg #F3EFFA`，1.5px 紫色点线边框，右上角**实心紫角标「假」**。
3. 已补交：底色 `--state-madeup-bg #EAF7EF`，1.5px 绿色实线边框，右上角**实心绿角标「补」**，并在主值下方加 10px 文字「补交」。
4. 角标与「已更正/优秀」印章角标**不互斥**，并排显示（印章在左上，状态角标在右上）。
5. 三态都必须同时满足「颜色 + 图标 + 文字」双通道（INV-17）；黑白打印后可辨。

**验收**
- AC-31.1 给定缺交 → 截图中角色标为纯色块而非白色描边，`getComputedStyle` 底色 = `#FFE9E9`。
- AC-31.2 补交后格子同时出现「补」角标与「补交」小字，且报表【已补交】段出现该学号。

### FR-32 过关规则可配置，并消除「全对」与「√」的重复

**痛点**：听写全对显示「全对」，又显示「√」，两个概念指同一件事；老师希望能配「A/A+ 自动算过关」。

**规则（BR-61）**
1. **唯一入口**：`isPassed(entry, scheme, passRule): boolean`。
   - `entry.pass === true` → 过关（听写手工/语音打了 √）。
   - 值的百分 `p = percentOf(entry, scheme)`：`p !== null` → `p >= scheme.passRate` 即过关。
   - 文本值：`classifyDictation(text).kind === 'perfect'` → 过关；`error`（错 N）→ 不过关。
   - 缺交/请假 → 不过关（但请假不计入「未过关」人数，见 BR-64）。
2. **可配置**（设置 → 录入偏好 → 过关规则）：
   ```ts
   interface PassRule {
     kind: 'percent' | 'grade' | 'mixed';
     gradePass: GradeLetter[];      // 默认 ['A+','A']，可勾选 A-、B+…
     dictationAutoPass: boolean;    // 默认 true：听写「全对/错0」自动算过关
   }
   ```
   - `percent`：只按 `passRate`（默认及格线 60%）。
   - `grade`：等级 ∈ `gradePass` 才算过关（分数仍按 `percent`）。
   - `mixed`：两者取并集（默认）。
3. **显示去重**：听写「全对」的格子，主值显示 `全对`，**不再同时显示 `√`**；过关状态用右上角小 ✅ 角标表示。手工打 √ 的格子仍显示 `√`。
4. **提示语必须写清输入方式**（原提示「直接输入『错2』『全对』」会误导键盘操作）：
   - 听写：`💡 错几：输入 0–9（0=全对）· 空格 盖章 · X 缺交 · L 请假 · G 手打过关`
   - 常规：`💡 1 A+ 2 A 3 A- 4 B+ 5 B 6 C 7 D · 空格 盖章 · X 缺交 · L 请假`
   - 提示语必须由 `scheme.grades` + 键位表**动态生成**，不得写死常量字符串。
5. **等级键位动态化**：键位表恒为 `1..7`，按当前方案启用的等级**从左到右依次绑定**（启用 A+/A/A-/B+ 时，`1→A+ 2→A 3→A- 4→B+`）。提示语同步显示实际映射。
6. 过关规则变更后：格子 ✅、统计条「达标率」、海报「过关/未过关」、只看未过关、积分「达成」条件**全部立即重算**，且不改写任何已录入值。

**验收**
- AC-32.1 听写敲 `0` → 格子文本 `全对`，`isPassed` 为真，**不出现 `√` 字符**。
- AC-32.2 设置 `gradePass=['A+','A']` 后，一个 `A-` 学生的 ✅ 消失、进入只看未过关；再勾上 `A-` 后恢复。
- AC-32.3 提示语随可用等级变化：勾选 B+ 后提示语出现 `4 B+`，且按 `4` 能录入 B+。

### FR-33 补交只对「未交 / 请假」开放，并全链路可见

**规则（BR-62）**
1. 门禁：`canMakeup(entry) = entry.status === 'missing' || entry.status === 'leave'`。其余状态（有值、已过关）点击【补交】→ 灰显 + Toast「只有缺交或请假可以补交」。
2. 补交弹窗：可选学生列表**只列出当前表中 `canMakeup` 为真的学号**，支持多选 + 统一说明，或逐个写说明。
3. 数据：`entry.makeup = { at: number, note: string }`；**保留原 `status`**（缺交仍是缺交，只是「已补交」）。
4. 名单：`RosterGroups` 增加 `madeUp`（已有的第 4 组），并保证**互斥**：已补交的不再出现在【暂未提交】。
5. 展示：格子（FR-31）、报表（`📥 【已补交】` 段，格式 `N号（说明）`）、当日汇总海报（该表统计行加「补交 k」）、周汇总均须出现。
6. 撤销：补交是批量操作，`Ctrl+Z` 一次全部撤销（沿用 V2 快照式撤销）。

**验收**
- AC-33.1 对已录入分数的学生点补交 → 被拒绝并提示；对缺交学生 → 成功。
- AC-33.2 补交后：格子有「补」角标；报表出现 `📥 【已补交】：`；该生不再出现在【暂未提交】；当日汇总该表统计出现「补交 1」。

### FR-34 汇总视图切换必须真的切换（**bug**）

**现状（缺陷根因，必须写进提交说明）**：`src/App.tsx:181` 传入 `onRegenerate={() => handlePoster(posterMode)}` 是**过期闭包**——`PosterModal` 先 `setMode('single')` 再调 `onRegenerate()`，而 `handlePoster(posterMode)` 里的 `posterMode` 还是切换前的值，于是又 `setPosterMode(旧值)` 并按其重新栅格化，画面回到原样。用户看到的就是「点了没反应」。

**规则（BR-63）**
1. 汇总目标是一个**显式状态**：
   ```ts
   type PosterTarget =
     | { mode: 'single'; sheetId: string }
     | { mode: 'daily' }
     | { mode: 'week'; weekStart: string };
   ```
2. 切换按钮必须**传入目标值**（如 `onSwitch({ mode: 'single', sheetId })`），禁止读取闭包里的旧值；禁止在 `PosterModal` 内 `setMode` 之后再依赖父组件闭包。
3. **单条模式必须有表选择器**：下拉列出「当天已登记的全部表」（`content` + 类型 + 登记人数），默认选中当前表；用户可切换为任意表——用户原话「应该可以设置切换为具体哪类」。
4. 点击切换后：立即显示「生成中…」，重新栅格化完成后替换预览图；失败时保留旧图 + Toast，不得白屏。
5. 三向切换：单条 ↔ 当日汇总 ↔ 本周汇总。

**验收**
- AC-34.1 打开单条海报 → 点【切换为当日汇总】→ 预览图内容变为多段（`img.naturalHeight` 变大，或预览文本含「登记汇总」）。
- AC-34.2 在当日汇总 → 点【切换为单条】→ 出现表选择器，选择「常规作业」后预览为该表。
- AC-34.3 连续点击 5 次来回切换，无报错、无内存泄漏（`posterUrl` 旧的被 `revokeObjectURL`）。

### FR-36 图标与控件随窗口自适应

**规则（BR-69）**
1. 三档密度（`--density`）：`compact`（宽度 ≤ 1280）、`normal`（1281–1679）、`wide`（≥ 1680）。
2. 关键尺寸：

   | 令牌 | compact | normal | wide |
   |---|---|---|---|
   | `--icon-size`（装饰图标） | 20px | 22px | 24px |
   | `--btn-h`（胶囊按钮高） | 32px | 36px | 40px |
   | `--fs-base` | 13px | 14px | 15px |
   | `--pill-pad-x` | 12px | 14px | 16px |
   | `--cell-h` | 68px | 76px | 84px |

3. **必须**保证 1366×768 下常规作业页**零纵向滚动**（V2 已是事实，不得回退）；工具栏允许换成两行，但两行必须同高、同间距。
4. 图标不得使用 emoji 作为**唯一**手段表达状态时依赖系统字体大小——状态角标（缺/假/补/✅）一律用 CSS 绘制或 SVG，保证不同系统下尺寸一致。
5. 所有按钮必须带 `title`（悬浮提示），图标按钮必须有 `aria-label`。

**验收**
- AC-36.1 在 1280 / 1366 / 1920 三个宽度下截图，`--icon-size` 分别为 20/22/24，且工具栏不重叠、不溢出。
- AC-36.2 1366×768 下 `document.scrollingElement.scrollHeight === 768`（常规作业模式）。

### FR-37 等级颜色区分 + 混合模式分数必须着色（**bug**）

**现状（缺陷根因）**
- `tone.ts` 的 `gradeTone()` 把 `A-` 硬编码成 `amber`，而 `C` 走档位也是 `amber` → 两档同色。
- 混合方案（`mixed`）下若 `maxScore === null`，`percentOfValue` 对分数返回 `null` → 一律 `gray`。

**规则（BR-66）**
1. **等级固定色表**（与统计四档**解耦**，统计仍按百分）：

   | 等级 | 底色 | 边框 | 主色 | 说明 |
   |---|---|---|---|---|
   | A+ | `#E8F5EC` | 实线 2px `#3F8F5F` | `#2F7A4E` | 深绿 |
   | A | `#EDF8F1` | 实线 1.5px `#5FA97C` | `#3E8A5E` | 绿 |
   | A- | `#F3FAEA` | 实线 1.5px `#8FBF6F` | `#6E9B4C` | 黄绿 |
   | B+ | `#FEF9E4` | 实线 1.5px `#E3B93F` | `#A9851F` | 黄 |
   | B | `#FDF2E3` | 虚线 1.5px `#E89A4A` | `#B4701F` | 橙 |
   | C | `#FDEDE6` | 虚线 1.5px `#E0704F` | `#B24A2C` | 橙红 |
   | D | `#FCE8E6` | 点线 1.5px `#D1453B` | `#A32A22` | 红 |

   每档必须**底色、边框样式、主色**三者至少两项不同（色弱可辨，INV-17）。
2. **分数着色**：分数格子按百分四档（绿 `#E8F5EC` / 蓝 `#E8F1FB` / 琥珀 `#FDF3E2` / 红 `#FCE8E6`），用**底色 + 数字颜色**表达，不加边框样式差异——与等级格子在形状上可区分（等级格右上有字母、分数格是纯数字）。
3. **混合方案**：`mixed` 必须设 `maxScore`（默认 100，可在本表设置里改）。若用户把某表方案改成 `mixed` 而 `maxScore` 为空，落库时自动补 100 并 Toast 提示；`percentOfValue` 对 `score` 在 `maxScore === null` 时回退到 `100`，**绝不允许出现「全灰」**。
4. 统计条、环形图、图例**仍按四档百分**着色（这是同一套 tier 色），但等级格子用 §1 的色表——两套色系允许并存，,须在手册里用一张对照表说明（「格子的颜色代表等级；图表的颜色代表分数段」）。

**验收**
- AC-37.1 同一屏内录入 A+ / A- / B+ / B / C / D 六格，两两之间 `background-color` 与 `border-style` 组合唯一。
- AC-37.2 混合方案下录入 95 / 85 / 65 / 30 四个分数 → 分别为绿/蓝/琥珀/红，**无 gray**。

### FR-38 等级配表情

**规则（BR-67）**

### FR-39 分数输入必须拒绝非法值（**bug**）

**规则（BR-65）**
1. 当方案含 `score` 能力时，分数必须满足：`Number.isFinite(x) && 0 <= x <= maxScore && 小数位数 <= decimals`。
2. **负号、字母、连续小数点、超过两段、空值以外的一切字符**：输入即拒绝（不进入缓冲区），并给一次性 Toast「只能输入 0–{max} 的数字」。
3. `-`、`+`、`e`、`E` 一律不进入缓冲区；全角数字要归一化为半角。
4. **粘贴**：监听 `paste` 事件，取 `text/plain`，用 `sanitizeScoreInput(text, scheme)` 清洗：去空白、全角转半角、只保留 `[0-9.]`；清洗后仍非法（多个小数点、负号、>max）→ **整条拒绝**并 Toast，不写入任何值。
5. 提交（Enter/失焦）时二次校验：非法 → 单元格红框 1.5s + Toast，`entry` 不变（不落库、不进撤销栈）。
6. 文本值（F2 自定义文字）不受分数校验限制，但长度 ≤ 20 字，且**不得**被误判为分数着色（走 `text` 分支）。

**验收**
- AC-39.1 依次尝试 `-5`、`12.5`（decimals=0）、`101`（max=100）、`1.2.3`、`abc` → 均不产生分值，格子保持原值。
- AC-39.2 粘贴 ` -5 ` → 被拒绝；粘贴 `８５`（全角）→ 存为 `85`。

### FR-44 数据不能丢（**严重 bug**）

**用户现象**：录入后关闭浏览器再打开，记录、历史、班级/教师设置全部回到初始状态。

**分析（必须按此顺序排查并逐条落地）**
1. **打开方式变化**是首要嫌疑：`file://` 与 `http://localhost:*` 是**不同 origin**，localStorage 不互通；`file://` 下不同文件夹共享同一 origin（已实测），但端口/协议变化就会「看起来数据没了」。
2. **空覆盖**：任何「内存态为空 → 写盘」的路径都会清空真实数据（`exportState()` 只导出有 `entries` 的记录，若启动期状态尚未装载完就被 `pagehide`/`beforeunload` flush，就会把空态写进磁盘）。
3. **校验失败**：`validateState` 拒绝后 `loadState` 回落快照；若快照也没有 → 进入只读空界面，用户看到的就是「全初始化」。
4. **浏览器策略**：Edge/Chrome「关闭时清除站点数据」、InPrivate 窗口、或把文件放在会被清理的临时目录。

**规则**
- BR-75 **覆盖保护**：写盘前比较「即将写入的内容」与「磁盘现有内容」的**非空程度**；若 `next` 的记录数 + 历史数 = 0 而 `prev` > 0 → **拒绝写入** + Toast「检测到数据为空，已阻止覆盖」+ 置 `readOnly`（只读），并在数据健康面板提示恢复方式。首次启动（prev 也不存在）正常写。
- BR-76 **数据健康面板**（设置 → 数据）：显示 ①打开方式（`双击文件` / `网址 http://…`）②存储键名 ③已用字节 ④最后保存时间 ⑤自动快照数 ⑥记录数/历史数/班级数；按钮【导出全部数据 JSON】【导入恢复】【复制诊断信息】。
- BR-77 **打开方式指纹**：首次运行写 `xq.env = { origin, href, at }`；若当前 `origin` 与记录不同 → 顶部黄条「你正在用另一种方式打开（上次是 file://，本次是 http://…），数据存在各自空间」+【如何找回】。
- BR-78 **自动备份**：默认每 7 天首次打开时提醒导出；设置里可开「每月 1 日自动下载 JSON 备份」。
- **导入恢复**：选择 JSON 文件 → 校验（同 `validateState`）→ 展示「将覆盖当前 N 条记录」→ 二次确认 → 先把当前数据导出到内存并提示「如需回退可撤销」→ 写入 → **一次 Ctrl+Z 可回退**。
- **读取失败必自愈**：主存校验失败 → 依次尝试最近 3 个 IDB 快照；成功则 Toast「已从备份恢复（{时间}）」，并**把损坏的原文另存为 `xq.corrupt.{ts}` 键**（不覆盖、不删除，供人工导出）。

**验收（必须真机 E2E，禁止只做单测）**
- AC-44.1 用 UI 录入 ≥3 条数据、改班级名、加 1 条历史 → `context.close()` → 用**同一 userDataDir** 重开 → 记录/历史/班级名全部还在。
- AC-44.2 手工把 `xq.state.v3` 改成非法 JSON → 重开 → 从快照恢复并提示。
- AC-44.3 手工写入「空状态」到磁盘（模拟空覆盖）→ 重开 → **不写盘**，出现黄条/提示，数据健康面板可导出。
- AC-44.4 在 `file://` 与 `http://` 两种方式下分别打开 → 出现「打开方式不同」提示。

## §6 我的测试反思（写给下一轮评审，也写给用户）

这一轮暴露的最大问题不是代码，而是**我的测试方法有系统性漏洞**：

| 我做了什么 | 为什么没抓到这些 bug |
|---|---|
| 只用 Playwright **注入 localStorage 种子**再截图 | 种子绕过了「录入 → 保存 → 关闭 → 重开」的真实链路，**FR-44 的数据丢失根本不在测试路径上** |
| 只在 **1366×768** 一个视口验证 | 图标过小、密度不适配（FR-36）从未被检查 |
| 只验证了**统计与报表的纯函数**和一次汇总图 | 海报弹窗的**交互状态机**（FR-34 切换）没被点过 |
| 用项目自带 fixtures 的「手工 metrics」做对照 | 与真实链路脱节，掩盖了 F1（V2 的「未过关 0」） |
| 未做**非法输入**的负向测试 | 分数负值（FR-39）没有用例 |
| 未逐档比对**颜色**（只看截图整体观感） | A- 与 C 同色、混合方案全灰（FR-37）看不出来 |

**改进（写进本轮设计 §8，作为长期制度）**
1. **每条新功能必须配一条「真实用户剧本」E2E**：从空库开始，只用键盘/鼠标操作，禁止注入种子（种子只允许用于「性能/边界数据」类测试）。
2. **持久化往返测试**成为每次发布的**准入闸门**：真实 UI 录入 → 关闭浏览器（复用 userDataDir）→ 重开 → 断言。
3. **颜色与尺寸必须有断言**（`getComputedStyle`），不能只靠肉眼看截图。
4. **负向测试清单**：非法输入、空数据、超大数、重复点击、快速切换、断网、只读态。
5. 每个里程碑交付时必须附**自测报告**（跑了哪些 E2E、截图几张、哪些没跑），评审先看报告再相信结论。
