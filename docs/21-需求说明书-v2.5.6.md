## FR-60 多窗口互写保护

### FR-60.1 问题

老师在**学校电脑**录完，回家再**另一个窗口**补几格——这是最常见的真实场景。
原实现：每个窗口以自己内存里的快照为准，写盘时**整表覆盖**。后果：

1. 窗口 B 录 4–6 号 → 磁盘变成只有 4–6，窗口 A 的 1–3 号**静默消失**。
2. 关掉窗口 A（触发卸载保存）→ 磁盘又被 A 的旧快照改回去，B 的 4–6 号**再次消失**。
3. 全程没有任何提示，老师以为"两边都有"。

### FR-60.2 规则

| 编号 | 规则 |
|---|---|
| BR-60.1 | 每次写盘带上**写入序号** `saveSeq`（从磁盘当前值 +1，单调递增） |
| BR-60.2 | 写盘前计算磁盘指纹 `diskStamp()` = `saveSeq + lastSavedAt + 原文长度` |
| BR-60.3 | 指纹与「我上次成功写入时的指纹」不一致 → **拒绝写入**，返回 `conflict: true`，磁盘内容一字不动 |
| BR-60.4 | 收到 `conflict` 时给**阻断级**提示（12 秒、红色），并停止本窗口的自动保存 |
| BR-60.5 | 收到其他窗口的 `storage` 事件时，同步更新本窗口基线，并给同样的阻断提示 |
| BR-60.6 | 已提示过冲突的窗口不重复弹提示（避免每次自动保存都弹） |
| BR-60.7 | 同一毫秒内连写两次也必须能分辨（`saveSeq` 兜住时间戳精度不足） |

### AC-60

- **AC-60.1** 窗口 A 录 1–3 号并落盘；窗口 B 打开后能**读到** 1–3 号。
- **AC-60.2** 窗口 B 录 4–6 号后，**磁盘仍是 A 的 1–3 号**，B 的写入被拒绝。
- **AC-60.3** 窗口 A 侧收到红色阻断提示「另一个窗口也在改这份数据…」。
- **AC-60.4** 两个窗口都不崩溃、不丢已成功写入的数据。

## FR-61 录入链路误操作防护

### FR-61.1 I-01 撤销后焦点错位

**原行为**：撤销把焦点写回「操作前的焦点」，而一次录入操作后焦点已经前移一格，
于是「撤 4 号 → 焦点跑到 3 号 → 按 5」实际记到了 **2 号**身上，全程零提示。

**规则**：
- BR-61.1 撤销补丁中存的是**本次实际改动的那一格**（`touchNo`）
- BR-61.2 撤销后焦点回到该格，而不是操作前的邻居格

**AC**：撤 4 号 → 焦点为 4 → 按 5 → 4 号被改，3 号不变。

### FR-61.2 I-02 多选从不退出

**原行为**：全选 3 格 → 点 5 号 → 按 1，**只改了 5 号**，但 1/2/3 的高亮还亮着，
老师以为「批量盖章/批量录入」没生效。

**规则**：
- BR-61.3 点击任一格 = 明确「我只改这一格」，**选区同时退出**（清空 `selection` 与 `selectionAnchor`）
- BR-61.4 没有选区时点击格子不产生任何额外状态变化

**AC**：全选 3 格 → 点 5 号 → `[data-selected="1"]` 数量为 0。

### FR-61.3 I-04 缺交被静默抹掉

**原行为**：点了「缺交」，后来又录了个 A+，`normalizeEntry` 直接把 `status` 写回 `normal`，
缺交记录凭空消失，统计里「录入人数 +1、未提交 −1」，老师事后完全看不出这孩子曾经缺交。

**规则**：
- BR-61.5 缺交或请假的学生被录入值时，**先自动补一条 `makeup` 记录**（`note` 说明来源），再转 `normal`
- BR-61.6 已有 `makeup` 的不覆盖（保留老师手填的补交说明）

**AC**：1 号缺交 → 录 A+ → 该格 `status='normal'`、`value=A+`、`makeup.note` 含「补交」。

### FR-61.4 I-06 双击编辑把等级变成文字

**原行为**：内联编辑框预填的是格子里原来的内容（如 `A+`）。老师双击进去想看看、
直接按 Enter（什么都没改），结果 `A+` 被当成**自定义文字**提交：格子从等级变文本、
颜色变灰、掉出优秀率。

**规则**：
- BR-61.7 提交内容与预填内容**完全一致** → 不做任何改写，直接原样退出编辑
- BR-61.8 内容有变化 → 正常按自定义文字提交

**AC**：录 A+ → 双击 → 直接 Enter → `data-kind` 仍为 `grade`。

### FR-61.5 I-08 确认框开着时全局快捷键仍生效

**原行为**：在「清空本条记录」确认框里下意识按 Enter（「Enter=确定」是最顺手的动作），
**确认框没关，1 号格的成绩却被改成了「过关」**；按空格会盖「已更正」章；Ctrl+Z 会撤销。

**规则**：
- BR-61.9 存在 `confirmRequest` 或 `modal` 时，全局录入快捷键**一律失效**
- BR-61.10 只放行 `Escape`（弹窗自己处理关闭）与 `Tab`（无障碍焦点移动）

**AC**：打开清空确认框 → 按 1 → 3 号格 `data-kind` 不变。
