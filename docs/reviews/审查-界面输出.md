## 二、逐条发现

### U-01 空表点「报表生成」照常生成「全员未交」的报表

**严重度**：P1（输出错：老师会直接把这份文案粘进班会/家长群）

**复现步骤**
1. 种入一个 50 人班、**0 条登记**的状态（`records: []`）。
2. 首页 50 格全空，直接点右上「📋 报表生成」。
3. 观察弹窗正文，点「复制文案」，粘贴。

**实测行为**
- `[首页格子数]= 50`、`[有值格子数]= 0` —— 确认表是空的。
- 弹窗**正常打开**（`modal=1`），正文：
  ```
  🌸 10月26日 【📝 常规作业】综合反馈 🌸
  📖 作业内容：未填写
  -------------------------
  🏫 班级：三年二班
  ❌ 【暂未提交】：
  1号、2号、…、50号
  ```
- 整个界面**没有任何「今天还没录」的提示**：没有 warn toast、没有黄条、没有措辞上的占位（对比「当日汇总」和「本周汇总」同场景都会 `showToast('今日暂无登记','warn')` 并**不打开**弹窗）。
- 截图：`U-79-空数据报表正文.png`、`U-03-空数据点报表生成.png`、`U-02-空数据首页.png`
- 代码：`src/components/OutputBar.tsx` 的报表按钮 `onReport={() => setModal('report')}` —— 只 setModal，**没有任何空数据检查**；`src/App.tsx:144-173` 的 `handlePoster` 里只有 `daily`/`week` 两种模式做了空数据拦截，报表完全没有。

**用户误解**
"报表出来了，标题、班级、名单都在，那说明今天的情况就是这样。" —— 实际上这份文案的意思是"全班 50 人一个都没交"，一旦复制发到家长群，就是一次群体误伤。而且它和"真的全班没交"在界面上**完全无法区分**。

**建议修法**
1. `OutputBar` 的报表按钮要与「当日汇总」对齐：`entered === 0` 时不打开弹窗，改弹 warn toast「今天还没有录入，报表会是全员未交。确定要生成吗？」，并提供「仍然生成」二次入口。
2. 更稳的做法：弹窗内正文顶部加一条**黄色横幅**「⚠️ 本次登记 0/50 人已录入，以下内容是『全员未交』」，复制按钮同时降级为空心样式。
3. 报表正文第一行后追加「（本次已录入 0 人 / 共 50 人）」的统计行，让老师一眼看出这是空表。

### U-03 切到「分数制」后，存量等级值仍按字母秩进光荣榜

**严重度**：P1（口径错，报表与老师预期不符）

**复现步骤**
1. 等级制下正常录入 50 人（A+~D）。
2. 点「⚙️ 本表设置」→ 方案类型改成「分数制」→ 完成。
3. 点「📋 报表生成」。

**实测行为**
- 方案弹窗里有如实提示：「改方案不会改动已录的值，只重算判定与名单（当前有 48 条等级不参与判定）」（`src/components/modals/SchemeModal.tsx:58-62`，截图 `U-31-分数制方案.png`）。
- **但关掉弹窗后首页 50 格仍然显示 A+/A/A-…，没有任何灰化或角标说明「不参与判定」**（截图 `U-37-L-切回等级制-分数不参与判定.png`）。
- 报表结果：`U-68-R7-分数制报表.png` —— 光荣榜是 **1号~28号**，需更正是 29~48 号。这正是等级制下的字母秩（A+/A 进榜、A- 及以下进需更正），**与老师的 90 分优秀线毫无关系**。
- 代码：`src/domain/roster.ts:19-26` `inHonor()` 里 `if (v.kind === 'grade') return RANK[v.grade] >= (honorIncludesA ? 5 : 6);` —— 等级值走字母秩，**完全不看 `excellentRate`**；只有 `v.kind === 'score'` 才走 `percentOf()`。

**用户误解**
"我改成了分数制、优秀线 90，光荣榜应该是 90 分以上的人，结果名单一模一样。" —— 老师会认为"改设置没生效"（这一点在 U-03 之外也复现过：优秀% 90→99 后首页无变化，见 `U-27-K2-改优秀阈值99.png` / `U-28-K2-改完阈值后首页.png` / `U-34-改阈值后首页.png`）。

**建议修法**
1. 方案切换时，把"旧值的种类 ≠ 新方案允许的种类"的格子**灰化 + 角标**（如 `!`），并在提示条常驻一行「48 格等级值不参与分数制判定」。
2. 更根本：`classifyRoster` 应按"当前方案的阈值"判定，对不参与判定的格子单独出一个「不计入」名单段，而不是让它们静默消失。
3. 报表正文加一行「说明：本次 48 格为等级值，分数制下不计入名单」，让老师和家长都看得见。

### U-04 复制文案失败后不自动全选，只给一句自救提示

**严重度**：P2（困惑 + 可能漏内容）

**复现步骤**
1. 打开报表弹窗。
2. 注入：`navigator.clipboard.writeText` 抛 `NotAllowedError` **且** `document.execCommand` 返回 `false`（等价于浏览器拒绝剪贴板权限，或非 HTTPS 页面）。
3. 点「📋 复制文案」。

**实测行为**
- toast：`"复制失败，请手动选中复制"`（warn，2.6s 后消失）。
- 弹窗不关、文本仍在 —— **这一点是对的**。
- 但：`[选区/焦点]= {"selText":"","docActive":"BODY","preHasFocus":false}` —— **没有任何自动选中**。
- 老师按提示"手动选中"时，如果只是点一下正文再按 Ctrl+C：`[点正文后选区]= {"len":0}` —— **剪贴板里一个字符都没有**，而界面上没有任何反馈。
- 截图：`U-08-剪贴板双失败.png`、`U-82-复制失败后选区为空.png`
- 代码：`src/components/modals/ReportModal.tsx:16-19` 失败分支只 `showToast('复制失败，请手动选中复制','warn')`；`src/infra/clipboard.ts:15-31` 的 `fallbackCopyText` 用离屏 `textarea` 复制，操作完成后**立刻 `remove()`，把移动过的选区也一并清掉了**。

**用户误解**
"提示说复制失败，让我手动选 —— 我选了啊，Ctrl+C 也按了。" 结果粘到微信里是空的，或者只粘到半句（点到哪算哪）。这时老师通常会怀疑"这软件删了我的东西"。

**建议修法**
1. 失败分支里立刻 `window.getSelection()` 选中 `.report-pre` 全部，`report-pre` 获得焦点，并 toast 改成「已全选，请按 **Ctrl+C** 复制」。
2. 或者更好：失败时**直接把这段文本落到一个可编辑的 textarea 里并 select()**，再给「再试一次 / 下载 txt」两个按钮（下载 txt 已经有现成 `downloadText`）。
3. `fallbackCopyText` 在移除临时 textarea 之前，恢复原选区（`selection.removeAllRanges()` 前先保存）。

### U-05 提示条（toast）2.6 秒必消失，而且会被"7 天备份提醒"抢占

**严重度**：P2（"成功"和"失败"都看不见）

**复现步骤**
1. 打开首页（种入 7 天以上未导出的状态），底部出现备份提醒。
2. 立刻点「清空」→ 确认，或点「复制文案」，或在导出弹窗点「📤 导出 ZIP」。
3. 观察底部提示。

**实测行为**
- 逐帧录制 `.toast` 文本变化（每 40ms 采样）：
  ```
  {"t":"已有一段时间没导出备份了，建议【设置 → 数据 → 导出全部数据】","at":301}
  …
  {"t":"没有可撤销的操作","at":501}
  ```
  —— **先到的 toast 被后到的直接顶替，且不排队**。
- 「清空当前记录」后的 `已清空本条记录，可 Ctrl+Z 恢复` 实测**被备份提醒覆盖到完全看不见**（U-39）。
- 硬编码时长：`src/store/uiSlice.ts:108-113` `toastTimer = setTimeout(() => set({ toast: null }), 2600)` —— **所有 toast 一律 2.6 秒**，包括"复制失败""导出结果"这类需要老师反应的信息。
- 老师的真实动作时序是"点完按钮 → 切到微信窗口 → 粘贴"，**2.6 秒往往正好是她切窗口的时间**。

**用户误解**
"点了导出 ZIP，好像灰了一下，也没弹成功提示，是不是没导出来？" → 于是再点一次，得到两个同名 zip（这一点与数据安全审查的 D-07 同源）。

**建议修法**
1. toast 分级时长：`ok` 2400ms、`warn` 5000ms、`error` **不自动消失**（点击关闭）。
2. 备份提醒这类"背景提醒"降级为顶部横幅或页脚常驻条，不要占用 toast 通道。
3. 所有输出类操作（导出 ZIP、仅明细、仅积分）在 toast 里带上**文件名**与「在下载栏查看」。

### U-07 Ctrl+Z 撤销批量操作后，提示被原操作提示覆盖（实为误报）

**严重度**：P2（误导性强，实测**撤销本身是成功的**）

**复现步骤**
1. 点工具栏「☑️ 全选」→ 显示「☑️ 已选 50 格 · 退出」。
2. 按空格（默认盖章「✅ 已更正」）。
3. 立刻按 `Ctrl+Z`。

**实测行为**
- 第 2 步 toast：`"已对 50 人盖「已更正」"`（`U-85-批量盖章提示.png`）。
- 第 3 步 **撤销成功**（格子角标恢复），但 toast **仍然是** `"已对 50 人盖「已更正」"`（`U-86-批量盖章撤销提示.png`，逐帧取样确认没有再出现新 toast）。
- 代码：`src/store/entrySlice.ts:165-170` `batchStamp()` 在 `writeMany()` **之后**才 `showToast`，于是它覆盖了 `undoSlice.undo()` 里刚弹出的「已撤销：…」；由于 toast 是单例，后到的赢。
- 反向验证（对照）：单格改值后 Ctrl+Z，格子确实回到原值（`U-78-单格改值后撤销.png`），撤销栈空时也有「没有可撤销的操作」（`U-77-撤销栈空时无提示.png`）——**撤销功能本身没问题，只是"撤销成功了"这句话被吃掉了**。

**用户误解**
"我盖了 50 个戳，Ctrl+Z 之后提示还在说'已对 50 人盖戳'，到底撤没撤？" → 老师会再按一次 Ctrl+Z，把撤销又撤回；或者干脆不信撤销，手动一个个改。

**建议修法**
1. 撤销成功的 toast 文案带上前一步的操作名与人数：「已撤销：批量盖章 50 人」。
2. toast 队列化（至少保证"新 toast 出来后，上一条至少完整显示 1 次"），或撤销后**推迟 100ms 再弹**，避免被同一帧的后续 setState 覆盖。

### U-08 撤销栈为空时的提示，来自一个空白页面

**严重度**：P3（瑕疵，但看起来像崩溃）

**复现步骤**

2. 再按一次 Ctrl+Z。

**实测行为**

### U-09 浏览器缩放 125% / 150% 时录入工具栏溢出，保存按钮被挤出视口

**严重度**：P2（"保存"按钮消失，老师以为改完就自动存了）

**复现步骤**
1. 1440×900 视口打开首页。
2. 模拟浏览器 Ctrl+加号：`document.documentElement.style.zoom = 1.25`（再试 1.5）。
3. 观察 `更新修改` 与 `⋯` 两个按钮是否还在视口内。

**实测行为**
- 125%：`scrollW 1491 > clientW 1440`，右侧「⋯」被切掉一半（`U-49-缩放125.png`）。
- 150%：`scrollW 1785`，`⋯` 完全不可见，`更新修改` 只剩一半（`U-49-缩放150.png`）。
- **四个输出按钮（报表生成 / 单条海报 / 当日汇总 / 本周汇总）仍在视口内**（`outBtnVisible` 全部可见）——溢出发生在下方 `.input-bar`。
- 对照：用**真实 viewport** 模拟（1152×720、1280×720、1366×768、1920×1080、800×600）**全部正常、无溢出**（`U-50`/`U-51`/`U-54-*`/`U-52`）。
- 代码：`src/styles/global.css:1567` `.input-bar { flex-wrap: nowrap; }`，`:1575` `@media (max-width: 1200px) { .input-bar { flex-wrap: wrap; } }`；手机端 `:1131-1132` 已经给了 `.input-bar { overflow-x: auto; }`。

**为什么 media query 没生效**：CSS `zoom` 不改变 `window.innerWidth`，`@media (max-width: 1200px)` 永远不触发；而 `nowrap` + 固定 `height: 48px` 又不允许横向滚动 → 溢出到视口外。**Ctrl+加号是 Windows 笔记本上最常见的手势**，这不是理论问题。

**用户误解**
"改完值找不到「更新修改」了，可能已经自动保存了吧？" → 于是把页面关掉，本条登记的修改**没有落到历史**（Ctrl+S 的提示也只活在 2.6 秒 toast 里）。

**建议修法**
1. 把手机端已有的 `.input-bar { overflow-x: auto; }` 提升为通用规则，或改成 `@container` / `clamp()` 布局，不依赖 `@media` 宽度。
2. `更新修改` 与 `⋯` 使用 `position: sticky; right: 0` 固定在工具条右端，任何宽度下都不被裁。
3. 更稳妥：把 `@media (max-width: 1200px)` 的换行阈值改成基于**实际内容宽度**的 `flex-wrap: wrap` 兜底（去掉 `nowrap`）。

### U-12 混合制下数字键默认是"等级"，录入分数要先切

**严重度**：P3（设计权衡，但提示力度不足）

**复现步骤**
1. 方案设为「混合制」。
2. 点某格，直接敲 `9`。

**实测行为**
- 提示：「本表没有该等级键，可按 \` 切到「数字＝分数」再输入」（`U-90-混合制敲9被拒.png`）；再敲 `2` → 落成等级 **A**（不是 92 分）。
- 切到分数后 chip 从「⌨ 数字＝等级」变成「⌨ 数字＝分数」（`U-91-反引号切数字语义.png`），敲 92 正常落值（`U-92-混合制92分落值.png`），报表把 1 号（A）和 3 号（92 分）都放进光荣榜（`U-93-混合制报表.png`）—— 这一条的**光榜口径是对的**（92 分走 `percentOf ≥ 90`）。
- 代码：`src/domain/digitKey.ts:36-45` `resolveDigitMeaning`：`if (schemeAllowsGrade(scheme)) return 'grade'` —— mixed 一律先判等级。

**用户误解**
"我敲了 92，格子显示 A，那 92 分去哪了？"（实测中 9 被拒、2 被当成 A）—— 老师很可能认为系统"把 92 记成了 A"。

**建议修法**
1. 连续数字输入时，若第一位数字**不在等级键位内**（如 9），直接把整串当分数进入缓冲区，而不是逐个按键拒绝。
2. chip 文案从「⌨ 数字＝等级」改成更易懂的「⌨ 当前：按 1–7 打等级（点这里切分数）」。
