## 2. 修复清单逐条对照

### 评审 P2-1：手机端底部固定操作条 ✅

- **改法**：`.output-bar` `sticky` → `fixed`（`bottom:0`，48px 高，z-index 40）；`.app-inner` 补 `padding-bottom` 防遮挡最后一行；`left/right` 用 12px（= `.app` padding）而不是 0——375px 实测 fixed 条宽 375 会把 `.app-inner` 的 scrollWidth 撑爆 1px（352 > 351），这是「贴视口边」与「容器不溢出」的矛盾，取后者。
- **规格回改**（08 §FR-50.3）：口径从「4 个图标 + 文字」修正为「图标 + `aria-label`」；并写明 `sticky` 对文档流上半部元素不可用。
- **暴露的真 UX 问题（顺手修）**：手机端点格子会弹 MobileKeypad（z-60），键盘期间底部操作条被盖住，「录完想立刻出图」点不到。已加让位：键盘打开时操作条滑出（`.app[data-keypad]` + transform 过渡），点键盘【完成】滑回。E2E-40 按真实用户流程补了「先收键盘再出图」步骤。

### 评审 P2-2：night 页面级文字对比度 ✅

- 实测（E2E-37c，WCAG 相对亮度公式，背景取夜渐变最亮端 `#3A2F52` 最严口径）：

  | 元素 | v2.3.0 | v2.3.1 |
  |---|---|---|
  | `.brand-text` 品牌名 | 1.20:1 ❌ | ≥10:1 ✅ |
  | `.field-label` 参数标签 | 1.20:1 ❌ | ≥10:1 ✅ |
  | `.hint` 提示条 | 3.98:1 ❌ | ≥6.8:1 ✅ |
  | `.save-indicator` 保存状态 | 6.65:1 ✅ | 保持 ✅ |

- 变量落在 `tokens.css` 的 night 组（`--text-on-bg: #EDE8F7` / `--text-2-on-bg: #C3BBDA`），应用规则在 `global.css`；**卡片内文字一行未动**（白底天然达标，ADR-24 边界保持）。
- **规格回改**（08）：新增 **FR-48.6-b**——对比度约束同时覆盖压在页面背景上的文字；`night` 必须提供上述两个变量。

## 5. 有意偏差与设计决策（请评审重点看）

1. **键盘期间操作条让位**（规格外补）：MobileKeypad（z-60）会盖住 fixed 操作条，用户「录完立刻出图」的路径被断。选择「模态键盘」心智（同手机输入法）：键盘开→条滑出→【完成】→条滑回。比把 4 个按钮塞进键盘顶部更简单，也不破坏 FR-50.3 的「底部固定条」语义。
2. **fixed 条 `left/right: 12px` 而非 0**：贴视口边会让 fixed 元素宽 375，把 `.app-inner` 的 scrollWidth 撑到 352（实测溢出 1px，E2E-39 红）。让条与内容区左右对齐，宽度恰好 351。视觉上像浮起的面板（上圆角 12px）。
3. **375 下印章缩至 11px**：56px 小格子里 14px 印章与 1-3 位主值包围盒相交（评审 P3-3 实测）。缩章 + 内缩后五对全不相交；**4 位以上长文本（听写类）在主网格窄视口下仍允许与印章贴近**，已记录在案，视觉有 `overflow:hidden` 兜底。
4. **表情空串在 domain 层归一**：CellView 的 `emoji ? …` 是第二道闸，但 domain 先把空串归一为 `undefined`，保证海报/导出/未来任何消费方都拿不到「假值」。
5. **纯白主题的实心语义按钮不变**：报表生成（橙）/ 单条海报（紫）/ 更新修改（绿）是语义色不跟主题走（ADR-24 边界：只换 `--bg-gradient/--brand/--brand-soft` 三组）。用户看到「还有彩色按钮」时，指的是这些语义钮——这是设计而非遗漏。
