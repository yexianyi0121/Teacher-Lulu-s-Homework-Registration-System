# 22 · 需求说明书 · v2.5.7

> 版本：2.5.7
> 起因：老师实机反馈「上方一直有数据为空的提示，我点了清空数据并重来也没有用」
> 定性：**这是三个叠加缺陷造成的真实数据事故**，不是提示文案问题。

## 1. 事故复盘（现场）

老师打开系统后，页面顶部同时出现两条提示：

- 黄条：`⚠️ 检测到数据为空，已阻止覆盖（原数据仍在）。请用【设置 → 数据】导出后再操作。`
- 红条：`⚠️ 检测到内存数据是空的，已阻止覆盖，避免把你的登记数据清掉。请先导出备份，再决定如何处理。`
  按钮：`导出原始数据` / `下载原始数据` / `清空并重来`

点「清空并重来」→ 清空成功 → 页面重新加载 → **提示照旧出现**，永远出不来。

同时还有一个老师没有直接说出来、但更严重的问题：她昨天录的成绩没了。

## 2. 根因（三个缺陷叠加，缺一不可）

### FR-62.1 打开看到的不是今天的表

`fromPersisted()` 取 `updatedAt` 最大的那条记录当当前草稿。

后果：老师昨天录完直接关掉浏览器（没有「结束本表」这个动作），今天打开看到的**还是昨天那张表**，
她以为是新表照录不误 → 今天的成绩全部写进昨天那条记录 → **昨天的数据被覆盖，今天的数据挂错日期**。

这是「昨天成绩没了」的真正原因，也是唯一会造成数据丢失的一条。

### FR-62.2 录入根本没存盘

`exportState()` 只导出 `records`，不含当前草稿 `draft`。
而 `draft` 只有在「切日期 / 切登记类型 / 改作业内容 / 切班级」时才会被固化进 `records`。

后果：老师录了一整天、不切表就关浏览器 → 磁盘上**根本没有今天的数据**。

这条是老师早前第 14 条反馈「关闭浏览器再打开数据全丢」的真正根因（当时的修复只补了草稿的自动保存路径，没有补导出/落盘路径）。

### FR-62.3 覆盖保护把「今天还没录」当成「数据被清空」

`storageHealth.ts` 的 `isEmpty(s)` 判据是 `records.length === 0 && history.length === 0`。

后果链：
1. 全新的老师第一次打开 → 没有记录 → 判空 → **直接只读**；
2. 点「清空并重来」→ 清完还是空 → 再判空 → **永远出不来**；
3. 叠加 FR-62.2：昨天录入没落盘 → 今天打开磁盘上确实只有空 → 判空 → 只读 → 老师以为数据丢了。

覆盖保护本来是防「异常空状态把磁盘数据冲掉」的好东西，但它把**正常的空白天**误判成了异常。

## 3. 修复

### FR-62.1 打开落点

| 磁盘状态 | 打开后显示 |
| --- | --- |
| 今天有记录 | 今天那张（继续录） |
| 今天没有，但库里有别的记录 | **库里最近一条有内容的记录**（让老师看得见自己的数据） |
| 库完全是空的 | 新建今天的空表 |

并保证一条硬不变量：**`draft.key` 必须等于它自己那条记录的 key**，
录入只写 `draft.entries`，因此永远不会串写到别的记录上。

> 为什么不直接「只认今天、否则新建空表」：v1 迁移上来的老数据日期不是今天，
> 老师升级后第一眼看到空表，会以为数据丢了（`persistence.spec.ts` 现场验证过）。

### FR-62.2 草稿进导出

`exportState()` 现在会把当前 `draft`（有内容时）一并并入 `records` 再导出。
效果：录一整天不切表，`localStorage` 与导出文件里都有今天的数据。

### FR-62.3 覆盖保护改判据

新增两个计数：

- `workCount(s)`：`records.length + history.length + points.length`
- `rosterCount(s)`：所有班级的 `students.length` 之和

`shouldBlockOverwrite(next, prevRaw)` 新逻辑：

1. `prevRaw` 为空 → 放行（第一次用）
2. 磁盘解析失败 → 放行（交给迁移/备份逻辑处理）
3. **磁盘上没有成绩（workCount === 0）→ 放行**
4. 仅当 `rosterCount(next) === 0 && 磁盘有成绩` → 拦截

即：**只有当「连班级名单都没了」而「磁盘上有成绩」时才拦**。这正是它该守的那个边界。

### FR-62.4 「清空并重来」真正能出去

`resetAll()` 追加 `setBlockedOverwrite(false)`，清空后不留残余的拦截标志。

## 4. 顺带修的两处（同一批实测发现）

### FR-62.5 Esc 关不掉弹窗

`useInputEngine.ts` 原写法：

```ts
if (e.key !== 'Escape' && e.key !== 'Tab') return;
return;   // ← 放行了 Esc，却什么都没做
```

等于「放行但不处理」，弹窗按 Esc 没反应（E2E-38b 现场）。改为显式关闭确认框或弹窗。

### FR-62.6 「⋯ 更多」浮层被裁掉、看得见点不到

上一版给 `.input-bar` 加了 `overflow-x: auto` 防挤压，结果把向上溢出的浮层整块裁掉。
改为 `position: fixed` 锚点定位 + resize/scroll 跟随，`.input-bar` 补 `z-index: 20`。

## 6. 未做（明确记录）

- FR-62.1 的「打开最近一条记录」并不是完美解：老师隔了几天再录入时，日期仍是旧日期，
  需要她自己改日期或点「新表」。彻底解是「打开时若今天没有内容，用自己的日期自动开新表并给一次性提示」，
  但那会让 v1 迁移场景再次看到空表，留待与「首次使用引导」一起做。
