# 需求说明书 v2.5.3 — Excel 花名册导入（FR-55）

> 上游：`14-需求说明书-v2.5.0.md`（FR-53 入口 App 化）
> 基线：v2.5.2（提交 `d6f6c4d`，tag `v2.5.2`）
> 触发：用户实测把 `7.19名单.xlsx` 导入系统，班级从 55 人变成 66 个乱码姓名并锁死只读。

## 1. 背景与问题

v2.5.2 的花名册导入只认「文本」：`decodeCsv` 把字节按 UTF-8 解码，`parseRosterText` 逐行拆。
而老师从微信收到的名单**绝大多数是 `.xlsx`**（Excel 本质是 ZIP 容器），于是：

- 二进制被当文本解码 → 全是 `PK\u0003\u0004` 之类的乱码；
- `parseRosterText` 逐行全收，`warnings` 为空 → **系统认为导入成功了**；
- 66 个乱码姓名写进班级 → 报表、海报、积分全被污染，且界面看起来"正常"。

**这是本产品最严重的一类缺陷：静默的数据破坏。**

另有两个在修复过程中实测发现的问题：

- 表格首行是大标题（「7年级19班作业情况登记表」）时，**标题被当成学生姓名导入了**；
- 没有表头、只有姓名列时，**第一行数据被丢弃**。

## 2. 目标

| 编号 | 目标 |
| --- | --- |
| G1 | 老师从微信收到的 `.xlsx` 能直接导入，不需要先另存为 CSV |
| G2 | 导入前让她**看见**读到了谁、从哪张表、表头在第几行 |
| G3 | 猜错表结构时，告诉她猜的是什么，而不是默默导错 |
| G4 | 仍然支持「没有 Excel」的场景：复制粘贴文本 |
| G5 | 解析在本地完成，文件不上传 |

## 3. 功能需求

### FR-55.1 文件格式支持

`accept` 限定为 `.xlsx,.xls,.csv,.txt`。

| 输入 | 处理 |
| --- | --- |
| `.xlsx` / `.xls` | SheetJS 解析整个工作簿 |
| `.csv` / `.txt` | 保留原有文本路径（UTF-8 / GBK 探测） |
| ZIP / OLE / 控制字符密集的字节 | 仍走文本路径时由 `looksLikeNonText()` 拦截，给出「另存为 CSV」的提示 |
| 其它扩展名 | 按文本处理 |

**AC-55.1**：一个真实的 55 人 `.xlsx` 导入后，班级人数 = 55，且第 1 格显示「1 王梓淇」这类真实姓名。

### FR-55.2 表结构自动识别

`studentsFromRows(rows)` 必须处理：

1. **表头定位**：在前 10 行里找含「姓名 / 名字 / 学生姓名 / 学号 / 序号 / 编号」等关键词的行；
2. **列定位**：分别定位姓名列与学号列，两者可以不在同一列、不必相邻；
3. **无表头的兜底**：
   - A 列大量是纯数字、B 列是汉字 → 「学号 + 姓名」；
   - 否则取「含汉字最多的一列」当姓名列，并在 `warnings` 里说明；
4. **行过滤**：
   - 「合计 / 小计 / 总计 / 备注 / 说明 / 统计 / 平均 / 班级：/ 共 N 人」→ 跳过；
   - 「××登记表 / ××名单 / ××花名册 / ××情况表 / ××统计表 / ××总表 / ××明细表」→ 跳过（**FR-55.2-b，v2.5.3 修复**）；
5. **学号处理**：从「1」「01」「1.0」「第1号」「0101」里取数字；缺失或重复时按行序重编号并记 warning；
6. **姓名截断**：超过 20 字截断保留，而不是整行丢弃；
7. **上限**：超过 `MAX_STUDENTS`（120）截断并提示。

**AC-55.2**：首行为「7年级19班作业情况登记表」的表格，导入结果是 55 个学生，不含标题行。
**AC-55.2-b**：没有表头、只有一列姓名的表格，第 1 行数据必须被保留（不能当成表头吃掉）。
**AC-55.2-c**：真实文件「7.19名单.xlsx」（第 0 行大标题、第 1 行表头、55 人）必须读出 55 人，且 `headerRow = 2`（1-based）。

### FR-55.3 导入前回显

选择文件后，弹窗必须显示：

1. 绿色成功条：`✅ 已从「{工作表名}」读取到 N 人（表头在第 M 行）`；
2. 前 8 个人名的预览，形如 `预览：1王梓淇、2林子玥、3张蓝予 …`；
3. 解析产生的 `warnings` 全部列出；
4. 主按钮文案为 `导入 N 人`（不是笼统的「导入」）。

**AC-55.3**：上面三项在真实文件上都必须出现，且 N = 55。

### FR-55.4 静态打包（构建约束）

SheetJS **必须静态导入**，不得用 `await import('xlsx')`。

理由：`dist/` 的入口脚本会被 `scripts/inline-dist.mjs` 内联进 HTML，以支持 `file://` 双击运行；而动态 import 产生的 `xlsx-*.js` 是独立 chunk，**不会被内联**，在 `file://` 下必然 404。

**AC-55.4**：`dist/assets/` 下只允许存在一个 `index-*.js`，不存在 `xlsx-*.js`。
**AC-55.4-b**：从 `file:///.../dist/学情登记系统.html` 打开，导入真实 xlsx 必须成功。

### FR-55.5 手册

`src/domain/manual.ts` 新增「导入学生名单」章节（id `roster`），必须包含：

- 支持的格式与三种粘贴写法；
- 「会显示读到了谁、哪张表、表头第几行」；
- 多工作表时读第一张的说明；
- 「导入只替换姓名，不影响已有成绩」的承诺。

**AC-55.5**：手册共 20 章，`roster` 章节存在且至少 2 条步骤。

## 4. 非功能需求

- **NFR-55.1** 解析必须纯本地，零网络请求。
- **NFR-55.2** 构建产物体积允许增加（xlsx 约 430KB 未压缩、100KB 级 gzip），因为产品要求可离线双击运行。
- **NFR-55.3** 解析失败必须给出**人话**错误（「读取 Excel 失败：…；可以试试在 Excel 里『另存为 CSV』再导入」），不得抛出原始异常。

## 6. 不做

- 不支持 `.et`（WPS 专有，需老师另存为 xlsx）；
- 不支持从 Excel 里**读成绩**（本版本只导名单，成绩仍靠录入或历史回放）；
- 不解析合并单元格的语义（合并区域按左上角值处理）。
