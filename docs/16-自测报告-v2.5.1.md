# 自测报告 v2.5.1 —— 启动器 URL 修复（评审 P2-1）

> 日期：2026-10-25 ｜ 来源：评审报告 v2.5.0 ｜ 结论：**已修复并全量回归绿**

## 1. 缺陷

`dist/启动学情登记系统.cmd` 生成的 `--app` URL 里带着**反斜杠**：

```
file:///D:/.../dist%5C%E5%AD%A6%E6%83%85%E7%99%BB%E8%AE%B0%E7%B3%BB%E7%BB%9F.html
                ^^^^^ %5C = 反斜杠
```

浏览器把它还原成 `dist\学情登记系统.html`，`dist` 被当成**文件名**、入口被当成**目录**，
实测 `net::ERR_INVALID_URL`、DOM 0 字节、0 个格子 —— **`--app` 窗口根本到不了应用页面**。
FR-53.3「双击后无边框打开」在 v2.5.0 实际是失效的。

## 2. 根因

启动器里这一行：

```bat
for /f "delims=" %%u in ('powershell ... "[uri]::EscapeUriString('%CD:\=/%\%APP_HTML%')"') do ...
```

`%CD:\=/%` 想表达「把 `%CD%` 里的反斜杠换成斜杠」。但 cmd 的变量子串替换
`%VAR:旧=新%` 在**无引号上下文**中**不会执行替换**——替换语法必须以引号收尾才算数，
这里 `…=%\` 后面不是引号，于是 cmd 解析成对变量 `CD:\=` 的取值，整体退化为字面量旁路，
**反斜杠原样保留**进入 URL。

自测报告 v2.5.0 §4 记录的人工验证（`FINAL_FORM_OK`）用的是**另手构造的正确 URL**，
不是启动器本身产出的 URL，所以没暴露。

## 3. 修复

`scripts/postbuild-app.mjs` 的 `launcherLines`：

1. **路径不再取自 `%CD%`**。整段路径在 PowerShell 内用 `(Get-Location).Path` 取，
   显式 `.Replace([char]92,'/')` 把反斜杠换成斜杠；文件名经**环境变量** `$env:APP_HTML`
   回传（中文经 ANSI 代码页往返会变形，走环境变量可规避）。
2. **Edge/Chrome 直接探测安装目录**（`%ProgramFiles(x86)%` → `%ProgramFiles%` →
   `%LocalAppData%`），不再只靠 `where msedge`——两台浏览器的安装目录默认**不在 PATH**，
   原逻辑因而永远落到最后一行「默认浏览器」，退化成带地址栏的普通窗口。
3. 入口选取加 `if not defined APP_HTML` 守卫，避免被 `index.html` 镜像覆盖；
   cmd 侧保持**全 ASCII**（中文文件名不硬写，仍由通配枚举）。

## 4. 守护测试（补上原来漏网的断言）

`tests/unit/app-entry.test.ts` 由 4 例增至 **7 例**，新增：

- **P2-1 回归**：拼 URL 的那一行不得出现 `%5C` 或裸反斜杠；不得再出现 `%CD:\=/%`；
  必须含 `[char]92` 与 `(Get-Location).Path`；
- 启动器必须直探 `Microsoft\Edge\Application\msedge.exe` 与 `Google\Chrome\Application\chrome.exe`；
- 启动器不得把中文入口名硬写进 cmd（守护全 ASCII），且必须显式排除 `index.html`。

原断言只查了「文本里出现 `EscapeUriString` 字样」，没查「路径分隔符是 `/`」——这是漏网原因。
