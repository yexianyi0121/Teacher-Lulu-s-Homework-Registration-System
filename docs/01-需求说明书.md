## 0. 阅读指南

### 0.1 术语表

| 术语 | 定义 |
|---|---|
| 学号 | 学生在班级内的序号，1 起始的整数。本产品**默认只显示学号不显示姓名**（隐私考量），姓名为可选字段 |
| 录入格 / 单元格 | 主界面网格中代表一个学生的一次登记位置 |
| 秒跳 | 提交一个单元格的录入值后，焦点自动跳到下一个单元格的开关 |
| 盖章 | 给单元格附加一个状态标记：已更正 / 优秀。与录入值相互独立、可叠加 |
| 记录（Session） | 一次登记行为的数据集合 = 班级 + 模式 + 日期 + 作业内容 + 全部单元格值 |
| 历史记录 | 被显式「更新修改」提交后固化下来的记录快照，用于趋势与对比 |
| 模式 | 三种录入口径：常规作业 / 单元测试 / 听写默写 |
| 光荣榜 | 报表与统计中「表现优异」的学生集合，判定口径随模式变化（见 §6.1） |
| 需更正 | 需要订正的学生集合，判定口径随模式变化（见 §6.1） |
| 未提交 / 暂未提交 | **同一概念的两种叫法，完全等价**：统计条字段叫「未提交」，报表名单叫「暂未提交」，二者数值相等（= `N − 录入人数`，定义见 §6.6）。代码里统一命名为 `missing` |

## 1. 产品概述

### 1.1 一句话定位

**一款面向初中语文教师的、在浏览器里本地运行的「作业/测验成绩极速登记 + 一键出图出文案」单页工具。** 老师批完作业后，只需键盘盲打即可完成整班登记，再点两下就能拿到可直接发微信群的海报图片和格式化文案。

> **本版本为刘露老师（初中语文）定制**：默认教师名「刘露」、学科「语文」、班级人数 50、单元测试 100 分制；海报页脚与报表署名默认使用该信息（可在设置中改）。

### 1.2 背景：被点名的四个痛点

来自原笔记的作者自述，这四条是本产品的**需求原点**，任何功能取舍都要回到它们：

| 编号 | 痛点原话 | 本质问题 |
|---|---|---|
| P-1 | 「批作业总是对着名单找学号找到眼花」 | **录入效率**：鼠标点击定位太慢，需要纯键盘流 |
| P-2 | 「算平均分、优秀率按计算器按到手抽筋」 | **统计自动化**：录完即出结果，零手工计算 |
| P-3 | 「发家长群的反馈截图总是又乱又丑」 | **对外呈现**：需要干净的、有署名的成图/成文 |
| P-4 | 「催交作业、查谁没订正又要核对半天名单」 | **名单归纳**：按规定口径自动分拣出光荣榜/未交/需更正三个名单 |

> 设计启示：**录入路径必须可以完全不碰鼠标**；**统计必须是派生的，不能靠老师二次填写**；**对外产物必须是「一键可复制」的**。

### 1.3 产品目标（可度量）

| 目标 | 度量方式 |
|---|---|
| G-1 录入极快 | 50 人班级、全键盘操作、完成一次常规作业等级录入 ≤ 90 秒（≥ 33 人/分钟） |
| G-2 零手工统计 | 任意时刻统计条与图表与当前网格数据的偏差为 0（由自动化测试保证） |
| G-3 一键对外 | 从数据完成到「文案已进剪贴板 + 海报已进剪贴板」≤ 3 次点击 |
| G-4 数据不出本机 | 运行期除加载自身静态资源外，**不发起任何网络请求**（可用 DevTools Network 面板验证）。**唯一例外**：用户**主动**点击【🎤语音】时浏览器原生语音识别产生的厂商请求；**未点语音时 Network 必须为 0 请求** |
| G-5 断电不丢 | 浏览器异常关闭 / 刷新后重开，最近一次修改不丢失（≤ 1 条录入的损失） |

### 1.4 非目标（本版本明确不做）

| 不做的事 | 原因 |
|---|---|
| 长期成绩档案 / 学期成绩单 / 教务系统对接 | 那是另一个产品，会把定位从「轻工具」拖成「管理系统」 |
| 家长端、学生端、家长扫码查看 | 涉及未成年个人信息对外传输，合规成本极高 |
| 账号体系、云同步、多设备漫游 | v1 用本地存储即可满足单机场景；联网即引入隐私与运维成本 |
| AI 自动批改 / OCR 识别作业本 | 不在本次范围，且会显著拉高复杂度 |
| 多用户协作 / 多人同时录入 | 单机单用户产品 |
| **120 分制 / 150 分制试卷** | 已与用户确认：**本版本只做 100 分制**（优秀线 90、及格线 60）。成绩 > 100 应拒绝录入（见 FR-05 校验），不做满分切换 |

### 1.5 目标用户

**主用户：刘露老师——初中语文教师（本系统的唯一真实用户）**

| 维度 | 描述 |
|---|---|
| 身份 | 初中语文教师，班主任；教 1–2 个班，每班 45–50 人 |
| 年龄 | 25–45 岁 |
| 设备 | Windows 办公电脑（Chrome/Edge，1366×768 起）为主；iPad + 蓝牙键盘为次 |
| 数字能力 | 会用 Excel、会发微信群、会截图；**不会也不想学复杂软件** |
| 时间压力 | 批完作业常在下班前 30 分钟内，需要「快」 |
| 审美偏好 | 偏爱浅色、圆角、可爱风（原笔记称之为「治愈系」） |
| 社交渠道 | 微信群（家长群 / 教研群）是唯一发布出口 |
| 典型作业 | **字词听写 / 古诗文默写**（→ 听写默写模式）・**抄写、作文、周记、练习册**（→ 常规作业模式，A+/A/A-）・**单元测试、月考**（→ 单元测试模式，100 分制） |

**次用户：课后托管老师、培训机构老师**——同样需要按学号登记与出反馈，班级规模更小。

### 1.6 核心用户旅程（Happy Path）

```
T-1  批改完 50 本作业，坐到电脑前
 └─ 打开工具（浏览器书签 / 本地 HTML 文件）
T-2  选择「常规作业」模式，确认日期，输入作业内容（如「语文本」）
T-3  手指放在数字键上，按学号顺序盲打：1→A+，2→A，3→A- ...
     开「秒跳」后每敲一个键自动跳下一格，全程不看鼠标
T-4  手边那叠「订正过的本子」逐个按空格盖上「已更正」章
T-5  点【报表生成】→ 弹窗里三段名单已排好 → 点【复制】→ 微信粘贴发送
T-6  点【截图发群】→ 生成一张干净的粉色海报 → 点【复制图片】→ 微信粘贴发送
T-7  关掉页面。数据已自动保存；下次打开可点【更新修改】把这次固化成历史记录
```

**关键旅程的量化约束**：T-3 的每一次「定位 → 赋分 → 前进」必须 **≤ 1 个按键 + 0 次鼠标移动**。

### FR-01 单页主界面与视觉体系 — P0

**目的**：承载全部录入操作的唯一页面，必须在 1366×768 上一屏放下「头部 + 工具栏 + 网格」。

**触发与前置**：打开应用即进入，无需登录、无需引导页（首次访问可有一次 3 步蒙层引导，可跳过）。

**交互细则**：
1. 页面为**单页**，不跳转路由。所有浮层（设置、报表、海报预览）以 Modal 形式覆盖。
2. 页面结构自上而下四区：**头部栏（Header）→ 参数行（Params）→ 操作行（Actions）→ 网格区（Grid）**，见 §4.2。
3. 头部左侧为品牌标识「🌸 学情登记分析系统」；右侧依次为【⚡秒跳】胶囊、【🔍搜学号】胶囊、**📁 圆形图标钮（导入花名册）**、**⚙️ 圆形图标钮（设置）**（与参考截图一致，后两个为纯图标圆钮，必须带 `title`）。
4. 参数行：模式选择、日期、作业内容 三个控件。
5. 操作行：语音、盖章、全选、报表生成、截图发群、清空、更新修改 七个按钮。
6. **提示条位于网格区上方**（参考截图中就在网格之上），与网格间距 `8px`，展示当前模式的快捷键说明（内容随模式变化，见 §4.6.4）。

**规则**：
- BR-01 界面语言固定为简体中文，不提供多语言。
- BR-02 所有按钮必须同时具备「图标 + 中文文字」，不允许纯图标按钮（除次要的圆形图标按钮需带 `title` 提示）。

**边界与异常**：
- 浏览器窗口宽度 < 1024px 时，网格列数自适应为 8 / 6 / 4 列（见 §4.8），但功能不减。
- 无任何数据时，网格仍渲染全部空单元格（不显示空白页），统计条显示 0 / —。

**验收标准**：
- `AC-01.1` Given 首次打开且本地无数据 When 页面加载完成 Then 显示 50 个空单元格、统计条 `录入人数 0`、平均分显示 `—`。
- `AC-01.2` Given 1366×768 视口且为**常规作业模式（无统计条、无图表）** When 页面渲染 Then 头部 64 + 间距 16 + 参数行 56 + 间距 16 + 操作行 52 + 间距 8 + 提示条 32 + 间距 8 + 网格 5 行（容量上限 412）全部**无需滚动可见**（总需求 ≤ 768，见 §4.2 高度预算表）。
- `AC-01.2b` Given 单元测试模式 When 页面渲染 Then 统计条（72px）可见且网格区至少可见 **4 行**；数据分析卡片默认展开时允许纵向滚动。
- `AC-01.3` Given 任意页面状态 When 刷新浏览器 Then 页面状态与刷新前一致（依托 FR-10）。

### FR-02 班级与花名册 — P0（多班级为 P2）

**目的**：定义「这一班有几个人、学号怎么排」，是所有登记的容器。

**触发与前置**：首次进入自动创建默认班级。

**交互细则**：
1. 首次进入（无任何本地数据）时，自动创建：
   - 班级名：`我的班级`
   - 学校名：空
   - 教师名：`刘露`（本版本默认值，可在设置中改）
   - 学科：`语文`
   - 学号范围：`1 ~ 50`
2. 【⚙️设置】浮层中可修改：班级名、学校名、教师名、学科、学生人数（1–120 整数）。
3. 支持两种花名册形态：
   - **仅学号**（默认）：学号 `1..N`，界面不显示姓名。
   - **含姓名**（P1）：每条记录为 `学号 + 姓名`，姓名默认**不展示**，可在设置中开启「显示姓名」后以小字显示在学号旁。
4. **花名册导入（P1）**：
   - 方式 A：粘贴文本。每行一条，支持 `1 张三`、`1,张三`、`1、张三`、`张三`（纯姓名则按行序自动编号）。
   - 方式 B：上传 CSV（UTF-8 / GBK 自动探测，首行若含「学号」「姓名」等表头则跳过）。
   - 导入后若人数与现有数据不符：**新增学号补空单元格，多余学号的数据保留在内存但不在网格展示，并在导入结果提示中告知「有 N 条历史数据超出当前人数，已隐藏」**。
5. 人数调整（`N` 变小）：超出 `N` 的单元格数据**不删除**，仅隐藏；人数调回后数据恢复。此规则必须实现，防止误操作丢数据。

**规则**：
- BR-03 学号唯一、从 1 连续递增，不允许跳号与重号。
- BR-04 姓名是**可选敏感字段**：默认不显示、不代入海报、不代入报表文案；仅在用户显式开启「显示姓名」后才展示，且展示为「12 张三」，报表仍只输出「12号」。

**边界与异常**：
- 人数输入非法（0、负数、小数、>120）→ 输入框标红并提示「请输入 1–120 的整数」，不提交。
- 导入文件解析失败 → 提示「文件解析失败，请检查是否为 CSV 或纯文本」，已有数据不受影响。

**验收标准**：
- `AC-02.1` Given 全新环境 When 打开 Then 存在班级「我的班级」、50 个学号、学科「语文」。
- `AC-02.2` Given 50 人且有数据 When 把人数改为 40 Then 网格只剩 40 格，41–50 号的已录值不丢失。
- `AC-02.3` Given 40 人状态 When 把人数改回 50 Then 41–50 号原值原样恢复。
- `AC-02.4` Given 粘贴 5 行「1 张三…5 李四」When 确认导入 Then 5 个学号与姓名建立，网格显示 5 格。
- `AC-02.5` Given 关闭「显示姓名」 When 查看任意单元格 Then 只显示学号，不出现姓名。

### FR-03 三种录入模式 — P0

**目的**：一个页面覆盖老师日常最常做的三种登记口径。

**触发与前置**：参数行的模式下拉框切换。

**交互细则**：

#### A. 常规作业（homework）
- 等级集合：`A+`、`A`、`A-`、`√`（已交/完成）、`×`（未提交）。
- 键盘映射：`1→A+`、`2→A`、`3→A-`、`4→×`、`5→√`。
- 单元格展示：居中的等级文字（`A+` 字号最大），左上角浅灰学号，右下角盖章角标（若已盖章）。
- 语义：`A+`=优秀（进光荣榜）、`A`=良好（无特殊归类）、`A-`=需更正、`×`=未提交、`√`=已交但未评级（不计入光荣榜与需更正）。

#### B. 单元测试（quiz）
- 值域：`0 ~ 100` 的数值，**最多 1 位小数**（如 `90.5`）。
- 键盘输入：直接敲数字与小键盘小数点，累积成串（如 `8` `7` `.` `5` → `87.5`）；退格删除末位。
- 单元格展示：居中分数（整数不显示小数点，`90` 不显示为 `90.0`）；按分段着色（见 §4.5.2）。
- 超范围处理：> 100 时截断为 100 并轻微抖动提示；输入 `.` 开头按 `0.` 处理。
- 统计区展示完整的六宫格统计条与图表（见 FR-06 / FR-07）。

#### C. 听写默写（dictation）
- 值域：**自由文本**，建议格式 `错2`、`全对`、`缺交`。
- 键盘输入：首个可打印字符触发内联编辑框（浮在单元格上的 input），Enter 提交，Esc 取消。
- 解析规则（BR-05）：
  - 命中 `/^错\s*(\d+)/` → 错误数 = N；`N=0` 视为全对。
  - 命中 `全对` / `√` / `100` / `错0` → 全对。
  - 命中 `缺交` / `未交` / `×` / `无` → 未提交。
  - 其他文本 → 归为「其他」状态：不计入任何名单，**计入录入人数**（统计条第 6 字段「其他」计数，见 §6.1.2）。
- 单元格展示：居中显示原文（字号随长度自适应，2 字大字、3 字中字、≥4 字小字）。

**规则**：
- BR-06 切换模式时，**当前记录不做数据迁移**，但**同一会话内各模式的值独立保存**：即同一日期+作业内容下，切换模式后在 A 模式录的值在切回时仍在。为此，记录以 `(日期, 作业内容, 模式)` 三元组为键组织（见设计说明书 §4）。
- BR-07 模式切换必须即时改变：网格配色规则、单元格输入方式、统计条字段、图表与报表口径、底部提示条文案。

**边界与异常**：
- 常规作业模式下按 `6`~`0`：无响应（不报错）。
- 单元测试模式下输入第二个小数点：忽略。
- 听写默写模式下粘贴超长文本（> 20 字符）：截断并提示。
- 任何模式下空单元格按 Enter：不产生值，直接跳下一格。

**验收标准**：
- `AC-03.1` Given 常规作业模式 When 对 1 号按 `1` Then 1 号显示 `A+` 且背景为绿系。
- `AC-03.2` Given 单元测试模式 When 对 1 号依次按 `9` `0` `.` `5` 再 Enter Then 1 号显示 `90.5`。
- `AC-03.3` Given 单元测试模式 When 输入 `1000` Then 值被截断为 `100`。
- `AC-03.4` Given 听写默写模式 When 在 3 号输入 `错2` Then 3 号显示 `错2` 且背景为黄系。
- `AC-03.5` Given 模式 A 录了 10 个学号 When 切到模式 B 再切回 A Then 10 个学号的值仍在。

### FR-04 键盘极速录入引擎 — P0

**目的**：这是产品的**灵魂功能**，决定「爽不爽」。目标是老师手不离键盘、眼不离作业本。

**触发与前置**：网格区任意单元格处于聚焦态。

**交互细则**：

1. **焦点模型**：任一时刻恰好有 ≤ 1 个单元格处于「焦点态」。焦点态用 `2px solid #4A90E2 + 外发光环` 表示，且页面**自动滚动**使其完整可见。
2. **秒跳（Auto-Advance）开关**【⚡秒跳】：
   - 开启（默认）：一次录入**提交**后，焦点自动移到 `学号 + 1` 的单元格；已是最后一个则停在末尾并给出「已完成最后一格」的轻提示。
   - **「提交」由模式决定，这是本需求最易实现错的一处，务必逐条对齐**：
     - **常规作业**：按 `1`–`5` 即完成一次录入 → **立即提交并前进**（一键一格，这是产品的核心手感）。
     - **听写默写**：内联框内按 `Enter` 提交并前进。
     - **单元测试**：数字键只往缓冲区累积（`8` `7` `.` `5` 拼成 `87.5`），**必须按 `Enter` 才提交并前进**；若数字键直接跳格，`87.5` 永远输不完。
   - 关闭：提交后焦点不动，单元格做一次 120ms 的「确认脉冲」动画。
   - 开关状态持久化到本地。
3. **学号极速定位**：按 `/` → 焦点跳到头部搜索框「搜学号」→ 输入数字 → 实时过滤/高亮匹配项 → Enter 跳转到该学号单元格并聚焦（搜索框清空）。Esc 退出。
   - 允许模糊：输入 `1` 时列出 `1,10,11,...19`，按 `Tab` 在候选中循环，Enter 取当前高亮候选。
4. **方向键导航**：`←→↑↓` 在网格中按行列移动；网格边界处不循环。
5. **Tab**：等同 `→`；`Shift+Tab` 等同 `←`。
6. **提交键**：`Enter`。
7. **清空**：`Delete` / `Backspace` 清空当前单元格的值（盖章也一并清除），并**记入撤销栈**。
8. **全选**【✨全选】：一键把**所有已录入值或已盖章的单元格**置为多选态，此后一次操作（盖章 / 清空）作用于全部选中项。再次点击取消。空单元格**不入选**。**多选态的完整行为（禁用哪些键、焦点环画不画、批量操作后停在哪）见 §4.6.5 状态矩阵，必须照表实现。**
9. **防误触**：当焦点在「作业内容」输入框或搜索框或任一 Modal 的 input 内时，以上网格快捷键**全部不生效**。

**规则**：
- BR-08 键位分两级，**必须按此实现**（两级混用会导致 Modal 内快捷键全部失效）：
  - **导航键**（`1`–`5`、`←→↑↓`、`Tab`、`空格`、`Delete`/`Backspace`、数字/小数点）：监听挂在**网格容器**的 `onKeyDown` 上，天然不会污染输入框。
  - **命令键**（`/`、`Esc`、`Ctrl+Z`、`Ctrl+Y`、`Ctrl+S`、`Ctrl+M`、`Ctrl+Enter`）：挂在**`document`** 级别，但入口必须先经 `isEditableTarget(e.target)` 白名单过滤——目标为 `input`/`textarea`/`contenteditable` 时**只放行** `Esc`、`Ctrl+Z`、`Ctrl+S`、`Ctrl+Enter`；`Ctrl+S` 必须 `preventDefault()` 阻止浏览器「另存为」。
- BR-09 必须兼容**中文输入法**：处于 composition 状态时（`isComposing === true`）忽略所有快捷键；听写默写的内联输入框必须正确处理 `onCompositionStart/End`，防止中文输入被打断。
- BR-10 一次录入（值变更 + 盖章）记一条撤销记录，撤销栈深度 50。

**边界与异常**：
- 网格为空（人数 0）时，`/` 与方向键无响应。
- 焦点所在单元格因人数调整被隐藏 → 焦点自动回到 1 号。
- 秒跳连按过快（> 20 次/秒）：做输入节流，保证不丢值。

**验收标准**：
- `AC-04.1` Given 常规作业、秒跳开 When 焦点在 1 号按 `1` Then 1 号为 `A+` 且焦点在 2 号。
- `AC-04.2` Given 秒跳关 When 焦点在 1 号按 `1` Then 1 号为 `A+` 且焦点仍在 1 号。
- `AC-04.3` Given 任意状态 When 按 `/` Then 焦点进入搜学号框；输入 `37` 后按 Enter Then 37 号单元格获得焦点。
- `AC-04.4` Given 焦点在 50 号 When 按 Enter（秒跳开）Then 焦点停在 50 号且出现「已完成最后一格」提示。
- `AC-04.5` Given 焦点在作业内容输入框 When 按 `1` Then 输入框内出现字符 `1`，网格 1 号**不发生**任何变化。
- `AC-04.6` Given 使用微软拼音输入法 When 在听写默写格输入「错」 Then 输入法候选框正常，`Enter` 用于上屏候选时**不触发**提交。
- `AC-04.7` Given 任意状态 When 按 Ctrl+Z Then 上一次录入被撤销且焦点与滚动位置回到该单元格。

### FR-05 盖章（已更正 / 优秀） — P0

**目的**：把「谁还没订正」这件事从翻本子变成扫一眼屏幕。

**触发与前置**：单元格聚焦态，按 `空格`；或点击【⭐盖章 ▼】下拉选择章型后再按空格。

**交互细则**：
1. 两种章型：
   - `✅ 已更正`（corrected）——默认章型，角标为绿色圆角底 + 白色对勾。
   - `⭐ 优秀`（excellent）——角标为金色星标。
2. 空格行为（当前聚焦单元格）：
   - 无章 → 盖上「当前选中的章型」；
   - 已有**同种**章 → 取消（toggle off）；
   - 已有**另一种**章 → 替换为新章型。
3. 【⭐盖章 ▼】下拉：切换「当前章型」，只影响后续盖章，不批量作用于已有格子。
4. **全选后盖章**：若处于全选态，一次空格对**所有选中且已有录入值**的单元格批量盖当前章；再按一次批量取消。
5. 角标位置：单元格右下角，尺寸 16×16，不遮挡等级/分数文字。
6. 盖章**不改变**单元格的底色与边框（底色只由录入值决定），只叠加角标。

**规则**：
- BR-11 盖章是独立维度，与值正交。清除值（Delete）时章一并清除。
- BR-12 盖章**会改变报表名单归类**（以 §6.6 为准）：盖章不改变四档归属，但「需更正」名单只收**未盖「已更正」章**的未达线学号；已盖的不及格格进入报表的可选第四段「✅【已更正】」。盖章同时影响屏幕与海报的视觉标记。

**边界与异常**：
- 空单元格盖章：允许（用于标记「口头已订正但本子没交」），但该格仍计入「暂未提交」名单——需在提示中说明。**决策：空单元格盖章时自动弹一次轻提示「该学号尚无录入值，仍会出现在未提交名单中」**。
- 全选态下按空格且选中集合为空：无响应。

**验收标准**：
- `AC-05.1` Given 3 号有值 `A-` When 聚焦 3 号按空格 Then 3 号右下角出现绿色对勾角标。
- `AC-05.2` Given 3 号已有「已更正」章 When 再按空格 Then 角标消失。
- `AC-05.3` Given 当前章型切换为「优秀」 When 对 4 号按空格 Then 4 号显示金色星标（原「已更正」被替换）。
- `AC-05.4` Given 全选态、10 格有值 When 按空格 Then 10 格全部盖当前章，统计条「已更正」计数同步 +10。
- `AC-05.5` Given 3 号有值且有章 When 按 Delete Then 值与章同时清除。

### FR-06 实时统计 — P0

**目的**：消灭计算器（对应痛点 P-2）。

**触发与前置**：任意值变更后 ≤ 50ms 内刷新，无需手动触发。

**交互细则**：
1. **统计条**位于网格区上方，一行等宽排列若干指标，每项为「标签 + 数值」两行，数值大字加粗且按语义着色。
2. **统计条只在【单元测试】模式渲染**（与参考截图 1 一致：常规作业页没有统计条）。常规 / 听写不占这块版面，以保证 1366×768 下首屏放得下 5 行网格（§4.2 高度预算）。三模式的统计量照常计算，只是后两者的计数通过【报表】的名单段体现：

| 模式 | 统计条 | 计算字段（口径见 §6.1） |
|---|---|---|
| 单元测试 | ✅ 渲染 | 录入人数 / 平均分 / 优秀(`{优秀线}+`) / 良好(80+) / 及格(`{及格线}+`) / 不及格 |
| 常规作业 | ❌ 不渲染 | 录入人数 / A+ / A / A- / √ / 未提交 / 已更正（供报表与海报派生） |
| 听写默写 | ❌ 不渲染 | 录入人数 / 全对 / 有错 / 其他 / 未提交 / 已更正 |

3. 数值格式化：
   - 人数：整数。
   - 平均分：保留 1 位小数（`87.7`）；录入人数为 0 时显示 `—`。
   - 百分比（若展示）：保留 1 位小数 + `%`。
4. 统计条外框为**圆角虚线边框**（参考截图），整体浅底。

**规则**：
- BR-13 统计全部由当前记录**派生计算**，不存储、不缓存跨会话。任何值变更必须让统计条与图表同步更新（同一帧内）。
- BR-14 「录入人数」= 当前模式下**有有效值**的单元格数；`×` 与「缺交」不计入录入人数。
- BR-15 已更正计数 = 有 `corrected` 章的人数。

**边界与异常**：
- 全班 0 人录入：平均分 `—`，其余 0。
- 有极小值（0 分）：正常计入平均分与不及格。

**验收标准**：
- `AC-06.1` Given 单元测试模式录入 §7.1 的 20 条数据 When 查看统计条 Then 显示 `20 / 87.7 / 13 / 3 / 3 / 1`（逐字一致）。
- `AC-06.2` Given 上述状态 When 把 17 号改为 90 Then 平均分与各分段计数在 50ms 内更新，且 17 号从「不及格」移入「优秀」。
- `AC-06.3` Given 无数据 When 查看统计条 Then 平均分为 `—`。
- `AC-06.4` Given 切到常规作业或听写默写模式 Then **页面上不出现统计条**，且 1366×768 下网格 5 行全部可见。
- `AC-06.5` Given 优秀线改为 85 When 查看统计条 Then 标签显示为 `优秀(85+)` 且各段计数按新阈值重算。

### FR-09 海报生成与复制 — P0

**目的**：生成一张干净的、带署名的图，直接发家长群（对应痛点 P-3）。

**触发与前置**：点击【📋截图发群】。

**交互细则**：
1. 点击后**不截取当前屏幕**，而是渲染一张**专用的海报 DOM**（隔离于编辑态 UI）再转成 PNG。这样保证：
   - 不出现工具栏、按钮、焦点环、选中态；
   - 分辨率可控（2× 或 3×）；
   - 网格可跨越多屏完整输出（长图）。
2. 海报内容与版式见 §6.3。
3. 生成流程：点击 → 按钮进入 loading（≤ 1.5s）→ 弹出「海报预览」Modal，展示图片缩略图 + 操作按钮：
   - 【复制图片】（写入剪贴板 `image/png`）
   - 【下载 PNG】
   - 【重新生成】（数据改动后）
   - 【关闭】
4. 复制图片使用 `ClipboardItem`，需在用户手势内调用；不支持时（Safari 旧版）自动隐藏「复制图片」并只保留下载。
5. 海报视觉：背景粉色渐变 + 白色圆角卡片，**不出现**焦点环、选中态、鼠标悬停态、工具栏。视觉一律以 §6.3 版式与 §4.4 令牌值为准，**不得使用任何主观形容词作为验收依据**（见 AC-09.4）。

**规则**：
- BR-21 海报必须包含页脚署名 `© Designed by {教师名} | {学校名}`；教师名或学校名为空时，显示 `© Designed by 一位老师`（两者都空）或只显示已有的一个。

- BR-23 海报网格列数固定 10 列，行数 = `ceil(人数/10)`，随人数自动增行（长图）。
- BR-24 海报**不显示**姓名，不显示分数/等级的统计信息（只显示网格），标题使用学科名。

**边界与异常**：
- 人数 100 人 → 海报高度约 2.4 倍，仍单张输出。
- 网络字体未加载 → 必须使用系统字体栈，禁止依赖远程字体（离线可用）。
- 生成失败（canvas 污染/内存溢出）→ Toast「海报生成失败，请重试」，不崩溃。

**验收标准**：
- `AC-09.1` Given 50 人有数据 When 点【截图发群】Then 1.5s 内出现海报预览，图中**不含**任何按钮、搜索框、焦点描边。

### FR-10 持久化与自动保存 — P0

**目的**：对应「断电防丢的毫秒级自动保存」。

**触发与前置**：任何会改变数据状态的操作。

**交互细则**：
1. 自动保存：值/章/参数变更后 **300ms 防抖**写入 `localStorage`；并在 `visibilitychange`（页面隐藏）与 `beforeunload` 时**同步强制落盘**。
2. 备份：每 30 秒额外写入一份带时间戳的快照到 `IndexedDB`（保留最近 5 份）。
3. 加载：启动时比较 localStorage 主数据与最近快照的 `updatedAt`，取较新者；若主数据解析失败（损坏），自动回退到最近快照并用 Toast 告知「已从备份恢复」。
4. 数据管理（在设置里）：
   - 【导出备份】下载 `学情登记-{yyyyMMdd-HHmm}.json`（全量状态）。
   - 【导入备份】选择 JSON 文件恢复（需二次确认，覆盖当前）。
   - 【清空全部数据】二次确认（输入「清空」二字方可执行）。
5. 顶部或底部显示极轻量的保存状态指示（如 `已自动保存 12:04`），不抢视觉焦点。

**规则**：
- BR-25 存储 schema 必须带 `version` 字段，加载时做迁移（见设计说明书 §4.3）。
- BR-26 存储失败（隐私模式 / 配额满）→ 顶部黄色警告条「浏览器存储不可用，刷新后数据会丢失，建议先导出备份」，**不阻断录入**。

**边界与异常**：
- 多标签页同时打开：后写入覆盖前写入，需监听 `storage` 事件并提示「另一个标签页修改了数据，点击刷新以载入」。
- 数据量（120 人 × 30 次历史）≤ 2MB，localStorage 5MB 上限内。

**验收标准**：
- `AC-10.1` Given 录入 3 个值 When **每条录入后间隔 ≥ 500ms**（超出 300ms 防抖窗口）再强制关闭浏览器并重开 Then 3 个值仍在。*（注：强杀进程不触发 `beforeunload`，防抖窗口内最多丢 1 条，与 NFR-09 容差一致）*
- `AC-10.2` Given 录入中 When 按 F5 刷新 Then 数据完整。
- `AC-10.3` Given 有数据 When 导出备份再清空全部 When 导入刚导出的 JSON Then 数据完全恢复。
- `AC-10.4` Given 手工把 localStorage 主数据改成非法字符串 When 刷新 Then 从快照恢复且出现提示，页面不白屏。

### FR-12 语音录入 — P1

**目的**：对应原笔记「语音呼叫：『12号优秀』『5号已更正』」，用于老师手上拿着本子、不方便打字的场景。

**触发与前置**：点击【🎤语音】按钮（或 `Ctrl+M`）。

**交互细则**：
1. 使用浏览器 `Web Speech API`（`SpeechRecognition` / `webkitSpeechRecognition`），语言 `zh-CN`，连续识别 + 临时结果。
2. 点击后按钮变为「🔴 聆听中」，页面底部出现**实时字幕条**，显示 interim 结果；再点一次停止。
3. 语义解析（BR-29）：从一句话中提取「学号 + 动作」，支持：
   - `12号优秀` / `十二号优秀` → 12 号盖「优秀」章
   - `5号已更正` → 5 号盖「已更正」章
   - `12号A加` / `12号A+` → 12 号值 `A+`；`A减` → `A-`
   - `12号九十八分` / `12号98分` → 12 号分数 98（中文数字需转阿拉伯数字）
   - `12号错2` / `12号错两个` → 12 号 `错2`
   - 一句话包含多个学号（`1号2号3号优秀`）→ 全部命中
   - `取消12号` → 清除 12 号
4. 命中后：单元格闪一次高亮 + Toast「12号 → 优秀 ✓」；未命中：Toast「没听懂：{原句}」。
5. **必须可撤销**：语音产生的每条变更进入撤销栈。

**规则**：
- BR-30 语音为**辅助输入**，不得成为唯一路径；浏览器不支持时按钮置灰并 `title="当前浏览器不支持语音识别，请使用 Chrome / Edge"`。
- BR-31 中文数字转换支持 0–120（覆盖学号与常见分数）；`100` 读作「一百」。

**边界与异常**：
- 无麦克风权限 → 提示「请在地址栏允许麦克风权限」。
- 识别到的学号超出当前人数 → Toast「{N}号不存在」。
- 嘈杂环境误识别 → 依靠撤销兜底。

**验收标准**：
- `AC-12.1` Given 支持语音的浏览器 When 说「12号优秀」Then 12 号出现金色星标，Toast 提示 12 号。
- `AC-12.2` Given 单元测试模式 When 说「12号九十八分」Then 12 号值变为 98。
- `AC-12.3` Given 说「一百二十号优秀」且班级 50 人 Then 提示「120号不存在」，数据不变。
- `AC-12.4` Given Chrome 以外的浏览器（不支持） When 打开页面 Then 语音按钮为禁用态并有提示。

### FR-16 清空当前记录 — P0

**目的**：把一条作业记录整体重来，而不是逐格删。

**触发**：点击操作行【🧹 清空】。

**交互细则**：

### 4.5 单元格状态矩阵

单元格由「**值状态**（决定底色与边框）+ **焦点/选中态**（外层光环）+ **盖章角标**（右下角）」三层叠加。

#### 4.5.1 常规作业（homework）

| 值 | 底色 | 边框 | 文字色 | 字号 |
|---|---|---|---|---|
| `A+` | `--green-bg` | `2px solid --green-line` | `--green` | 28px/700 |
| `A` | `--green-bg`（浅一档 `#F2F9EA`） | `2px solid --green-line` | `--green` | 28px/700 |
| `A-` | `--amber-bg` | `2px dashed --amber-line` | `--amber` | 28px/700 |
| `√` | `--blue-bg` | `2px solid --blue-line` | `--blue` | 28px/700 |

| 空 | `--surface` | `2px dashed #DCE1EA` | — | — |

#### 4.5.2 单元测试（quiz）

| 分数区间 | 底色 | 边框 | 文字色 | 说明 |
|---|---|---|---|---|
| `score ≥ 优秀线`（默认 90） | `--green-bg` | `2px solid --green-line` | `--green` | 优秀 |
| `80 ≤ score < 优秀线` | `--blue-bg` | `2px solid --blue-line` | `--blue` | 良好 |
| `及格线 ≤ score < 80`（默认 60） | `--amber-bg` | `2px solid --amber-line` | `--amber` | 及格 |
| `score < 及格线` | `--red-bg` | `2px solid --red-line` | `--red` | 不及格 |
| 空 | `--surface` | `2px dashed #DCE1EA` | **不渲染任何字符**（三种模式一致，**不得显示 `—`**） | — |

> **判定方式（唯一）**：先转「十分位整数」`t = Math.round(score * 10 + Number.EPSILON)`，再与 `优秀线×10 / 800 / 及格线×10` 比较。区间上界一律按 `< 下一档下界` 处理，**不得出现因浮点比较导致的空档**（如 `89.95`）。舍入统一为 **half-up**（`Math.round`），禁止 `toFixed`。
> **配色阈值跟随设置**：绿色 = `t ≥ 优秀线×10`；蓝色 = `800 ≤ t < 优秀线×10`；黄色 = `及格线×10 ≤ t < 800`；红色 = `t < 及格线×10`。默认 90 / 60 时即得上表。

| 其他文本 | `--blue-bg` | `2px solid --blue-line` | `--blue` |
| 空 | `--surface` | `2px dashed #DCE1EA` | — |

#### 4.6.5 编辑态 / 多选态状态矩阵（【必须】照表实现）

三个互相叠加的态：**焦点态**（恰好 0 或 1 个）、**多选态**（由【全选】进入）、**内联编辑态**（仅听写模式，同一时刻 0 或 1 个）。

| 按键 \ 当前态 | 普通 | 多选态 | 内联编辑态 |
|---|---|---|---|
| `1`–`5`（常规作业） | 赋值并（秒跳开时）前进 | **忽略** | 不适用 |
| 数字 / 小数点（单元测试） | 累积到 buffer，**不前进** | **忽略** | 不适用 |
| 可打印字符（听写） | 进入内联编辑 | **忽略** | 作为文本输入 |
| `Enter` | 提交并前进（单元测试提交 buffer） | **忽略** | 提交文本并退出编辑 |
| `空格` | 盖章 toggle 焦点格 | **对所有选中项批量盖章** | **作为文本空格输入** |
| `Delete` / `Backspace` | 清空焦点格的值与章 | **清空所有选中项** | **删除一个字符** |
| 方向键 / `Tab` | 移动焦点 | **忽略**（先 `Esc` 退出） | 不适用 |
| `/` | 进入搜索 | 进入搜索（保留选中） | 不适用 |
| `Esc` | 关最上层 Modal；无 Modal 时无操作 | **退出多选，焦点回 anchor** | **取消编辑，恢复原值** |
| 鼠标点击某格 | 聚焦该格 | **退出多选并聚焦该格** | 先提交编辑再聚焦 |
| 点【✨全选】 | 进入多选，anchor = 当前焦点格 | 退出多选 | 不适用 |

**多选态细则**：
- `anchor` = 进入多选时焦点的那个格；**不绘制焦点环**（见 §4.5.5），但内部记录 anchor 供 `Esc` 返回。
- 选中集合 = 「**所有已录入值或已盖章**的单元格」，空单元格不入选。
- 批量盖章 / 清空后**保持多选态**便于连续操作，并 Toast「已对 N 个单元格盖章」。
- 一次批量操作**只产生一条撤销记录**（整批一次撤销）。
- 选中集合为 0 时，点【全选】Toast「还没有可选的单元格」且不进入多选。

**内联编辑态细则（听写模式）**：
- 内联框获得焦点后，`空格` / `Backspace` / `Delete` **一律作为文本编辑键**，**不触发盖章、不整格清空**——必须先 `Esc` 或 `Enter` 退出编辑。
- 因此在听写模式要盖章，必须在**未进入编辑**的格子上按空格。

## 6. 业务规则与计算公式

### 6.1 名单分拣与统计口径

#### 6.1.1 三名单判定（报表用）

| 名单 | 常规作业 | 单元测试 | 听写默写 |
|---|---|---|---|
| **光荣榜** | 值 = `A+`（或 `A`，受设置「光荣榜含 A」控制，默认**仅 A+**） | 分数 ≥ 优秀线（默认 90） | 全对（错 0） |
| **暂未提交** | 值 = `×` 或 空 或 盖章但无值 | **无分数（空单元格；单元测试值域只有 `0–100` 数值或空，缺考一律留空）** 或 盖章但无值 | 缺交 / 未交 / 空 |
| **需更正** | 值 = `A-` | 分数 < 及格线（默认 60） | 错误数 ≥ 1 |
| **不计入任何名单** | 值 = `√`（已交未评级）、`A`（当「光荣榜含 A」关闭时） | 分数 ∈ `[及格线, 优秀线)`（良好档与及格档——正常完成、无需提醒；样例 A 中的 4/14/15/18/19/20 号即属此类） | 其他文本（无法判定为全对 / 有错 / 缺交） |

> **互斥性要求**：三个名单**必须互斥**，一个学号最多出现在一个名单中。优先级：暂未提交 > 需更正 > 光荣榜（先判空，再判低，最后判高）。
> 另有**可选第四组「已更正」**：命中「需更正」但已盖「已更正」章的学号从需更正移到该组（二者互斥），只有报表第四段会用到，详见 §6.6。

#### 6.1.2 统计条数值

| 指标 | 公式 |
|---|---|
| 录入人数 `n` | `count(值有效)`；`×`/缺交/空 不计 |
| 平均分 | `round(sum(score)/n, 1)`；`n=0` → `—` |
| 优秀（标签动态：`优秀({优秀线}+)`） | `count(t ≥ 优秀线×10)` |
| 良好（标签动态：`良好({良好线}+)`） | `count(800 ≤ t < 优秀线×10)`，良好线**固定 80** |
| 及格（标签动态：`及格({及格线}+)`） | `count(及格线×10 ≤ t < 800)`，及格线默认 60 |
| 不及格 | `count(t < 及格线×10)` |
| 未提交 | `N − 录入人数`（含空格子、`×`、`缺交`、盖章但无值，详见 §6.6） |
| 已更正 / 优秀（盖章计数） | `count(stamp === 'corrected')` / `count(stamp === 'excellent')`；**一格只可能有一个章**，不计入 n、不入四档 |
| 优秀率 | `round(优秀/n*100, 1)`；`n = 0` → `—` |
| 最高分 / 最低分 | `max/min(score)`；`n = 0` → `—` |

**边界规则**：
- 分数恰好等于某一档下界，归入该档（`90` → 优秀，`80` → 良好，`60` → 及格）。
- 分段判定统一在「十分位整数」空间进行：`t = Math.round(score * 10 + Number.EPSILON)`，再与 `优秀线×10`、`800`、`及格线×10` 比较，彻底消除浮点误差。
- **四档判定是优先级判定**（优秀 → 良好 → 及格 → 不及格，自上而下命中即止），因此恒有 `优秀 + 良好 + 及格 + 不及格 ≡ 录入人数`，任何合法阈值组合下都不会重复计数或漏计。
- **标签必须跟随设置动态生成**：`优秀({优秀线}+)` / `良好(80+)` / `及格({及格线}+)`。**PRD 中出现的 `优秀(90+)` 等字样均为默认值下的展开形式，不得写死**（否则用户把优秀线改成 85 后，标签与判定不一致）。
- 常规作业与听写模式的统计字段见 §6.1.1 与 §6.6，**无平均分、无四档**。
- `及格线`、`优秀线` 可在设置中调整；`良好线` 固定 80 不可调。**必须满足 `0 ≤ 及格线 ≤ 80 ≤ 优秀线 ≤ 100`**，设置面板越界时夹取并提示——否则会出现区间重叠（如及格线填 85），使四档之和超过录入人数、百分比合计超过 100%。
- **舍入方式统一为四舍五入（half-up）到 1 位小数**：`87.65 → 87.7`、`87.05 → 87.1`。实现用 `Math.round((x + Number.EPSILON) * 10) / 10`；`toFixed(1)` 在部分边界上与 half-up 不一致，**禁用**。
- `录入人数 = 0` 时，`平均分`、`优秀率`、`最高分`、`最低分` 一律显示 `—`，禁止显示 `0` 或 `NaN`。

**占位符规则**：

| 占位符 | 规则 |
|---|---|

| `modeEmoji` / `modeName` | 常规作业 → `📝` / `常规作业`；单元测试 → `💯` / `单元测试`；听写默写 → `✍️` / `听写默写` |

### 6.5 记录生命周期与数据可见性（补充裁决）

|---|---|
| BR-39 | **切换记录**：`日期` / `作业内容` / `模式` 任一变更即视为切到另一条记录。切换前若当前记录有值且未固化，**先静默写入历史**（Toast「已保存上一条」），再载入目标记录（不存在则空网格）。**不得**让新记录共享旧值，也**不得**直接丢弃旧值。 |

**补充验收**：
- `AC-39.1` Given 单元测试已录 10 个值、作业内容为空 When 填写「语文本」 Then 界面切到新记录（空网格），旧记录已进历史且可查回。
- `AC-40.1` Given 50 人已录满 When 人数改为 40 Then 统计条按 40 人重算、报表不含 41–50 号；改回 50 后原值全部恢复。

### 6.6 统计字段的唯一定义（可加性等式）

**必须保证严格可加、互斥且穷尽**：
- 单元测试：`录入人数 = 优秀 + 良好 + 及格 + 不及格`
- 常规作业：`录入人数 = A+ + A + A- + √`
- 听写默写：`录入人数 = 全对 + 有错 + 其他`

| 字段 | 定义（三模式统一口径） |
|---|---|
| 录入人数 n | 学号 1..N 中**有有效值**的格子数。`×` / `缺交` / 空 / 盖章但无值 **不计入** |
| 未提交 | 学号 1..N 中**无有效值**的格子数 = `N − n`。**含空格子、`×`、`缺交`、盖章但无值**。首次打开时等于 N（这是正确行为，不是 bug） |
| 已更正 / 优秀（盖章计数） | 对应章的格子数；**不进 n，不进四档** |
| 其他（仅听写） | 无法解析的文本数；**进 n**，不进任何名单 |
| A+ / A / A- / √（仅常规） | 对应等级的格子数；四者之和 = n |

> **单元测试无「缺考」值**：值域只有 `0–100` 的数值或空。缺考一律**留空**（不进 n、进未提交、不影响平均分），不得在数值模型里塞字符串枚举。

> **盖章对名单的影响（修正 BR-12）**：盖章不改变四档归属，但**会改变名单归类**——「需更正」名单 = 不及格格**且未盖「已更正」章**；已盖「已更正」的不及格格进入报表第 4 段「✅【已更正】」。即 `需更正 ∪ 已更正 = 全部不及格`，二者互斥且穷尽。这样老师盖完章后名单才真的「清零」，与痛点 P-4「查谁没订正」一致。

报表模板相应支持**可选的第四段**（插在 ⚠️【需更正】之后、`（请核对后及时找老师更正）` 之前）：

```
✅ 【已更正】：
{已更正名单}
```

该段仅在存在「已更正」盖章时输出；**样例 A / B 无任何盖章，故 §7.1.3 的期望文案不变**。

### 8.3 已知风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 浏览器剪贴板写图片的兼容性差异 | 无法一键粘贴 | 降级为下载 PNG；同时保留 `ClipboardItem` 探测 |
| `html-to-image` 在字体未就绪时截图缺字 | 海报文字消失 | 生成前 `document.fonts.ready` 等待；只用系统字体 |
| 语音识别在嘈杂环境错误率高 | 误改数据 | 全部可撤销；语音仅作辅助 |
| 老师习惯用微信内置浏览器打开 | Web Speech / 剪贴板 API 受限 | 明确提示「请在 Chrome/Edge 打开以获得完整功能」 |
| 100+ 人班级海报过高 | 微信压缩后变糊 | 提高导出倍率；提供「每 50 人分页」选项（P2） |
| 用户把「作业内容」当班级名填 | 海报标题错 | 学科单独设置，标题只用学科 |
