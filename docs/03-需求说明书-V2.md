## 1. 术语与概念（必须先统一）

| 术语 | 定义 |
|---|---|
| **登记表（Record）** | 某班、某天、某项作业的一张登记表，键 = `(classId, date, content, kind)` |
| **登记类型（RecordKind）** | `dictation` 听写默写 ｜ `homework` 常规作业 ｜ `quality` 质量监测 ｜ `custom` 自定义 |
| **评分方案（ScoringScheme）** | 决定「这一格能填什么、怎么算达标」的配置：`mode` / `maxScore` / 等级集 / 达标规则 / 百分比阈值 |
| **值（CellValue）** | 单元格里记录的**业务内容**：等级、分数、自定义文本三者之一 |
| **状态位（status）** | 与值正交的**到课/交作业**状态：`normal` 正常 / `missing` 缺交 / `leave` 请假 |
| **过关（pass）** | 与值正交的布尔位，用于「过关制」登记表（听写默写默认用它） |
| **补交（makeup）** | 与值正交的「事后补上」标记 + 说明文字 |
| **盖章（stamp）** | 沿用 v1：`none / corrected 已更正 / excellent 优秀`，与值正交 |
| **达标（qualified）** | 由方案的 `passRule` 决定，是「光荣榜/未过关/需更正」判定的统一依据 |
| **积分事件（PointEvent）** | 积分账本的一行：谁、哪天、因哪条规则、加减多少 |

**四条不可违反的不变量（INV）**

- **INV-1** 一条登记表只有**一个** `ScoringScheme`；同表内不允许一部分格子按分数、一部分按另一套等级集。
- **INV-2** `status='leave'` ⇒ 值必须为 `null` 且 `pass=false`；`status='missing'` ⇒ 值必须为 `null`。
- **INV-3** 四档计数恒可加：`优秀 + 良好 + 及格 + 不及格 = 有值人数`（`entered`）。请假、缺交、空白**都不进四档**。
- **INV-4** 积分账本按 `dedupeKey` 幂等：同一条规则对同一个学生的同一次登记，重复保存**不得**重复计分。

## 2. 概念模型变更（本次升级的核心）

### 2.1 从「模式决定值域」到「方案决定值域」

| v1.1 | v2.0 |
|---|---|
| 模式 = `homework / quiz / dictation`，各自写死值域（A+/A/A-/×/√ ｜ 0–100 ｜ 全对/错N） | 登记类型只决定**默认方案与文案**；真正决定值域的是 `ScoringScheme` |
| 优秀/及格线是**全局绝对分**（90/60） | 阈值是**按满分百分比**（默认 90% / 80% / 60%），每条登记表可覆盖 |
| 单元格只能有一种值 | 单元格值 ∈ {等级, 分数, 文本} 之一，混合方案下老师想填哪种填哪种 |
| 未交只用 `×` 表达 | `status` 位表达（缺交/请假），与值解耦 |

### 2.2 值模型（概念层，实现见设计说明书 §3）

**等级集（默认 7 档，全局唯一枚举）**

| 等级 | `percent`（用于换算与达标） | 说明 |
|---|---|---|
| `A+` | 100 | 满分/全对 |
| `A` | 95 | 优秀 |
| `A-` | 90 | 达标线（正好 90%） |
| `B+` | 85 | 良好偏上 |
| `B` | 80 | 良好线 |
| `C` | 70 | 及格 |
| `D` | **55** | 不合格 / 质量差 |

> 为什么是 7 档而不是只有 A/B/C/D：① 用户原话要 A B C D，这四档都在里面；② v1 的 `A+ / A / A-` 可无损迁移；③ 6 档以上才有区分度，且 `percent` 让「等级」与「分数」能用同一套达标判定。
>
> **`D` 为什么是 55 而不是 60**：默认及格线是 60%，若 `D=60` 则 `D` 会被判成「及格」，与「D = 不合格」的常识以及积分规则 7（「等级为 D 或分数 < 60%」扣分）自相矛盾。取 55 保证默认阈值下 `D` 恒为「不及格」；若老师把及格线调到 50%，`D` 自然变「及格」，语义自洽。**实现时不得把 55 改成 60。**
> `√（已交未评）` 与 `×（未交）` **不再是等级**：`√` → `pass=true`，`×` → `status='missing'`（见 §3 迁移）。

**值类型**

| 值 | 何时可用 | 录入方式 | 展示 |
|---|---|---|---|
| `grade`（等级） | 方案 `mode ∈ {grade, mixed}` 且等级在方案等级集内 | 字母键 `A/B/C/D`，`+`/`-` 修饰；或点选 | 档位字母，颜色按档 |
| `score`（分数） | 方案 `mode ∈ {score, mixed}`，范围 `0..maxScore`，最多 1 位小数 | 数字键直接输入（可带小数点），`Enter` 提交 | 数字（如 `118`、`87.5`），颜色按百分比档 |
| `text`（自定义文本） | **任何方案**（FR-20） | 双击单元格或按 `F2` 进入内联框，`Enter` 提交，`Esc` 取消 | ≤10 字原样显示，超长省略号 + `title` |

**正交位**

| 位 | 取值 | 快捷键 / 入口 | 规则 |
|---|---|---|---|
| `status` | `normal` / `missing` / `leave` | `X` = 缺交；`L` = 请假（再按一次取消，回到 `normal`） | 置 `missing`/`leave` 会清空值；置值会重置 `status='normal'` |
| `pass` | `true / false` | 【✅ 过关】按钮、`G` 键、`Enter`（仅在「过关制」方案下） | `pass=true` 时值必须为 `null`；再按一次 `G` 取消 |
| `makeup` | `null` / `{at, note}` | 选中后点【📥 补交】 | 只能对 `status='missing'` 或「判定未达标」的学生标记；补交**不改变**原值，只影响名单与积分 |

### 2.3 判定优先级（唯一口径，实现不得各写一套）

对某学号，按下表**从上到下**取第一条命中：

| 顺序 | 条件 | 归类 | 是否进报表 |
|---|---|---|---|
| 1 | `status='leave'` | 请假 | 【🏖️ 请假】段 |
| 2 | `status='missing'` 且无 `makeup` | 未提交 | 【❌ 暂未提交】段 |
| 3 | `status='missing'` 且有 `makeup` | 已补交（原缺交） | 【📥 已补交】段 |
| 4 | `pass=true` | 已过关 | 【✅ 已过关】段 |
| 5 | 有值且 **入光荣榜**（见 §2.3.1） | 光荣榜 | 【🏆 光荣榜】段 |
| 6 | 有值、未达标、有 `makeup` | 已补交（仍不达标） | 【📥 已补交】段 + 【⚠️ 需更正】段 |
| 7 | 有值、未达标、`stamp='corrected'` | 需更正（已订正） | 【⚠️ 需更正】段 → 归入【✅ 已更正】子段 |
| 8 | 有值、未达标 | 需更正 | 【⚠️ 需更正】段 |
| 9 | 以上都不是（无值无状态） | 未提交（空白） | 【❌ 暂未提交】段 |

> 「有值」= `value !== null`。**未提交 = 空白 + 缺交**，二者合并进同一段，顺序按学号升序。

### 2.3.1 名单口径 ≠ 四档口径（极易写错，必须逐字照抄）

四档（`excellent/good/pass/fail`）是对**百分**的分段，用于统计条与配色；**名单是另一套口径**：

| 判定 | 等级值（`grade`） | 分数值（`score`） | 文字值（`text`） |
|---|---|---|---|
| **入光荣榜** | 字母秩 ≥ `A`（即 `A+` / `A`）；若开关 `honorIncludesA` 打开，则 `A-` 也入（秩 ≥ `A-`） | `percent ≥ 优秀线`（默认 90%） | 否 |
| **入需更正** | 不入光荣榜、且有值：即秩 ≤ `A-`（`A- / B+ / B / C / D`） | `percent < 及格线`（默认 60%） | 仅过关制（`check`）下为真：即听写的 `错N` |
| **中立（不进任何名单）** | 无（等级制下非荣即需） | `及格线 ≤ percent < 优秀线`（及格档 / 良好档） | 非过关制下的自定义文本 |

字母秩：`A+=7, A=6, A-=5, B+=4, B=3, C=2, D=1`。

**为什么要分两条口径**（否则一定写错）：
- 参考成品里 `A-`（=90 分）的格子在统计条里算「优秀」，但名单里进【需更正】——老师的真实意图是「非常优秀但有错要订正」，不是分数不够。因此**等级值按字母秩**判名单。
- 而分数值（质量测验）看百分：`43` 分进【需更正】，`72` 分是及格但不出现在任何名单（教师不需要通知家长「考了 72 分」）。
- 两个样本钉死这两条：V1 样例 A（分数制）光荣榜 13 人（≥90）、需更正 1 人（43分）；V1 样例 B（等级制）光荣榜 = `A+`21 + `A`4 = **25 人**、需更正 = `A-` **24 人**、`×` 1 人（第 17 号）；若打开开关 `honorIncludesA`，24 名 `A-` 也入光荣榜（共 49 人）。

> **实现要求**：`roster.ts` 必须写成 `rankOf(value) / percentOf(value)` 两条分支，**禁止**只用 `tierOf` 判名单（那会把 `A-` 归入光荣榜，与参考成品不符）。

### 2.3.2 报表段落顺序（唯一）

```
🏆 光荣榜 → ✅ 已过关 → ❌ 暂未提交 → 📥 已补交 → ⚠️ 需更正（内含 ⤷ ✅ 已更正 子段） → 🏖️ 请假
```

- 【暂未提交】**恒输出**（空时写 `（无）`）；其余段空则整段省略（含标题）。
- 【已更正】是【需更正】的**子集**，不从【需更正】里拿掉，只在其下加子段。
- 【已补交】每人为 `N号（说明）`，说明为空则只写 `N号`。
- 若补交后仍不达标，该生**同时**出现在【已补交】与【需更正】（规则 6）。

### 2.4 统计字段唯一定义（实现方不得自行发明字段）

| 字段 | 定义 | 参与计算 |
|---|---|---|
| `N` | 班级人数（`class.students.length`） | — |
| `entered` | **有登记**的人数 = `value !== null` **或** `pass === true`（含补交后补录的；不含请假/缺交） | `notSubmitted` 的计算（平均值与四档的分母是「有百分的人数」，见下） |
| `excellent / good / pass / fail` | 按 `percent` 与阈值分档，仅统计**能折算百分**的值（分数 / 等级）；过关与纯文本不产生百分，不进四档（设计 §16-18） | 四档，必须可加（INV-3） |
| `missing` | `status='missing'` 且 `makeup === null` | 单独计数 |
| `leave` | `status='leave'` | 单独计数 |
| `madeUp` | `makeup !== null` | 单独计数（与 `entered` 可重叠） |
| `notSubmitted` | **`N − entered − leave`**（含缺交与空白） | 报表【暂未提交】段长度 |
| `avgPercent` | `mean(percent of entered)`，1 位小数；`entered=0` 时为 `null` | 平均值 |
| `avgScore` | `round1(avgPercent / 100 × maxScore)`；`maxScore` 为空（等级/过关制）时为 `null` | 统计条展示 |
| `excellentRate` | `excellent / 有百分的人数`；分母为 0 时 `null` | 图表 |
| `qualifiedRate` | `(excellent + good + pass) / 有百分的人数`；分母为 0 时 `null` | 图表、积分达标判定 |
| `passCount` | `pass === true` 的人数 | 过关制统计 |

> 三个计数恒等式（单测必须断言）：`entered + leave + (N − entered − leave) = N`；`excellent + good + pass + fail = 有百分的人数 ≤ entered`（分数 / 等级 / 混合方案下取等号，过关/纯文本方案下四档为 0）；`missing ≤ notSubmitted`。
>
> **为什么 `entered` 要把 `pass` 算进来**：FR-21-2 规定过关时清空 `value`（`pass=true` / `value=null`）。若 `entered` 只认 `value`，过关制的 `entered` 会恒为 0，`notSubmitted = N − entered − leave` 就恒等于全班人数、当日汇总的「未过关」恒为 0（v2.0.0 的 P1 缺陷 F1）。四档仍只统计能折算百分的值，故四档之和可能小于 `entered`，这是语义正确的。

## 3. 数据迁移（v1 → v2，必须无损）

| v1 数据 | v2 映射 | 备注 |

## 4. 功能需求（FR-17 ~ FR-30）

### FR-17 评分方案：打分 / 打等级 / 混合 — P0

**目的**：让用户「想打分数就打分数、想打等级就打等级」，且同一张表可以混着用。

**交互细则**：
1. 新建登记表时先选**登记类型**（听写默写 / 常规作业 / 质量监测 / 自定义），系统给出**默认方案**：

| 登记类型 | 默认方案 `mode` | 默认满分 | 默认档位 | 默认达标规则 |
|---|---|---|---|---|
| 听写默写 `dictation` | `check`（过关制，可切混合） | — | 全部 7 档 | `manual`（老师点【过关】） |
| 常规作业 `homework` | `grade` | — | A+ / A / A- / B / C / D | `gradeAtLeast: 'A-'` |
| 质量监测 `quality` | `score` | **100** | 7 档 | `rateAtLeast: 0.6` |
| 自定义 `custom` | `mixed` | 100 | 7 档 | `rateAtLeast: 0.6` |

2. 参数行右侧新增【⚙️ 本表设置】小按钮，打开「评分方案」面板（不打断录入），可改：
   - 方案类型（等级 / 分数 / 过关 / 混合 / 纯文本）
   - 满分（分数/混合方案下显示，1–200 的整数，默认 100）
   - 达标规则（见 §2.2 `passRule` 五选一）
   - 优秀/良好/及格百分比（0–100，默认 90 / 80 / 60，且必须满足 `及格% ≤ 良好% ≤ 优秀% ≤ 100`）
   - 可用等级集（默认全 7 档，可勾掉不用的档，**至少留 1 档**）
3. 方案变更对**已有数据**的处理：见 §6 边界表（默认「不重算值、只重算判定」，并提示影响人数）。
4. 键盘录入按方案分流（键位总表见 §7）。

**验收标准**：
- `AC-17.1` Given 常规作业表（grade 方案）When 聚焦 1 号按 `A` Then 记为等级 `A`；按 `1` 数字键 **无反应**（该方案不接受分数）并 Toast「本表只接受等级」。
- `AC-17.2` Given 混合方案表 When 1 号按 `1`、`0`、`0`、`Enter` Then 记为分数 `100`。
- `AC-17.3` Given 同一张混合方案表 2 号按 `B`、`+` Then 记为等级 `B+`。
- `AC-17.4` Given 混合方案表 When 3 号先录 `90` 再录 `A` Then 最终只保留 `A`（值互斥，后写覆盖）。
- `AC-17.5` Given 方案改为 `grade` When 已存在分数值 Then 这些值**不丢失**，但在等级视图里显示为「分数不可用于本方案」并阻止再次录入分数。

### FR-18 满分可配置与百分比阈值 — P0

**交互细则**：
1. `maxScore` 默认 100，范围 **1–200**，整数；切换后已录分数**不做等比缩放**（提示「已有 N 条分数，若需缩放请重新登记」）。
2. 判定一律走**百分比**：`rate = 分数 / maxScore`（等级用 `percent/100`）。
3. 阈值默认 `优秀 90% / 良好 80% / 及格 60%`；与 v1 的绝对分 90/60 在满分 100 时**完全等价**（这是迁移不破坏历史的保证）。
4. 统计条文案随满分与阈值变化：`优秀(≥90%)`、分数展示形如 `87.5 / 100`（仅在该表 maxScore ≠ 100 时显示分母）。
5. 图表纵轴上限 = `maxScore`；平均分按真实分数显示（1 位小数）。

**验收标准**：
- `AC-18.1` Given 满分 120、及格线 60% When 73 分 Then 60.83% → 及格；When 72 分 Then 恰 60.0% → 及格；When 71 分 Then 59.17% → 不及格。（边界必须逐点断言，禁止用 `>` 与 `>=` 混写。）
- `AC-18.2` Given 满分 100、阈值默认 When 统计条 Then 显示 `优秀(≥90%)`，且与 v1 的 `优秀(90+)` 判定结果完全一致（回归样例 A）。

### FR-26 积分规则引擎 — P0

**目的**：把「连续 3 次全对 +5、积极回答 +2」这类口头规则变成可配置、可审计的账本。

**规则结构**（老师可在设置里改）：`名称 / 触发 / 条件 / 分值 / 频率 / 启用`。

**默认规则集（8 条，全部可改分值、可停用）**

| # | 名称 | 触发 | 条件 | 分值 | 频率 |
|---|---|---|---|---|---|
| 1 | 连续 3 次听写全对 | 自动（登记保存时） | 连续 3 条听写登记均达标 | **+5** | 每达成一次计一次 |
| 2 | 课堂积极回答 | 手动（点学生 → 给分） | 无 | **+2** | 每点一次 |
| 3 | 定时训练优秀 | 自动 | 本次登记 ≥ 优秀阈值 | **+3** | 每条登记一次 |
| 4 | 错题再练全对 | 自动 | 本次登记为「错题再练」类且达标 | **+3** | 每条登记一次 |
| 5 | 每周拓展完成 | 手动 | 本周已登记「拓展」 | **+5** | 每周一次 |
| 6 | 作业未完成 | 自动 | 本次登记 `status='missing'` | **−3** | 每条登记一次 |
| 7 | 作业质量差 | 自动 | 本次等级为 `D` 或分数 < 60% | **−1** | 每条登记一次 |
| 8 | 补交 | 自动 | 触发一次补交 | **−2** | 每次补交一次 |

**通用规则**：
1. 每次「保存/提交一个值」「标记缺交」「标记补交」「手动给分」都触发一次规则评估；评估结果写入账本并 Toast 提示（如「1号 连续3次全对 +5」）。
2. 所有自动加分**幂等**（INV-4）；同一规则同一学生在同一条登记上只记一次。
3. 账本可撤回：积分页支持「删除某条记录」并写一条反向记录（不物理删除），审计可追。
4. 手动给分：积分页 + 网格右键菜单【⭐ 给分】→ 选规则/自定义分值（−10…+10 整数）→ 必填理由（≤20 字）。
5. 积分可为负；总分为 0 时显示 `0`，不显示负数下限截断。

**验收标准**：
- `AC-26.1` Given 听写表连续 3 天（3/11、3/12、3/13）1 号均达标 When 保存第 3 次 Then 账本新增 `+5`（规则 1），且**只新增一次**。
- `AC-26.2` Given 重复保存第 3 次登记 When 再次保存 Then 账本**不新增**（幂等）。
- `AC-26.3` Given 4 号缺交 When 保存 Then 账本新增 `−3`（规则 6）。
- `AC-26.4` Given 5 号补交 When 确认补交 Then 账本新增 `−2`（规则 8）。

### FR-30 语音识别优化 — P0

**现状**：原生 Web Speech API（`zh-CN`），识别率低。

**目标**：常用指令（`12号优秀`、`5号已更正`、`23号A减`、`全对`、`7号过关`）识别准确率从「勉强可用」提升到「老师愿意用」。

**必须做的四层**（详见设计说明书 §8）：

| 层 | 措施 |
|---|---|
| ① 识别层 | 保留原生 API；开启 `maxAlternatives: 5`；若浏览器支持 `SpeechRecognitionPhrases` / `phrases`（Chrome 138+ on-device），把「1–120 号 + 全部动作词」注入偏置词表；否则静默降级 |
| ② 归一化层 | 中文数字解析（十二/一十二/幺二/两/廿三/一百二十）、全角半角、标点剥离、同音词表（优秀/优绣、已更正/以更正/已耕正、过关/过官/过光、请假/请驾）、等级词（A加/A+、A减/A-、B、C、D） |
| ③ 解析层 | 槽位正则 `(学号)(动作/等级)`，学号做范围约束（1..N）与最近邻纠错；一个 utterance 支持多指令（`1号全对，2号错1`） |
| ④ 确认层 | 识别结果进入底部**确认条**（「听到：12号 优秀 → 应用到 12号」3 秒可撤销 / 可改学号），不再「听错就写错」 |
| ⑤ 稳定性 | `continuous` 自动停止后自动重启（带退避）；静音 8 秒自动停；识别中禁止「语音」按钮重复点击 |

**必须做的体验兜底**：
- 识别失败/低置信度（`confidence < 0.6`）→ 确认条标黄，需老师点【确认】才生效。
- 任何语音写入都可 `Ctrl+Z` 撤销（沿用 v1 撤销栈）。

**明确不做**：云端付费 ASR、需下载 40MB+ 的本地大模型（与「离线单文件」冲突）。

**验收标准**：
- `AC-30.1` Given 说「十二号 优秀」Then 归一化为 `12号` 并写入优秀。
- `AC-30.2` Given 说「五号 以更正」Then 归一化为 `5号 已更正`。
- `AC-30.3` Given 说「二十三号 过官」Then 归一化为 `23号 过关`。
- `AC-30.4` Given 说「99号 优秀」而班级只有 50 人 Then 不写入，确认条提示「超出学号范围」。
- `AC-30.5` Given 麦克风权限被拒 Then 提示「请在浏览器地址栏允许麦克风」，不崩溃。

## 6. 边界与异常（实现方最容易写错的地方）

| 场景 | 应有行为 |
|---|---|
| 方案从「分数」改「等级」而表里已有分数 | 值保留、判定改为「不可判定」，名单里这些学生进「需更正」但不参与四档；顶部黄条提示「本表方案已变更，N 条旧值不参与判定」 |
| 满分从 100 改 150 | 已录 95 仍是 95 分（不是 142.5），但判定从 95% 变 63.3% → 提示「N 人判定结果已变化」 |
| 人数从 50 改 40，而 41–50 有积分 | 隐藏不删；积分照旧保留；月度统计只统计 1–40（与 v1 BR-40 一致） |
| 同一天同一 content 同 kind 再次登记 | 复用同一条记录（recordKey 幂等），不新建 |
| 补交后又被清空 | 清空只清值/状态/盖章，`makeup` 一并清除（记一条撤销） |
| 过关后又录了值 | 录值即 `pass=false`（互斥），值优先 |
| 语音连续触发同一句 | 3 秒内按 `(学号+动作)` 去重，只应用一次 |
| 导出时正在录入 | 导出快照为「点击那一刻」的状态，不阻塞录入 |
| 浏览器存储写满 | 复用 v1 降级：告警条 + 引导导出备份；不得丢内存中的新数据 |

**期望统计**（必须逐位相等）：

| 字段 | 期望值 | 推导 |
|---|---|---|
| 人数 N | 50 | |
| 有值 `entered` | **18** | 1–10（10）+ 13–17（5）+ 18–20（3） |
| 优秀（≥90%） | **7** | 1(98.33)、2(A+=100)、6(A=95)、7(91.67)、8(95.83)、16(A-=90)、19(100) |

→ `1440.833 / 18 = 80.046` → 显示 `80.0`；`80.046% × 120 = 96.056` → 显示 `96.1`。
